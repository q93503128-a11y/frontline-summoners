# 구현 상태

이 문서는 `docs/CANONICAL.md`를 대체하지 않는다. 매 작업 전 정본을 먼저 읽고, 이 문서는 현재 구현 진행도와 미완료 항목을 기록한다.

## 2026-08-24 — campaign vertical slice 0.0.12

### 기반
- Cloudflare Pages `frontline-summoners`: GitHub `main` 자동 배포 연결 상태.
- Worker / Durable Object / D1 골격 구성 완료.
- `packages/sim`: 30Hz 이동·탐지·공격 프레임·동시피해·자연 KB·강제이동·DYING·기지승패·stateHash 구현.
- `packages/sim/playable`: 보급, 보급소 Lv.1~8, 생산비/재생산 쿨다운, 적 웨이브, 처치 보급, 단일 장착 거점 병기 구현.

### 사용자 첫 테스트 기준
- 예전 5개 도형 유닛 개발 하네스는 사용자 테스트 빌드로 취급하지 않는다.
- 메인 → 스테이지 → 편성 → 실제 스프라이트 전투 → 결과/보상까지 한 사이클이 게임처럼 보여야 테스트를 요청한다.
- 내부 렌더 기준은 1280×720.
- 일반 플레이 화면에 tick/hash 등 개발자 디버그 텍스트를 노출하지 않는다.

### 진행 / 보상
- 신규 진행은 `징집병` 1종만 보유하고 STAGE 1만 개방한다.
- 앞 스테이지를 클리어해야 다음 스테이지가 열린다.
- 확정 캐릭터 해금: ST1 방벽기사 → ST2 수렵창병 → ST4 결투검사 → ST6 청창대 → ST8 전투마도사 → ST10 화염술사 → ST13 왕실기사 → ST16 이단주술사 → ST20 공허현자.
- 각 스테이지 보물은 첫 클리어 100% 획득하며 IndexedDB에 저장한다. 보물 등급/RNG/반복 보물작은 없다.
- 승리 결과 저장이 끝나기 전에 화면을 이탈해 다음 스테이지가 잠겨 보이는 저장 레이스를 차단했다.
- **미완료:** 보물 ID의 보유/저장은 동작하지만, 보물 설명에 적힌 영구 스탯·경제 효과를 실제 전투 수치에 반영하는 progression modifier는 아직 연결하지 않았다. 첫 사용자 테스트 전에 구현한다.

### 콘텐츠 / 맵
- 플레이어 10종(C3/B3/A2/S1/SS1), 적 8종 + 보스 2종, 제1장 20스테이지.
- 스테이지 선택은 5개씩 4페이지.
- 전장 7계열: 풀바람 평원 / 붉은 협곡 / 불붙은 곡창지대 / 안개 폐허 / 달그늘 고개 / 철문 요새권 / 황금가면 관문.
- 각 스테이지는 별도 `decorSeed`, 780~1340 전장 길이, 지역별 하늘/원경/중경/지면/장식/거점 팔레트를 사용한다.
- `mapLength`는 배경 장식이 아니라 실제 1D 시뮬레이션 거리다.
- 최종장 보스가 기지 러시 때문에 등장 전에 스킵되는 위험을 줄이기 위해 ST19 황금가면 대주술사를 1000틱, ST20 황금가면을 900틱, 철문장군을 1250틱에 등장하도록 앞당겼다.
- ST19/ST20 baseline은 지정 보스가 실제 등장했는지까지 검사한다. 현재 프로토타입 baseline 보호 장치이며, 향후 성장 폭이 커지면 기지 HP 조건형 보스 트리거 등 더 강한 구조로 확장할 수 있다.

### JSON 단일 정본
- `content/units/chapter-01.json`: 플레이어 수치/역할/비용/공격 타이밍/속성/전문.
- `content/enemies/chapter-01.json`: 적 수치/처치 보급/공격 타이밍/속성.
- `content/stages/chapter-01.json`: 20스테이지 맵/웨이브/보물/해금.
- `apps/client/src/prototype.ts`는 위 JSON을 `parseCampaignBundle()`로 검증한 뒤 실제 전투 객체로 변환한다.
- 스키마는 ID 중복, 범위 오류, 잘못된 공격 프레임, 적 참조, 해금 중복/누락, 보물 중복, 웨이브 순서, 맵 다양성, 속성/전문 데이터 등을 거부한다.

### 속성 / 전문 능력 1차
- `LIGHT / ARMORED / ARCANE / BOSS` 4태그.
- 속성 자체에는 전역 가위바위보 상성이 없다.
- 명시된 전문 보너스만 특정 태그에 적용하며, 여러 조건이 맞아도 가장 강한 배율 하나만 적용한다.
- 배율은 permille 정수로 처리하고 거점 공격에는 적용하지 않는다.
- 편성 카드에는 한글 속성/특효, 적 HP바 위에는 적 속성 라벨을 표시한다.

### 거점 병기 / ForcedDisplacement
- **한 전투의 장착·즉시개입 병기 슬롯은 1개다.** 장기적으로 병기 종류 후보를 추가할 수 있으나 여러 병기 버튼을 동시에 두지 않는다.
- 현재 장착 병기 `전선포`: 적 거점 제외 적 전체 90 피해 → 사망/자연 KB 판정 → 남은 적 60 거리/10F 강제 후퇴, 900틱 재충전.
- `FORCED_DISPLACEMENT`는 자연 KB와 별도 상태이며 현재 행동을 취소한다.
- 강제이동 중 hurtbox는 유지되고, 그동안 자연 KB 임계 피해를 받으면 자연 KB가 우선하며 강제이동이 취소된다.
- 같은 포격에서 자연 KB와 강제 Push가 한 대상에 중복 적용되지 않는다.
- 전선포 처치도 일반 처치와 동일하게 보급 보상을 준다.

### 공격 연출 / 원거리
- LuizMelo CC0 계열 7개 아트 패밀리 Idle/Run/Attack 사용.
- 실제 플레이는 외부 raw URL을 읽지 않고 build-time vendoring 후 로컬 `/assets/characters`를 사용한다.
- 각 아트 패밀리에 `attackContactFrame`을 두고 실제 첫 hitFrame과 접촉 포즈를 맞춘다.
- `SLASH / PIERCE / BLUNT / MAGIC / FIRE / VOID` 6종 공격 시각 언어.
- HP 감소를 감지한 공통 충격 VFX, 거점 피격 VFX, 지면 그림자, 소환 VFX 구현.
- `PIERCE / MAGIC / FIRE / VOID`는 선딜 후반에 실제 Phaser 발사체를 만들고 hitFrame에 도달하도록 거리별 정수 travel tick을 역산한다.
- 판정은 여전히 30Hz hitFrame 즉시 판정이며 투사체 충돌 판정으로 바꾸지 않는다.
- **미완료:** 현재 발사체 위치 갱신이 정수 `battle.tick` 기준이라 시각적으로 30Hz 계단감이 남을 수 있다. `accumulator / SIM_TICK_MS`를 이용한 렌더 전용 fractional interpolation을 연결한다.

### 결정성 / stateHash
- 유닛 해시에 HP/좌표/상태뿐 아니라 공격 정의, 속성/전문, 자연 KB, displacement 시작·목표·지속시간을 포함한다.
- core hash에 `mapLength`, 양쪽 거점 anchor/maxHP/currentHP를 포함한다.
- playable hash에 보급소 전체 정의, 슬롯 비용/쿨다운/전투 정의, 적 전투 정의/처치 보급, 미래 웨이브 count/interval/runtime, 배치 한도, 거점 병기 설정/런타임을 포함한다.
- 현재 보이는 화면이 같아도 미래 판정이 달라지는 두 상태가 같은 hash로 뭉개지는 문제를 줄였다.

### 캠페인 baseline
- ST1: 징집병만 사용, 60초 이내 승리 + 아군 거점 50% 이상.
- ST1~5: 실제 순차 해금 로스터만 사용.
- ST6~10: ST6 청창대 / ST8 전투마도사 / ST10 화염술사가 실제 클리어 이후에만 합류.
- ST11~15: ST13 클리어 전 왕실기사 사용 금지, ST14부터 사용 가능.
- ST16~20: ST16 클리어 전 이단주술사 사용 금지, ST17부터 사용 가능. 공허현자는 ST20 클리어 보상이므로 제1장 전투 중 사용 금지.
- ST19 baseline은 황금가면 대주술사 실제 등장 확인.
- ST20 baseline은 황금가면 대주술사 + 철문장군 두 보스 실제 등장 확인.
- ST20 클리어 후 정확히 10종 전체 로스터 해금을 검사한다.

- 전선포 피해/Push/처치보급/쿨다운/결정성.

## 현재 검증 중 / 미완료

1. 최신 push의 실제 GitHub Actions/Cloudflare build 성공 여부. 연결된 commit status가 계속 비어 있어 성공을 단정하지 않는다.
2. 실행 환경에서 외부 npm/GitHub DNS가 차단되어 별도 로컬 `npm install → typecheck → test → build` 재현을 하지 못했다.
3. 정본은 `package-lock.json` 커밋을 요구하지만 현재 루트에는 lockfile이 없다. 무결성 해시를 임의 생성하지 않고 실제 npm 실행 가능한 환경에서 생성 후 커밋한다. 현재 CI는 `npm install`을 사용한다.
4. 보물 20종의 실제 영구 효과 적용.
5. 투사체 60fps 렌더 보간.
6. 7개 전장 계열의 캐릭터 발 위치/그림자/거점 상대 크기 수동 시각 감사.
7. 대규모 웨이브에서 적 속성 라벨 과밀, 편성/전투 UI의 모바일 가독성 수동 감사.
8. build-time vendoring 21개 PNG의 실제 배포 결과 확인.

## 다음 작업

1. 보물 20종을 typed progression modifier로 만들어 실제 스탯/경제/배치 한도에 적용하고, 보유 보물 목록과 전투 설정이 일치하는지 회귀검사한다.
2. 원거리 발사체에 렌더 전용 fractional interpolation을 붙여 30Hz 판정을 유지하면서 60fps 이상에서 부드럽게 이동시킨다.
3. 최종보스 등장 시각 피드백과 보스전 화면 가독성을 보강한다.
4. 필요하면 일반 공격의 데이터 기반 Push 능력이 `FORCED_DISPLACEMENT`를 재사용하도록 확장한다. 캐릭터별 액티브 버튼은 만들지 않는다.
5. 최신 배포의 빌드/런타임 오류가 확인되면 즉시 수정한다.
6. 첫 사용자 수동 테스트 게이트를 전부 통과한 뒤 사용자 실플레이 피드백을 받는다.

### 속성 / 전문 능력 1차
- 정본 원칙대로 속성 자체에 전역 가위바위보 상성을 만들지 않았다. 기본 공격은 속성과 무관하게 모든 적에게 정상 피해를 준다.
- 1차 전투 속성은 `LIGHT / ARMORED / ARCANE / BOSS` 네 태그다. 한 유닛이 둘 이상을 동시에 가질 수 있다.
- 공격자가 `damageBonuses`를 명시한 경우에만 특정 속성 대상 피해가 증가한다.
- 대상에게 여러 속성이 동시에 맞아도 배율을 곱하거나 합산하지 않고 가장 강한 전문 배율 하나만 적용한다.
- 배율은 부동소수 대신 permille 정수(1000=1.0배)를 사용해 싱글/멀티 결정성을 보존한다.
- 거점에는 속성이 없으므로 전문 피해 배율이 거점 공격력까지 뻥튀기되지 않는다.
- 제1장 10종 플레이어/10종 적 JSON에 속성을 명시했다. 현재 전문 예시는 수렵창병 LIGHT 1.25배, 결투검사 ARMORED 1.30배, 이단주술사 ARCANE 1.30배, 공허현자 BOSS 1.50배다.
- 속성/전문 데이터도 `packages/content-schema`에서 알려지지 않은 태그, 중복 태그, 중복 전문 대상, 잘못된 배율을 거부한다.
- 편성 카드에서 캐릭터의 한글 속성과 전문 보너스를 실제 `BattleUnitDefinition`에서 읽어 표시한다. UI용 수치를 따로 복사하지 않는다.
- 전투 중 적 HP바 위에는 `경량 / 중갑 / 비전 / 우두머리` 속성 표기를 붙여 전문 캐릭터를 언제 쓰는지 읽을 수 있게 했다.

### 거점 병기 / 강제이동 1차
- 정본상 거점 병기는 **1개만** 둔다. 구현 상태 문서에 잠시 남아 있던 “2종째 거점 병기 후보”는 폐기했다.
- 전투 시작 시 충전 완료된 `전선포` 버튼을 사용한다.
- 현재 수치: 적 기지에는 피해를 주지 않고 적 전체 90 피해, 60 거리 강제 후퇴, 강제이동 10틱, 재충전 900틱(30초).
- 처리 순서는 `광역 피해 → 사망/자연 KB 판정 → 남은 대상 강제이동`이다. 같은 포격에서 자연 KB와 Push를 겹쳐 두 번 튕기지 않는다.
- `FORCED_DISPLACEMENT`는 자연 KB와 별도 상태다. 현재 행동을 취소하고 뒤로 이동하지만 hurtbox는 유지되어 이동 중에도 다른 공격에 맞을 수 있다.
- 강제이동 중 자연 KB 임계 피해를 받으면 자연 KB가 우선하며 남은 강제이동을 취소한다.
- 자연 KB/DYING 대상은 강제이동 적용에서 제외한다.
- 전선포 처치도 일반 공격 처치와 동일하게 처치 보급을 지급한다.
- 화면에는 충전 남은 시간, 발사 가능 상태, 짧은 광선/섬광/화면 흔들림을 표시하며 실제 적 위치는 코어 강제이동에 따라 후퇴한다.

### 결정성 / stateHash 보강
- 속성과 전문 능력 정의는 `packages/sim` stateHash의 전투 정의 서명에 포함한다.
- 수동 감사에서 기존 stateHash가 자연 KB의 시작/목표 위치를 포함하지 않아 서로 다른 미래 상태가 같은 해시가 될 수 있는 문제를 발견해 수정했다.
- 이제 유닛 해시에 displacement 시작/목표 좌표, 강제이동 지속시간을 포함한다.
- 전투 정의 서명도 ID/속성만이 아니라 HP, 공격력, 이동속도, standingRange, 공격 최소/최대 사거리, targetMode, 자연 KB 규칙, 사망 프레임, 공격 cycle/hit/backswing 프레임까지 포함한다.
- 전선포 해시에도 피해, 쿨다운, 밀치기 거리/지속시간, 준비 틱/대기 상태/마지막 발사 틱을 포함한다.

- 각 아트 패밀리에 `attackContactFrame`을 명시했다. 공격 시트 전체를 단순 균등 재생하지 않는다.
- `apps/client/src/combat-visuals.ts`의 순수 매핑 함수가 시뮬레이션 첫 `hitFrame`과 지정된 스프라이트 접촉 포즈를 정확히 일치시킨다.
- 단일 히트 공격은 실제 피해가 적용된 직후 Backswing으로 상태가 넘어가더라도 contact pose가 유지되도록 상태 전환 의미를 반영했다.
- 이동/대기 반복 애니메이션은 simulationId 기반 시각 phase offset을 적용해 같은 종류 병력이 완전히 같은 박자로 걷는 현상을 줄였다. 전투 판정에는 영향이 없다.
- 유닛 HP 감소를 실제 렌더 상태에서 감지해 경/중/강 타격 섬광을 발생시킨다. 임의 타이머가 아니라 실제 피해 결과를 기준으로 한다.
- 거점 HP 감소도 동일하게 감지해 거점 섬광/먼지/중량별 화면 흔들림을 발생시킨다.
- 캐릭터 아래 반투명 지면 그림자를 추가해 서로 다른 원본 시트의 투명 여백 때문에 캐릭터가 떠 보이는 문제를 완화했다.
- 새 유닛 등장 시 짧은 지면 소환 섬광을 추가했다.
- 플레이어/적 20종에 공격 시각 언어를 `SLASH / PIERCE / BLUNT / MAGIC / FIRE / VOID` 6종으로 명시했다.
- 대상의 HP 감소 연출은 공격 종류와 별개인 공통 충격 섬광으로 유지해 마법 공격에도 흰 베기선이 뜨는 혼선을 막는다.

### 원거리 발사·도달 연출
- 실제 피해 판정은 투사체 충돌식으로 바꾸지 않는다. 기존 30Hz `hitFrame` 판정을 정본으로 유지한다.
- `PIERCE / MAGIC / FIRE / VOID`는 실제 Phaser 투사체 오브젝트를 생성해 공격자에서 목표 방향으로 이동한다. `SLASH / BLUNT`는 즉시 근접 VFX다.
- 거리 기반 원하는 이동시간을 30Hz 정수 틱으로 올림한 뒤 `launchFrame = hitFrame - travelTicks`로 역산한다. 따라서 먼 목표도 시각 투사체가 실제 피해보다 늦게 도착하지 않는다.
- 창은 직선, 마력/화염/공허는 서로 다른 높이의 시각 포물선을 사용한다. Y축은 장식이며 전투 판정은 여전히 1차원 X축이다.
- 발사체 목표는 발사 시점의 실제 공격 범위 안 가장 가까운 적/거점을 사용하고, 유효 대상이 없으면 사거리 안 전방 지점으로 시각 fallback한다.
- 원거리 계열의 기존 공격자 주변 VFX는 발사 순간 캐스팅/총구 효과로 사용하고, 실제 hitFrame 순간에는 중복 재생하지 않는다.
- 피해 대상의 공통 충격 섬광은 실제 HP 감소를 감지해 그대로 hitFrame에 발생한다.
- 발사 타이밍/거리별 travel tick/포물선 시작·종료와 BattleScene 배선 순서를 자동검사한다.

### 초반/중반 전투 baseline
- 신규 계정 ST1은 징집병만 사용한 자동 baseline 전투로 실제 30Hz 코어를 끝까지 진행한다.
- ST1은 자동 baseline 기준 60초 이내 승리 + 아군 거점 HP 50% 이상 유지를 요구한다.
- ST1~ST5 연속 baseline 검사를 추가했다. 각 스테이지는 이전 스테이지에서 실제로 해금한 캐릭터만 사용할 수 있다.
- ST1~ST5 제한은 각각 60/90/105/120/135초이며, 아군 거점 최소 생존 비율은 50/40/35/30/25%다.
- ST5까지의 합법 로스터는 `징집병 / 방벽기사 / 수렵창병 / 결투검사`뿐이어야 하며 이후 캐릭터가 baseline에 섞이면 검사 실패한다.
- ST6~ST10 순차 baseline 검사도 추가했다. ST5까지 실제 클리어한 계정에서 시작하고, ST6 청창대 → ST8 전투마도사 → ST10 화염술사가 정확한 시점 이후에만 사용된다.
- ST6~ST10 제한은 150/165/180/195/210초, 거점 최소 생존 비율은 20/18/15/12/10%로 설정했다.
- ST10 이후 baseline 로스터가 정확히 `militia / guard / hunter / duelist / lancer / battlemage / pyromancer`인지 검사한다.
- 속성 전문과 전선포 Push가 동일 `createPrototypeBattle()`/`packages/sim` 경로에 들어가므로 baseline은 별도 모의 규칙이 아니라 실제 전투 정의를 사용한다.

## 현재 검증 중

1. 최신 `main`의 실제 GitHub Actions/Cloudflare build 결과. 현재 연결 도구가 push 기반 Actions check-run을 직접 열람하지 못해 통과를 단정하지 않는다.
2. 이 실행 환경은 외부 GitHub/패키지 레지스트리 DNS 접근이 차단돼 별도 로컬 clone/npm install/typecheck/test/build 재현도 하지 못했다.
3. 속성 전문 + 실제 투사체 UI + 전선포 Push가 들어간 상태에서 ST1~ST10 전체 baseline이 CI에서 실제 통과하는지 확인 필요.
4. build-time vendoring의 21개 PNG 기대 해상도 전수 대조.
5. 7개 전장 계열에서 캐릭터 실제 발 위치·그림자·거점 상대 크기 수동 시각 검수.
6. 원거리 발사체 크기/포물선/도달점과 실제 무기·마법 접촉 포즈 정렬 수동 시각 검수.
7. 적 속성 라벨이 대규모 웨이브에서 과밀하지 않은지, 편성 카드 추가 정보가 1280×720 및 모바일 축소에서 읽히는지 검수.

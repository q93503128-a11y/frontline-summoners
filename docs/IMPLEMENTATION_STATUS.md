### 스테이지 시스템 정밀 기획 복원

- 스테이지를 `PROGRESSION(진도)` / `SPECIAL(특수)` 두 축으로 분리하는 원칙을 정본화.
- 현재 제1장 20개는 모두 진도 스테이지로 정규화됨.
- 진도 스테이지는 모두 싱글 클리어 가능해야 함.
- 특수 스테이지는 보스·외전·이벤트·캐릭터/진화재료·제한전·생존전·러시·도전전 등 별도 콘텐츠 축으로 사용.
- 기존 난이도 1~5 스키마를 **1~12**로 확장.
- 제1장 실제 JSON은 1~9를 사용. ST20은 난이도 9이며 10~12는 이후 더 높은 체급 콘텐츠에 남겨둠.
- 스키마에 `stageType`, `playerUnitCap`, `enemyUnitCap`, `formationRestrictions`, `specialRules` 추가.
- 입력값이 없는 현재 제1장은 `PROGRESSION / 50 / 50 / 제한 없음 / 특수규칙 없음`으로 정규화.
- `formationRestrictions`는 희귀도 허용/상한, 역할, 비용 상한, 필요/금지 유닛 태그, 최대 편성 종류, 동일 세력 제한을 표현할 수 있는 데이터 구조까지 복원.
- `specialRules`는 향후 등록된 deterministic rule ID만 실제 실행하도록 설계. 현재는 스키마 저장/검증 틀만 있고 런타임 규칙 레지스트리는 아직 미구현.
- 현재 웨이브 런타임은 `atTick` 시간 기반이 정본. 거점 HP/특정 적 사망/누적 처치·사망/페이즈/AND·OR trigger evaluator는 상세 설계 복원 완료, 런타임 구현은 후속 작업.
- 특수 스테이지 전용 콘텐츠 파일/선택 UI/보상 모델도 아직 미구현. 스키마가 있다고 실제 콘텐츠가 구현됐다고 간주하지 않는다.

### 협동 정본

- 2인 협동은 플레이어당 5칸, 팀 전체 10칸.
- 공유: 거점 HP, 승패, 거점 병기.
- 개인: 보급, 보급소, 생산 쿨다운.
- 협동은 어려운 동일 스테이지를 싱글보다 실질적으로 수월하게 공략할 수 있는 선택지로 설계.
- **`협동 권장` 태그는 사용하지 않음.** 싱글 플레이를 열등한 선택처럼 보이게 만드는 UI/문구 금지.
- 협동 난이도 보정은 필요 시 **적 최대 HP / 적 공격력 / 적 거점 최대 HP만 단순 배율** 적용.
- 협동 때문에 이동속도·공격주기·사거리·KB·스폰 시간·적 수·웨이브·패턴·AI를 바꾸거나 solo/coop 스테이지를 두 벌로 복제하지 않음.
- 정확한 협동 배율은 멀티 구현 후 2인 baseline/실플레이로 결정. 아직 수치 확정/런타임 구현 전.

### 제1장 후반 baseline 재설계

- 과거 `STABLE_FRONTLINE_COUNT + selectReadyBossCounter` 방식은 ST20에서 실제로 한 번도 발동하지 않는 죽은 전략 경로였음. 보스 등장 시점에는 이미 전선이 4기 미만으로 무너져 있었기 때문.
- 해당 경로를 **완전히 제거**하고 ST16~20에만 적용되는 전술 baseline으로 교체. ST1~15의 기존 roster-cycle 경로는 그대로 유지하여 후반 조정이 초중반을 재작성하지 않게 함.
- 후반 전술 baseline:
  - 적이 오기 전에는 싼 병력 최대 3기로 작은 전선만 만든 뒤 보급을 비축.
  - 실제 5회 배치 후 Lv3 보급소 투자를 허용. 강화비가 부족하면 값싼 유닛을 더 뽑지 않고 강화비를 모음.
  - 적이 있는 동안 현재 적 속성, 명시적 특효, 단일/광역 가치, 사거리, 체력, 실제 보급 대기시간을 함께 평가하여 생산 후보를 고름.
  - 최대 12초 안에 살 수 있는 준비 완료 유닛만 저축 후보로 삼아 지나친 장기 대기를 방지.
  - 전선이 0기가 되면 HP/비용 효율이 높은 즉시 구매 가능한 전열 앵커를 우선 재배치.
  - 미래 해금인 공허현자를 제1장 클리어 전에 사용하지 않음.

### ST20 최종전 페이싱 수정

기존 ST20은 저보급 경제에 비해 초반 압박이 지나치게 빨라, 보스 자체보다 **보스 도착 전에 경제/전선이 이미 붕괴하는 구조**였음. 보스 HP/공격력은 건드리지 않고 초반 웨이브만 재구성함.

현재 ST20:

- 시작 보급 300, 아군/적 거점 4000/7200, mapLength 1280 유지.
- 녹슨 방패병 2기: tick 450, 간격 250 — 첫 압박 15초.
- 철퇴 광전사 1기: tick 1000 — 33.3초. 기존 2기 러시에서 1기로 감소.
- 황금가면 대주술사: tick 1500 — 50초.
- 유리봉 저격술사: tick 1800 — 60초.
- 철문장군: tick 2400 — 80초.
- 황금가면/철문장군 전투 능력치는 그대로 유지.
- 회귀 테스트가 위 타이밍과 두 보스 실등장을 고정한다.

## 첫 사용자 테스트 전 남은 주요 항목

1. 현재 HEAD를 실제 install → typecheck → test → build 가능한 환경에서 한 번 더 검증. 소스 충실 독립 재현에서는 ST1~20이 전부 통과했지만 CI 자체 확인은 별도다.
2. 7개 맵에서 캐릭터 발 위치/그림자/거점 상대 크기/PC·가로 모바일 가독성 수동 감사.
3. Cloudflare Pages 실제 배포 상태와 최신 빌드 반영 여부 확인.
4. 첫 수동 테스트 게이트의 UI/전투 화면 항목을 전체 체크한 뒤에만 사용자 테스트를 요청.
5. 특수 스테이지의 실제 콘텐츠 파일/선택 UI는 첫 vertical slice 안정화 뒤 다음 큰 단계에서 구현.

## 첫 vertical slice 이후 큰 단계

- 캐릭터 레벨/강화/성장 UI
- 진화 form 데이터/외형/애니/VFX/전투 효과/저장
- 기본 10종 이후 캐릭터 풀
- 모집 및 다양한 획득 경로
- 10칸 수동 편성
- 특수 스테이지 런타임/제한 evaluator/복합 trigger DSL
- 제2장 이상 진도 캠페인
- 2인 협동 → 1v1 → 2v2

## 개발 원칙 재확인

- GitHub `main` 정본.
- 새 코드를 옛 hotfix/override 위에 덧씌우지 않는다.
- 대체된 상수/함수/워크플로/진단 결과는 필요한 결론을 정본으로 옮긴 뒤 삭제한다.
- 문서·content JSON·실제 코드·테스트가 서로 다른 규칙을 가진 채 장기 방치되지 않게 한다.

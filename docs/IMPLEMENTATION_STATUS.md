## 3. 스테이지 시스템

- `PROGRESSION` 진도 / `SPECIAL` 특수 두 축을 정본화.
- 현재 제1장 20개는 모두 진도 스테이지.
- 모든 진도 스테이지는 싱글 클리어 가능해야 한다.
- 특수 스테이지는 보스, 외전, 이벤트, 캐릭터/진화 재료, 제한전, 생존, 러시, 도전 콘텐츠용 별도 축.
- 난이도는 1~12. 현재 제1장은 1~9, ST20=9.
- 스키마에 `stageType`, `playerUnitCap`, `enemyUnitCap`, `formationRestrictions`, `specialRules`가 존재한다.
- 현재 제1장에 생략된 값은 `PROGRESSION / 50 / 50 / 제한 없음 / 특수 규칙 없음`으로 정규화.
- 편성 제한 스키마는 희귀도 허용/상한, 역할, 비용 상한, 필요/금지 태그, 최대 편성 종류, 동일 세력 제한까지 표현한다.
- `specialRules`는 향후 등록된 deterministic rule ID만 실제 실행하도록 설계한다.
- 현재 실제 웨이브 런타임은 `atTick` 기반. 거점 HP, 특정 적 사망, 누적 처치/사망, 페이즈, AND/OR 복합 trigger evaluator는 설계만 완료되고 아직 미구현.
- 특수 스테이지 실제 콘텐츠 파일/선택 UI/보상 모델도 아직 미구현.

## 4. 협동 정본

- 2인 협동: 플레이어당 5칸, 팀 전체 10칸.
- 공유: 거점 HP, 승패, 거점 병기.
- 개인: 보급, 보급소, 생산 쿨다운.
- 협동은 동일 스테이지를 싱글보다 실질적으로 수월하게 공략할 수 있는 선택지.
- `협동 권장` 태그/경고는 사용하지 않는다.
- 필요 시 협동 보정은 적 최대 HP / 적 공격력 / 적 거점 최대 HP만 단순 배율 조정한다.
- 협동 때문에 적 이동속도, 공격주기, 사거리, KB, 스폰 시간, 적 수, 웨이브, 패턴, AI를 바꾸지 않는다.
- solo/coop 스테이지를 두 벌로 복제하지 않는다.
- 정확한 협동 배율과 실제 멀티 런타임은 아직 미구현.

## 5. 솔로 일시정지

- 전투 HUD 일시정지 버튼 구현.
- PC `P`, `ESC` 지원.
- 정지 중 simulation tick, 보급, 쿨다운, 적 스폰, 이동/공격, 투사체 진행이 멈춘다.
- Phaser tween도 pause/resume.
- 정지 중 소환/보급소/전선포 입력 차단.
- 세로 모바일 가드 중에도 simulation이 accumulator 이전에 정지한다.
- 멀티에서는 개별 사용자가 전체 전투를 멈추지 않는 방향.

## 6. PC 전투 단축키 / 입력 피드백

- PC `1 2 3 4 5 6 7 8 9 0` = 현재 전투 편성의 1~10번째 슬롯.
- 단축키는 전역 캐릭터 목록이 아니라 `activeSlots` 순서를 참조한다.
- `Q` = 보급소 강화.
- `E` = 전선포.
- `P` / `ESC` = 일시정지.
- 키 반복을 별도로 막지 않아 연타/키 홀드 플레이가 가능하다.
- 마우스/터치와 키보드는 `trySpawnSlot / tryUpgradeSupplyInput / tryFireBaseWeaponInput` 공통 경로를 사용한다.
- 소환 쿨다운, 보급 부족, 동시 출격 한도, 잠긴 슬롯, 보급소 강화 실패/MAX, 전선포 쿨다운/대기 같은 정상 실패 입력에서는 화면을 흔들지 않는다.
- 잠긴 스테이지 클릭, 승리 저장 중 버튼 클릭도 조용히 무시한다.
- 현재 camera shake는 **전선포 성공 발사 / 강한 유닛 피격 / 거점 피격** 세 실제 전투 충격 경로에만 존재하도록 테스트가 고정한다.

## 7. PC / 모바일 UI 분리

공유 데이터/게임 로직 위에서 **PC 상세 UI와 compact 모바일 UI를 명시적으로 분리**한다. 모바일을 고친다는 이유로 PC 상세 정보나 단축키가 사라지지 않게 회귀 테스트를 둔다.

### 공통 모바일 기준

- compact 기준: `min(width,height) <= 540`.
- 세로 모바일은 가로 전환 안내를 표시하고 전투 simulation을 정지한다.
- 공용 버튼은 `pointerout`과 `pointerupoutside`에서도 scale을 1로 복구한다. 손가락이 버튼 밖으로 미끄러져도 눌린 모양으로 고착되지 않는다.

### 전투

- PC: 1~0/Q/E 단축키 표기 유지.
- 모바일: 1~0/Q/E 시각 표시는 숨기고 캐릭터명, 비용, 쿨다운, 보급소, 전선포 상태를 크게 표시.
- compact 소환 버튼 높이 80, PC 62.
- compact 보급소/전선포 버튼 높이 76, PC 60.
- compact 하단 HUD는 y=540~720 안에 배치.
- 소환 두 줄 중심 y=582/662, 우측 컨트롤도 y=582/662.
- 다섯 번째 소환칸과 우측 컨트롤 사이 19 logical px 이상 간격을 회귀 테스트로 검증.

### 스테이지 선택

- PC: 전장 테마, mapLength, 부제, 확정 보물, 동료 보상 등 상세 카드 유지.
- 모바일: 스테이지명, 난이도, 클리어/잠금, 보물, 동료 보상, 전투 버튼 중심으로 축약.
- 5성 레거시 UI는 제거되어 `난이도 N / 12`를 사용한다.

### 편성

- PC: 희귀도, 이름, 역할/비용, 속성, 특효, 캐릭터 설명 유지.
- 모바일: 이름, 역할/비용, 속성/특효, 해금 조건 중심. 긴 설명 생략.
- compact 초상화 기준 높이를 132로 사용하며 PC는 152 유지.
- 플레이어 최대 displayScale 1.12 기준으로 둘째 줄 초상화가 첫째 줄 카드 하단을 침범하지 않도록 기하 검사를 추가했다.
- 미해금 compact 조건 문구 Y좌표는 `y + 62`로 감사/고정. 메인·결과 수정 중 잘못 `y + 56`으로 되돌아간 회귀를 diff에서 발견해 즉시 복구했다.

### 도감

- PC: 캐릭터 설명, HP/공격/사거리/재생산, 보물 획득처 상세 유지.
- 모바일: 이름, 역할/비용, 속성/특효, 핵심 HP/공격/사거리, 보물 이름/효과/획득 상태 중심으로 축약.

### 메인 화면

- PC: 기존 전체 소개 문구, 완전한 진행도 분모, `PRE-ALPHA` 표기 유지.
- 모바일: 소개 문구와 진행도 문구를 짧게 줄이고 메인 3버튼 높이를 108로 확대한다.
- PC 버튼 높이는 기존 92 유지.

### 결과 화면

- PC: 기존 첫 클리어/저장/실패 상세 문구 유지.
- 모바일: 저장 상태와 동료 보상 문구를 짧게 표시하고 보물 효과를 넓은 word-wrap 영역으로 표시.
- compact 결과 버튼 높이 84, PC 68.
- 결과 저장이 끝나기 전 버튼은 조용히 무시한다.

## 9. 제1장 후반 baseline / ST20

과거 ST20 실패 원인은 보스 누락이 아니라 저보급 경제에 비해 너무 빠른 초반 압박과 단순 baseline의 값싼 유닛 과소비가 겹친 것이었다.

현재 후반 baseline은 ST16~20에만 적용한다.

- 적이 오기 전 싼 병력 최대 3기로 전선을 만들고 저축.
- 실제 5회 배치 후 Lv3 보급소 투자를 허용.
- 강화비 부족 시 값싼 유닛을 더 뽑지 않고 강화비를 모음.
- 적이 있을 때 적 속성, 명시적 특효, 광역 가치, 사거리, 체력, 실제 보급 대기시간을 함께 평가.
- 최대 약 12초 안에 구매 가능한 준비 완료 유닛만 저축 후보.
- 전선 0기면 즉시 구매 가능한 HP/비용 효율 앵커 우선.
- 공허현자는 ST20 보상이므로 ST20 전투에서 사용하지 않는다.

현재 ST20 웨이브:

- 방패병 2기: tick450, 첫 압박15초.
- 광전사 1기: tick1000, 약33.3초.
- 황금가면 대주술사: tick1500, 50초.
- 저격술사: tick1800, 60초.
- 철문장군: tick2400, 80초.
- 시작 보급300, 거점4000/7200, mapLength1280 유지.
- 두 보스 능력치는 이 수정에서 너프하지 않았다.

소스 충실 독립 결정론 재현 결과:

- 변경 전 과거 ST20 109.7초 패배를 스폰 수까지 동일하게 먼저 재현해 모델 일치를 확인했다.
- ST1~15: 기존 각 테스트 제한 안에서 전부 승리.
- ST16 약138.1초 승리.
- ST17 약165.2초 승리.
- ST18 약78.8초 승리.
- ST19 약102.5초 승리 + 황금가면 실제 등장.
- ST20 약411.4초 승리 + 황금가면/철문장군 모두 실제 등장.
- 따라서 **소스 충실 독립 재현 기준으로 ST1~20 합법 baseline은 통과**한다.
- 이것을 실제 `npm test`/Actions green이라고 주장하지 않는다.

## 10. 캐릭터 / 진행 / 메타

- final campaign 테스트는 ST20 15초 오프닝, 50초 황금가면, 80초 철문장군 타이밍을 고정한다.
- `battle-ui-wiring.test.ts`는 다음을 정적 회귀 검사한다.
  - 1~0/Q/E/P/ESC 및 activeSlots 기반 입력.
  - 마우스/키보드 공통 실패 경로.
  - camera shake 정확히 3개 전투 충격 경로.
  - compact 전투 HUD와 하단 hitbox geometry.
  - 스테이지/편성 PC 상세정보 유지 + 모바일 축약.
  - 메인/결과 PC 상세 문구 유지 + compact 별도 레이아웃.
  - 공용 버튼 pointer 취소 시 scale 복구.
  - compact 편성 초상화 행간 미침범.
  - 난이도 12단계 UI.
- `catalog-boss-mobile-ui.test.ts`는 세로 simulation 선차단, 540px compact breakpoint, 도감 PC 상세/모바일 축약, 보스 경고를 검사한다.
- 이번 UI 감사에서 수정한 파일은 UI와 UI 테스트이며 전투 판정/경제/스폰/content 수치는 변경하지 않았다.
- 이전 마지막 실제 완전 검증에서는 install/typecheck/build 성공, 당시 테스트 실패는 과거 ST20 baseline 1개였다.
- 현재 `.github/workflows/ci.yml`은 main push/PR에서 install → typecheck → test → build를 실행하도록 설정되어 있다.
- 현재 연결의 workflow-run 조회는 PR-triggered 실행만 반환하며 direct-main push 결과는 보이지 않는다.
- 최신 commit combined-status도 status context가 없어 현재 HEAD의 실제 CI green/red는 이 연결로 확인하지 못했다.
- **확인되지 않은 CI 성공을 주장하지 않는다.**

## 14. 첫 사용자 테스트 전 남은 항목

1. 현재 HEAD의 실제 install → typecheck → test → build 결과를 직접 확인할 실행 경로 확보.
2. PC/compact 모바일의 코드/정적 레이아웃 분리는 완료됐지만 **실제 렌더된 PC 브라우저와 작은 가로폰에서 텍스트 겹침, 터치감, 카드/아트 잘림을 최종 시각 확인**해야 한다.
3. Cloudflare Pages 실제 프로젝트 URL/최신 배포 상태 확인. 저장소에는 현재 명시적인 `pages.dev` URL/프로젝트 설정을 찾지 못했다.
4. 첫 수동 테스트 게이트 전체를 확인한 뒤에만 사용자에게 테스트를 요청한다.

## 16. 개발 원칙 재확인

- GitHub `main` 정본.
- 새 코드를 옛 hotfix/override 위에 덧씌우지 않는다.
- 대체된 상수/함수/워크플로/진단 결과는 필요한 결론을 정본으로 옮긴 뒤 제거한다.
- 같은 책임은 하나의 권위 경로만 남긴다.
- 문서·content JSON·코드·테스트가 서로 다른 규칙을 가진 채 방치되지 않게 한다.

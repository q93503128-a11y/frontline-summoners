## 2026-08-24 — campaign vertical slice 0.0.18

### 문서 정본

- `docs/CANONICAL.md`: 현재 **v0.31**. 최신 핵심 결정 정본.
- `docs/GAME_DESIGN_FULL.md`: 통합 전체 기획서.

- 구체 콘텐츠 수치는 `content/` JSON이 우선한다.

- 공유 `packages/sim` 30Hz 결정적 전투 코어 사용.

### 스테이지 시스템 정밀 기획 복원

- 스테이지를 `PROGRESSION(진도)` / `SPECIAL(특수)` 두 축으로 분리하는 원칙을 정본화.
- 현재 제1장 20개는 모두 진도 스테이지로 정규화됨.
- 진도 스테이지는 모두 싱글 클리어 가능해야 함.
- 특수 스테이지는 보스·외전·이벤트·캐릭터/진화재료·제한전·생존전·러시·도전전 등 별도 콘텐츠 축으로 사용.
- 기존 난이도 1~5 스키마를 **1~12**로 확장.
- 제1장 실제 JSON도 1~9로 재평가하여 1~5 압축 상태를 제거. ST20은 난이도 9이며 10~12는 이후 더 높은 체급 콘텐츠에 남겨둠.
- 스키마에 `stageType`, `playerUnitCap`, `enemyUnitCap`, `formationRestrictions`, `specialRules` 추가.
- 입력값이 없는 현재 제1장은 `PROGRESSION / 50 / 50 / 제한 없음 / 특수규칙 없음`으로 정규화.
- `formationRestrictions`는 희귀도 허용/상한, 역할, 비용 상한, 필요/금지 유닛 태그, 최대 편성 종류, 동일 세력 제한을 표현할 수 있는 데이터 구조까지 복원.
- `specialRules`는 향후 등록된 deterministic rule ID만 실제 실행하도록 설계. 현재는 스키마 저장/검증 틀만 있고 런타임 규칙 레지스트리는 아직 미구현.
- 현재 웨이브 런타임은 `atTick` 시간 기반이 정본. 거점 HP/특정 적 사망/누적 처치·사망/페이즈/AND·OR 트리거 evaluator는 상세 설계 복원 완료, 런타임 구현은 아직 후속 작업.
- 특수 스테이지 전용 콘텐츠 파일/선택 UI/보상 모델도 아직 미구현. 제1장 campaign parser가 보물을 필수로 요구하므로 SPECIAL 실콘텐츠를 바로 넣은 상태는 아님.

### 협동 정본

- 2인 협동은 플레이어당 5칸, 팀 전체 10칸.
- 공유: 거점 HP, 승패, 거점 병기.
- 개인: 보급, 보급소, 생산 쿨다운.
- 협동은 어려운 동일 스테이지를 싱글보다 실질적으로 수월하게 공략할 수 있는 선택지로 설계.
- **`협동 권장` 태그는 사용하지 않음.** 싱글 플레이를 열등한 선택처럼 보이게 만드는 UI/문구 금지.
- 협동 난이도 보정은 필요 시 **적 최대 HP / 적 공격력 / 적 거점 최대 HP만 단순 배율** 적용.
- 협동 때문에 이동속도·공격주기·사거리·KB·스폰 시간·적 수·웨이브·패턴·AI를 바꾸거나 solo/coop 스테이지를 두 벌로 복제하지 않음.
- 정확한 협동 배율은 멀티 구현 후 2인 baseline/실플레이로 결정. 아직 수치 확정/런타임 구현 전.

### 제1장 경제 / 전투 템포

- 이전 ST1 `시작 520 / Lv1 65초당 / 지갑 3000` 폐기.
- 현재 기본 보급소: Lv1 `12/s·1000` → Lv2 `20/s·1400` → Lv3 `30/s·1900` → Lv4 `42/s·2500` → Lv5 `56/s·3200` → Lv6 `72/s·4000` → Lv7 `90/s·5000` → Lv8 `110/s·6200`.
- 강화비: 160 / 260 / 390 / 560 / 760 / 1000 / 1300.
- 시작 보급은 ST1~7 50→110, ST8 160 이후 단계적으로 증가하여 ST19 280 / ST20 300.
- ST1 아군/적 거점 900/800. ST20 4000/7200.
- 징집병 이속 3, 첫 일반 적 2, 명시적 돌격 역할 약 4.
- 적 처치 보급은 초반 스노우볼을 막되 저보급 환경에서 전투가 정체되지 않도록 역할별 조정.
- Lv1 최대 보급 1000보다 비싼 왕실기사/이단주술사는 보급소 업그레이드가 필요.
- deterministic 캠페인 baseline은 실제 그 시점에 얻은 캐릭터와 보물만 사용해야 함.

### 제1장 최종 baseline 현황

가장 최근 완료된 전수/집중 진단의 결론을 정본 상태로 보존한다.

- ST1~19: 당시 합법 순차 baseline에서 승리권 확인.
- ST19: 황금 보스 실제 등장 확인 후 승리.
- ST20: 황금 보스와 철문 보스 **둘 다 실제 등장**하지만 baseline이 약 109.7초에 패배. 적 거점은 사실상 손상되지 않음.
- ST20에서 보스 등장 자체가 누락되는 문제는 아님.
- 단순 보스 지연, 시작 보급 상향, 철퇴병 수 감소만으로는 안정적으로 해결되지 않았고, 일부 조합은 장기 TIMEOUT으로 변함.
- 원인 후보는 ST20에서 baseline이 저비용 유닛에 보급을 소모해 실제 해금된 고비용 전문 카운터(이단주술사/화염술사/왕실기사 등)를 충분히 운용하지 못하는 것.
- 이전 일회성 trait-aware counter probe는 결과를 남기지 못하고 정체되어 제거됨. 실패한 임시 workflow를 레거시로 유지하지 않음.
- 따라서 **첫 사용자 테스트 게이트는 아직 통과하지 않았다.** ST20은 다음 전투 밸런스 작업에서 다시 해결해야 함.

- 신규 계정: 징집병 1종 + STAGE 1만 개방.

## 개발 원칙 재확인

- GitHub `main` 정본.
- 새 코드를 옛 hotfix/override 위에 덧씌우지 않는다.
- 대체된 상수/함수/워크플로/진단 결과는 필요한 결론을 정본으로 옮긴 뒤 삭제한다.
- 문서·content JSON·실제 코드·테스트가 서로 다른 규칙을 가진 채 장기 방치되지 않게 한다.

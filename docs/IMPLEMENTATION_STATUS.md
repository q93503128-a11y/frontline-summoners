# 구현 상태

이 문서는 `docs/CANONICAL.md`를 대체하지 않는다. 매 작업 전 정본을 먼저 읽고, 이 문서는 현재 구현 진행도만 기록한다.

## 2026-08-23 — campaign vertical slice 0.0.8

### 기반
- Cloudflare Pages `frontline-summoners`: GitHub `main` 자동 배포 연결 완료.
- Worker/DO/D1 골격 배포 완료.
- `packages/sim`: 30Hz 이동/탐지/공격 프레임/동시피해/자연 KB/DYING/기지승패/stateHash 구현.
- `packages/sim/playable`: 보급, 보급소 Lv.1~8, 비용/재생산 쿨다운, 적 웨이브, 처치 보급, 기본 거점 병기 구현.

### 첫 브라우저 하네스 피드백 반영
- 5개 도형 유닛만 노출된 개발자용 하네스를 사용자 테스트 빌드로 취급하지 않는다.
- 메인/스테이지/편성/전투/결과 흐름과 실제 스프라이트, 거점 HP, 선명한 UI가 갖춰진 뒤 사용자 테스트를 요청한다.
- 내부 렌더 기준은 1280×720이다.
- 보물은 각 스테이지 첫 클리어 100% 확정 획득이며 등급/드랍 RNG를 쓰지 않는다.

### 진행 구조
- 신규 게스트 진행은 `징집병` 1종만 보유하고 STAGE 1만 개방한다.
- 이전 PRE-ALPHA IndexedDB 진행은 저장 스키마 v2에서 초기화해 구형 자유개방 진행이 새 캠페인에 섞이지 않게 했다.
- 앞 스테이지를 클리어해야 다음 스테이지가 열린다.
- 첫 클리어 캐릭터 해금: ST1 방벽기사 → ST2 수렵창병 → ST4 결투검사 → ST6 청창대 → ST8 전투마도사 → ST10 화염술사 → ST13 왕실기사 → ST16 이단주술사 → ST20 공허현자.
- 보유 캐릭터 10종 이하인 현재 단계에서는 보유 캐릭터를 전부 자동 편성하고 미해금 슬롯은 전투/편성 UI에서 잠금 표시한다.
- 결과 화면에서 확정 보물, 신규 동료 합류, 다음 스테이지 개방을 분리해 표시한다.
- 승리 결과 저장이 끝나기 전에 화면을 이탈해 다음 스테이지가 잠긴 것처럼 보일 수 있던 비동기 레이스를 차단했다.

### 콘텐츠/맵
- 플레이어 10종(C3/B3/A2/S1/SS1) 로스터.
- 적 8종 + 보스 2종.
- 제1장 20스테이지.
- 스테이지 선택은 5개씩 4페이지로 나눠 화면 밖으로 넘치지 않게 했다.
- 전장 계열 7종: 풀바람 평원 / 붉은 협곡 / 불붙은 곡창지대 / 안개 폐허 / 달그늘 고개 / 철문 요새권 / 황금가면 관문.
- 각 스테이지는 별도 `decorSeed`와 780~1340 범위의 전장 길이를 사용한다.
- 맵 계열별 하늘/원경/중경/지면/장식/거점 팔레트를 달리하고, 같은 계열 내부에서도 장식 위치를 바꾼다.
- 전장 길이는 시각 정보가 아니라 실제 `packages/sim` mapLength로 전달된다.

### JSON 단일 정본화
- `content/units/chapter-01.json`: 플레이어 10종 수치/역할/비용/공격 타이밍 정본.
- `content/enemies/chapter-01.json`: 적 8종 + 보스 2종 수치/처치 보급/공격 타이밍 정본.
- `content/stages/chapter-01.json`: 제1장 20스테이지 맵/웨이브/보물/해금 정본.
- `apps/client/src/prototype.ts`의 대규모 하드코딩 배열을 제거하고 위 3개 JSON을 `parseCampaignBundle()`로 검증한 뒤 전투 런타임 객체로 변환한다.
- 캐릭터/적/스테이지 중 한쪽 코드만 수정해 데이터가 갈라지는 이중 정본 구조를 제거했다.
- `@frontline/content-schema`는 희귀도/역할/타겟 모드, 수치 범위, 공격 프레임, ID 중복, 적 참조, 캐릭터 해금, 보물 중복, 웨이브 순서, 맵 다양성을 검증한다.
- 비스타터 9종이 캠페인에서 정확히 한 번씩 해금되지 않으면 검증 실패한다.

### 거점 병기 1차
- 전투 시작 시 충전 완료된 `전선포` 버튼을 추가했다.
- 1차 수치: 적 기지에는 피해를 주지 않고 현재 타겟 가능한 적 전체에 동시 90 피해, 재충전 900틱(30초).
- 별도 UI 꼼수로 HP를 수정하지 않고 `packages/sim`의 일반 피해 패킷과 자연 KB/DYING 규칙을 재사용한다.
- 전선포로 적을 처치해도 일반 공격 처치와 동일하게 처치 보급을 지급한다.
- 전선포 상태도 playable stateHash에 포함해 동일 명령 로그의 결정성을 유지한다.
- 화면에는 충전 남은 시간, 발사 가능 상태, 짧은 광선/섬광/화면 흔들림을 표시한다.
- 강제 밀치기는 아직 넣지 않았다. `ForcedDisplacement` 정식 규칙을 정의하기 전까지 자연 KB와 섞어 임시 구현하지 않는다.

### 아트/UI 안정화
- LuizMelo CC0 계열 7개 아트 패밀리의 Idle/Run/Attack을 사용한다.
- 실제 플레이 중 외부 GitHub raw URL을 읽던 구조를 제거했다.
- `tools/vendor-client-assets.mjs`가 클라이언트 `prebuild`/`predev`에서 핀 고정된 원본 21개 PNG를 로컬 `public/assets/characters`로 복사한다.
- 다운로드는 15초 타임아웃 + 최대 3회 재시도이며, PNG 시그니처와 기대 시트 해상도를 검사한다. 하나라도 틀리면 배포 빌드를 실패시킨다.
- Hero Knight Idle 원본이 1980×180 / 11프레임인데 프레임 폭이 231로 잘못 기록된 오류를 찾아 180으로 수정했다.
- Asset Registry를 현재 빌드 시 vendoring 구조에 맞게 갱신했다.
- 모든 플레이어/적 20종이 `UNIT_ART`와 존재하는 아트 패밀리에 연결되는지 자동검사를 추가했다.
- 양쪽 거점 HP바 + 현재/최대 HP 숫자, 일반 화면의 개발자 debug 텍스트 비노출을 유지한다.

### 공격 연출 / 타격 동기화
- 각 아트 패밀리에 `attackContactFrame`을 명시했다. 공격 시트 전체를 단순 균등 재생하지 않는다.
- `apps/client/src/combat-visuals.ts`의 순수 매핑 함수가 시뮬레이션 첫 `hitFrame`과 지정된 스프라이트 접촉 포즈를 정확히 일치시킨다.
- 단일 히트 공격은 실제 피해가 적용된 직후 Backswing으로 상태가 넘어가더라도 contact pose가 유지되도록 상태 전환 의미를 반영했다.
- 이동/대기 반복 애니메이션은 simulationId 기반 시각 phase offset을 적용해 같은 종류 병력이 완전히 같은 박자로 걷는 현상을 줄였다. 전투 판정에는 영향이 없다.
- 유닛 HP 감소를 실제 렌더 상태에서 감지해 경/중/강 타격 섬광을 발생시킨다. 임의 타이머가 아니라 실제 피해 결과를 기준으로 한다.
- 거점 HP 감소도 동일하게 감지해 거점 섬광/먼지/중량별 화면 흔들림을 발생시킨다.
- 캐릭터 아래 반투명 지면 그림자를 추가해 서로 다른 원본 시트의 투명 여백 때문에 캐릭터가 떠 보이는 문제를 완화했다.
- 새 유닛 등장 시 짧은 지면 소환 섬광을 추가했다.

### 초반 전투 baseline
- 신규 계정 ST1은 징집병만 사용한 자동 baseline 전투로 실제 30Hz 코어를 끝까지 진행한다.
- 승리 여부만 보던 기존 검사를 강화해 자동 baseline 기준 60초 이내 승리 + 아군 거점 HP 50% 이상 유지까지 요구한다.
- 이번 패스에서는 해당 기준을 먼저 고정하고, 불필요한 감각 조정을 이유로 JSON 전투 수치를 임의 변경하지 않았다.

### 자동 회귀검사
- 신규 저장 = `militia` 1종만 보유.
- 신규 저장 = STAGE 1만 진입 가능.
- ST1 클리어 = ST2 + 방벽기사만 추가 개방.
- 전체 제1장 클리어 = 플레이어 10종 전부 해금.

- 비스타터 캐릭터 9종의 정확한 해금 마일스톤.

- 전선포 초기 충전, 재충전, 동시 피해, 자연 KB, 처치 보급, stateHash 결정성.
- 플레이어/적 20종 전부의 아트 매핑 존재 여부와 로컬 에셋 URL 사용 여부.

- ST1 신규 계정 baseline의 승리/전투시간/거점 생존 여유 검사.

## 현재 검증 중

1. 최신 `main`의 실제 Cloudflare/GitHub build 결과. 연결 도구에서 push 기반 Actions check-run을 안정적으로 열람하지 못해 통과를 단정하지 않는다.
2. build-time vendoring의 21개 PNG 기대 해상도 전수 대조.
3. 7개 전장 계열에서 캐릭터 실제 발 위치·그림자·거점 상대 크기 수동 시각 검수.
4. 7개 공격 시트의 지정 contact frame이 실제 칼날/창/마법 발사 순간과 가장 자연스러운지 브라우저 수동 검수.
5. 모바일/PC 스테이지 페이지와 전투 하단 슬롯 가독성.

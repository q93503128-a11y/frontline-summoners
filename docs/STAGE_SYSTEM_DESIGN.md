# 전선소환전 — 스테이지·특수 스테이지·협동 정밀 기획 정본

문서 상태: **복원된 상세 정본 보조 문서**  
상위 정본: `docs/CANONICAL.md`  
전체 상세본: `docs/GAME_DESIGN_FULL.md`  
실제 구현 상태: `docs/IMPLEMENTATION_STATUS.md`

> 이 문서는 초기 정밀 기획에서 통합 과정 중 축약된 스테이지 DSL, 출격 제한, 편성 제한, 특수 규칙, 난이도, 협동 규칙을 복원한다. 스테이지 시스템과 협동 난이도에 관해서는 `CANONICAL.md`와 충돌하지 않는 범위에서 이 문서가 `GAME_DESIGN_FULL.md`의 축약된 표현보다 우선한다.

---

## 1. 스테이지의 두 축

스테이지는 플레이 목적에 따라 **진도 스테이지**와 **특수 스테이지**로 분리한다.

### 1.1 진도 스테이지

- 메인 세계 진행과 장(Chapter) 진행을 담당한다.
- 앞 스테이지를 깨면 다음 스테이지가 순차 개방되는 것이 기본이다.
- 핵심 캐릭터, 지역, 기능, 다음 장 등 주요 진행 해금의 기준이 된다.
- 모든 진도 스테이지는 싱글 플레이만으로 정상 클리어 가능해야 한다.
- 협동으로 같은 스테이지를 플레이할 수 있어도 싱글을 열등하거나 잘못된 선택처럼 표현하지 않는다.
- 현재 제1장 20스테이지는 첫 번째 진도 캠페인이다.

### 1.2 특수 스테이지

메인 진도와 분리된 별도 콘텐츠 축이다. 다음과 같은 용도를 포함할 수 있다.

- 특정 보스 / 강적
- 외전 / 사이드 스토리
- 이벤트
- 캐릭터 획득
- 진화 재료 / 특수 재료 획득
- 제한 편성전
- 출격 수 제한전
- 시간 제한 / 생존전
- 연속전 / 러시
- 특정 속성·역할을 활용하는 도전전
- 주간·기간 콘텐츠가 필요할 경우 해당 콘텐츠

특수 스테이지의 존재가 메인 진도 클리어의 필수 벽이 되어서는 안 된다. 단, 선택형 캐릭터·진화·수집 콘텐츠의 획득처가 될 수 있다.

## 2. 난이도 표기

기존 1~5 단계는 폐기하고 **1~12 단계**를 정본으로 사용한다.

- 난이도 값은 절대 전투력 공식이 아니라 플레이어가 체감 난도를 비교하기 위한 세밀한 표기다.
- 동일 장 안에서도 필요하면 서로 다른 난이도 값을 촘촘히 배치한다.
- 특수 스테이지와 진도 스테이지가 같은 1~12 축을 사용해 대략적인 체급을 비교할 수 있게 한다.
- `협동 권장` 같은 별도 태그는 만들지 않는다.
- 협동이 더 유리하더라도 UI가 싱글 플레이를 꺼리게 만드는 문구를 사용하지 않는다.

### 2.1 난이도를 만드는 수단

난이도를 단순 HP/공격 배율 하나로 만들지 않는다. 싱글 스테이지 설계에서는 다음을 조합한다.

- 적 종류와 전후열 조합
- 적 스폰 시점과 간격
- 한 번에 겹치는 적 수
- 맵 길이
- 적/아군 사거리 관계
- 시작 보급
- 처치 보급과 경제 압박
- 보급소 투자 타이밍
- 거점 HP
- 거점 HP·시간·처치 수 등에 따른 트리거
- 출격 가능 총 개체 수
- 편성 제한
- 특수 규칙

따라서 `난이도 8`이 항상 `난이도 7`보다 모든 적 능력치가 높다는 뜻은 아니다.

## 3. 기본 출격 제한

### 3.1 전장 동시 개체 수

- 기본 아군 동시 출격 한도: **50기**.
- 기본 적 동시 출격 한도: **50기**를 현재 구현 기본값으로 사용한다.
- 살아 있는 개체 수가 한도에 도달하면 추가 소환/스폰은 보류된다.
- 죽는 중(`DYING`)인 개체는 살아 있는 출격 수에 포함하지 않는다.
- 이 제한은 10칸 편성과 별개다. 10칸은 전투에 가져가는 **종류 수**, 출격 한도는 전장에 동시에 존재 가능한 **개체 수**다.

### 3.2 스테이지별 출격 제한

스테이지 데이터가 `playerUnitCap`, `enemyUnitCap`을 직접 지정할 수 있어야 한다.

특수 스테이지에서는 예를 들어 다음과 같은 아군 제한을 사용할 수 있다.

- 30기
- 20기
- 15기
- 10기
- 5기
- 3기
- 1기

이 값들은 고정 난이도 계단이 아니라 설계 도구다. 특히 낮은 출격 한도에서는 값싼 유닛을 무지성으로 채우는 행동이 강한 유닛의 자리를 막으므로 전투 중 의사결정 자체가 달라진다.

보물 등 계정 성장 효과가 출격 수를 늘리는 경우, **스테이지의 기본 한도에 성장 보정을 적용**한다. 스테이지 제한을 무시하고 전역 50으로 되돌리는 별도 경로를 만들지 않는다.

## 4. 정밀 스테이지 데이터 모델

초기 정밀 기획의 스테이지 데이터는 다음 항목을 데이터로 조립할 수 있어야 한다.

- 스테이지 ID / 장 / 이름 / 설명
- 스테이지 종류: 진도 / 특수
- 난이도 1~12
- 맵 길이
- 아군 거점 HP
- 적 거점 HP
- 시작 보급
- 아군 동시 출격 한도
- 적 동시 출격 한도
- 적 스폰 목록
- 스폰 트리거
- 적 능력 배율이 필요한 경우 해당 배율
- 보상
- 편성 제한
- 특수 규칙
- 배경 테마 / 장식 seed

스테이지별 로직을 UI나 전투 코드에 직접 하드코딩하지 않고, 가능한 한 데이터 → 검증 → 결정론적 전투 코어의 한 경로로 내린다.

## 5. 스폰 / 페이즈 트리거 DSL

현재 제1장 구현은 시간 기반 `atTick` 웨이브가 우선이지만, 정밀 기획의 최종 목표는 아래 트리거를 데이터로 표현하는 것이다.

### 5.1 기본 트리거

- 전투 시작 후 특정 시간
- 적 거점 HP가 특정 비율 이하
- 아군 거점 HP가 특정 비율 이하
- 특정 적 사망
- 누적 적 처치 수
- 누적 아군 사망 수
- 특정 페이즈 완료

### 5.2 복합 트리거

`AND / OR` 조합을 지원하는 방향으로 설계한다.

복원된 초기 예시:

- 20초 경과 → 늑대 3기 등장
- 적 거점 HP 75% 이하 → 기사 분대 등장
- 중간보스 사망 → 2페이즈 시작
- 아군 20기 사망 → 특수 적 등장
- 60초 경과 **AND** 적 거점 HP 50% 이하 → 후속 웨이브 시작

복합 조건은 순서 의존 임시 코드가 아니라 동일한 deterministic trigger evaluator를 사용해야 한다.

## 6. 편성 제한 DSL

편성 제한은 특수 스테이지의 핵심 설계 도구다. 제한을 적용하기 위해 유닛은 장기적으로 희귀도·역할 외에 태그와 세력 정보를 가질 수 있다.

복원된 초기 제한 예시:

- C/B 희귀도만 사용 가능
- A 이하만 사용 가능
- 근거리 태그만 사용 가능
- 생산비 1000 이하만 사용 가능
- 인간형 태그 사용 금지
- 마법형 태그만 사용 가능
- 최대 5종만 편성 가능
- 같은 세력 캐릭터만 편성 가능

### 6.1 제한 원칙

- 제한은 스테이지 입장 전에 명확히 표시한다.
- 입장 후 몰래 캐릭터를 비활성화하지 않는다.
- 여러 제한이 겹치면 편성 화면에서 최종 사용 가능 캐릭터를 즉시 판별할 수 있어야 한다.
- 제한을 만족하는 캐릭터가 하나도 없는 상태로 스테이지를 열어 진행 불능에 빠뜨리지 않는다.
- 제한전 때문에 특정 고희귀 캐릭터 하나가 사실상 필수가 되는 상황을 피한다.

---

## 7. 특수 규칙

`specialRules`는 자유로운 임시 문자열 핫픽스가 아니라 **등록된 규칙 ID**를 참조하는 데이터 경로로 설계한다.

예시 후보:

- 거점 병기 사용 불가
- 보급소 최대 레벨 제한
- 전투 시작 보급 고정
- 특정 역할 재생산 보정
- 시간 제한
- 일정 시간 생존 시 승리
- 특정 보스 처치 시 승리

새 규칙이 필요하면 기존 전투 함수를 뒤에서 override하지 않는다. 규칙 레지스트리와 deterministic simulation 경로를 확장하고, 사용 종료된 임시 구현은 제거한다.

---

## 8. 협동의 위치

협동은 싱글보다 실질적으로 유리한 선택지다. 특히 어려운 스테이지를 친구와 함께 공략하면 체감 난도가 낮아져야 한다.

그러나 다음은 금지한다.

- `협동 권장` 난이도 태그
- 싱글 플레이를 경고하거나 열등한 방식처럼 보이게 하는 UI
- 메인 진도에서 사실상 협동을 강제하는 밸런스
- 협동에서만 추가되는 적 패턴
- 협동에서만 추가되는 적 종류
- 협동에서만 추가되는 웨이브
- 협동 전용 AI 분기

### 8.1 2인 협동 기본 구조

- 플레이어당 편성 5칸.
- 팀 전체 캐릭터 종류 최대 10칸.
- 각 플레이어는 자신의 보급과 보급소를 가진다.
- 거점 HP와 승패는 공유한다.
- 거점 병기는 팀 공유 자원으로 취급한다.
- 두 플레이어의 생산 쿨다운은 각자 관리한다.

### 8.2 협동 난이도 보정

협동에서 적을 보정해야 할 경우 **기존 적의 스탯만 조정**한다.

허용되는 기본 보정 축:

- 적 최대 HP
- 적 공격력
- 적 거점 최대 HP

금지되는 보정 축:

- 이동속도 변화
- 공격주기 변화
- 사거리 변화
- KB 규칙 변화
- 스폰 시점 변화
- 적 수 증가
- 추가 웨이브
- 추가 패턴 / AI

정확한 배율은 실제 2인 baseline과 플레이테스트로 조정한다. 배율을 맞추기 위해 콘텐츠를 복제하거나 `soloStage` / `coopStage` 두 벌로 나누지 않는다.

### 8.3 보상

- 협동이라고 기본 클리어 보상을 깎지 않는다.
- 첫 클리어 보상은 각 플레이어의 진행 상태 기준으로 정상 지급한다.
- 드롭/재료형 보상은 파티원끼리 하나를 나눠 갖는 방식보다 각자의 보상 판정을 기본으로 한다.
- 협동을 반복 강제하기 위한 독점 보상은 두지 않는다.

## 9. 진도와 특수 콘텐츠의 진행 관계

- 진도 스테이지는 세계 진행의 뼈대다.
- 특수 스테이지는 수집·성장·도전의 옆축이다.
- 특정 진도 클리어가 새로운 특수 스테이지를 열 수 있다.
- 특수 스테이지 클리어가 선택형 캐릭터·진화 재료·특수 보상을 열 수 있다.
- 특수 스테이지 미클리어 때문에 다음 메인 진도 자체가 막히는 구조는 기본적으로 사용하지 않는다.

## 10. 구현 우선순위

1. 현재 제1장 20개를 `진도 스테이지`로 명확히 취급한다.
2. 난이도 스키마를 1~12로 확장한다.
3. 현재 simulation에 이미 존재하는 `playerUnitCap / enemyUnitCap`을 스테이지 콘텐츠 스키마와 연결한다.
4. 편성 제한과 `specialRules`의 데이터 스키마를 추가하되, 미구현 규칙을 실제 작동하는 것처럼 UI에 표시하지 않는다.
5. 시간 외 트리거 DSL은 기존 `atTick` 경로와 중복 구현하지 말고 하나의 정규화된 evaluator로 확장한다.
6. 특수 스테이지 선택 UI와 별도 콘텐츠 파일을 추가한다.
7. 2인 협동 구현 시 동일 stage definition을 사용하고 적 HP/공격력/거점 HP만 모드 배율로 조정한다.
8. 모든 제한·트리거·협동 배율은 결정론 테스트와 stateHash 범위에 포함한다.

---

## 11. 금지 사항

- 진도/특수 스테이지를 한 목록에 뒤섞어 목적이 불명확해지는 구조.
- 난이도 5단계에 모든 콘텐츠를 억지로 압축.
- `협동 권장` 태그.
- 협동을 위해 스테이지/웨이브/AI를 복제.
- 출격 제한을 UI에만 표시하고 simulation은 무시하는 구현.
- 편성 제한을 화면별로 각각 다시 계산하는 중복 코드.
- 특수 규칙마다 hotfix/override 파일을 추가하는 방식.
- 구식 제한 규칙을 새 규칙 뒤에 남겨 실행 순서에 의존하는 방식.

이 문서에 명시된 스테이지/협동 규칙을 수정할 때는 `content-schema`, simulation adapter, 관련 테스트, `IMPLEMENTATION_STATUS.md`를 함께 확인한다.

상위 정본: `docs/CANONICAL.md`

이 문서는 1차 완성의 메인 80스테이지, SPECIAL, 난이도, 재클리어 편의, 협동/PvP 연결 규칙을 정의한다. 개별 맵의 정확한 스폰 frame·보상량·배율은 콘텐츠 위키가 정본이다.

## 1. 스테이지 계층

### 1.1 메인

- 1차 완성: 4장 × 20 = 80스테이지.
- 앞 스테이지 순차 개방이 기본.
- 장 최종 클리어는 레벨 상한 해제 + 추가 보상을 제공한다.
- 각 장은 새 속성, 적 역할, 사거리 문법, 상태/공격 구조를 단계적으로 학습시킨다.
- 일부 튜토리얼성 초반전을 제외하면 대부분 `SOLO_OR_COOP`을 목표로 한다.
- 협동 최초 클리어도 **정상 클리어**이며 진행, 첫 클리어 보상, 영구 보상, 다음 스테이지 해금을 모두 인정한다.

### 1.2 SPECIAL

SPECIAL은 큰 카드/묶음 안에 여러 내부 스테이지를 가질 수 있다.

분류:

- 상시 SPECIAL
- 주기 SPECIAL
- 이벤트 SPECIAL
- 기록 SPECIAL

`1회성`은 별도 대분류보다 `첫 클리어 보상 1회` 속성으로 처리한다. 가능한 경우 스테이지 자체는 다시 플레이할 수 있게 남긴다.

### 1.3 SPECIAL 최초 개방

SPECIAL 허브 자체는 **제1장 최종 스테이지 `main_01_020`을 NORMAL_CLEAR한 뒤 처음 열린다.**

```text
main_01_020 NORMAL_CLEAR
→ Chapter 1 완료
→ Lv20 상한 및 장 보상
→ SPECIAL 허브 해금
```

- 솔로/정상 협동 클리어 모두 같은 해금으로 인정한다.
- ST19까지만 진행한 상태에서는 SPECIAL 허브가 열리지 않는다.
- 소탕은 최초 NORMAL_CLEAR를 만들 수 없으므로 최초 SPECIAL 해금을 만들 수 없다.
- 허브가 열렸다고 모든 SPECIAL/모든 단계가 즉시 풀리는 것은 아니다.
- 개별 collection/고단계/기록전은 메인 진행에 따라 추가 해금할 수 있다.

제1장까지는 메인 전투 문법 학습에 집중하고, ST20 이후 메인 2장과 SPECIAL을 자유롭게 오가는 구조를 만든다.

상세 접근 정책은 `SPECIAL_ACCESS_AND_STORY_PRESENTATION.md`를 따른다.

## 2. 난이도 1~12

난이도는 장기 확장 공간을 포함한다.

- 1: 튜토리얼급
- 2: 매우 쉬움
- 3: 쉬움
- 4: 보통 이하
- 5: 보통
- 6: 제법 어려움
- 7: 1차 완성의 일반적인 상위 난도
- 8: 일부 후반 보스/SPECIAL
- 9~12: 후반 성장/업데이트용

**1차 완성에서 9~12를 채우기 위해 억지 고난도를 만들지 않는다.**

난이도 산정 입력:

- 정상 해금 시점의 권장 기본 Lv/+Lv/형태
- 적 총 전투력과 동시 전선 압박
- 첫 30~60초 압박
- 보스 체급/패턴
- 필요한 속성 대응 폭
- 덱 선택 민감도
- 경제 압박/보급소 투자 난도
- 맵 길이/사거리 구조
- 예상 클리어 시간
- deterministic 샘플 시뮬레이션
- 사람 플레이테스트 성공률/재도전 횟수

정확한 점수화와 등급 판정은 `docs/content-wiki/systems/DIFFICULTY_CALIBRATION.md`를 따른다.

## 3. 메인 20스테이지 장 구조

기본 골격:

- ST01~04: 새 문법 소개
- ST05: 첫 복합 응용
- ST06~09: 적 조합/경제/사거리 심화
- ST10: 중간보스 또는 변곡점
- ST11~14: 신규 적/속성/공격 구조
- ST15~18: 복합 압박
- ST19: 최종보스 전조
- ST20: 장 최종전

모든 장을 기계적으로 같은 공식으로 만들지는 않는다. 장별 테마/보스/웨이브 리듬을 달리한다.

현재 설계 지도:

- 1장 `뒤집힌 국경`: NEUTRAL/BEAST, 난이도 1~6
- 2장 `뒤틀린 숲`: NATURE/UNDEAD, 난이도 3~7
- 3장 `마도도시 세라페`: ARCANE/DEMON, 난이도 4~7
- 4장 `기어 제국의 균열`: MACHINE/ANOMALY, 난이도 5~8

개별 80전장의 맵 길이, 기지 HP, 시작 보급, 스폰, 트리거, 목표 시간은 `docs/content-wiki/stages/main/CHAPTER_XX_DETAILED_STAGE_SPECS.md`에서 관리한다.

## 4. 영구 보상

- 각 메인 스테이지 첫 클리어에 확정 영구 보상을 둘 수 있다.
- 같은 효과가 여러 번 반복되어 누적되는 것을 허용한다.
- RNG 드랍률/품질/등급 없음.
- 이동속도 영구 증가 금지.
- 아군 최대 출격 개체 수 영구 증가 금지.
- 사거리 영구 증가는 기본 축으로 사용하지 않는다.

주요 축:

- 전체/역할 HP
- 전체/역할 공격
- 거점 HP
- 시작 보급
- 처치 보급
- 보급소 강화비 감소
- 재생산 감소

모든 감소 적용 뒤 재생산 최소 60F를 강제한다.

장 마지막:

- 1장 → Lv20 상한 + 추가 보상 + SPECIAL 허브 해금
- 2장 → Lv30
- 3장 → Lv40
- 4장 → Lv50 + 1차 메인 엔딩/후반 업데이트 진입 플래그 후보

정확한 누적식/80개 표는 `MAIN_PERMANENT_REWARDS.md`가 담당한다.

## 5. NORMAL_CLEAR

`NORMAL_CLEAR`는 소탕/자동 지급이 아니라 실제 전투를 완료한 클리어다.

다음 둘 모두 정상 클리어:

- 솔로 실제 전투 클리어
- 허용된 스테이지의 2인 협동 실제 전투 클리어

NORMAL_CLEAR는 다음을 해금할 수 있다.

- 다음 스테이지/장 진행
- FIRST_CLEAR
- PERMANENT 보상
- 재클리어 2배속
- sweep 허용 스테이지의 소탕
- 제1장 ST20의 SPECIAL 허브

기록 SPECIAL은 별도의 record 규칙을 사용한다.

---

## 6. 2배속

- 최초 NORMAL_CLEAR 전: 기본 1×.
- NORMAL_CLEAR 후: 해당 스테이지 1×/2× 무료 전환 가능.
- 소모품 아님.
- simulation 규칙/결과/보상 동일.
- PvP에는 사용하지 않는다.
- 기록 SPECIAL은 1× 고정을 기본 후보로 한다.
- 2배속에서도 보스 공격 예고와 위험 VFX가 판독 가능해야 한다.

---

## 7. 소탕

사용 조건:

- 해당 스테이지를 1회 이상 NORMAL_CLEAR.
- 스테이지가 sweep 허용.
- 소탕권 보유.

솔로/협동 어느 쪽 NORMAL_CLEAR든 조건 충족.

소탕 가능:

- 일반 반복 보상
- 충전형 SPECIAL의 charged/depleted 반복 보상

소탕 불가:

- 최초 클리어
- 최초 영구 보상
- SPECIAL 허브 최초 해금
- 신기록
- 끝없는 전선/보스 러시 기록
- PvP 승리/랭킹
- `직접 전투` 명시 업적

소탕권은 에너지/입장권이 아니다.

## 8. SPECIAL 묶음 구조

한 collection 안에 3~10개 이상의 내부 전장을 둘 수 있다.

예: `황금 수송대`

1. 외곽의 짐마차
2. 황금 호송대
3. 무장 수송열차
4. 왕실 금고 행렬
5. 황금왕의 대수송

단계 상승은 적 조합, 전후열 비중, 전용 적, 보스, 스폰 리듬, 경제 압박, magnification을 함께 발전시킨다.

같은 적/같은 시간표에 HP만 올린 단계 복제 금지.

다단계 구조는 보스, 속성 도전, 진화 연속전, 이벤트, 외전에도 사용한다.

collection이 해금되어도 고단계는 별도 진행 조건을 가질 수 있다. 잠금 사유는 플레이어 자연어로 표시한다.

## 9. 주기 SPECIAL

1차 기본 4종:

- 황금 수송대 — 골드 — 5단계
- 혼의 제련소 — 공용 +레벨 재화 — 4단계
- 진화의 문 — 진화재료 — 5단계
- 별빛 균열 — 모집 재화 — 4단계

SPECIAL 허브 해금 이후부터 접근한다. 각 collection이 현재 주기에 열려 있는지와 내부 단계 해금은 별도다.

정확 단계/스폰/보상은 `PERIODIC_RESOURCE_SPECIALS_DETAILED.md`를 따른다.

### 보상 충전

- 입장은 무제한.
- 묶음 단위 `고효율 보상 충전` 사용.
- 충전이 남으면 charged 반복 보상.
- 0이어도 플레이 가능하며 depleted 반복 보상.
- 각 단계 FIRST_CLEAR는 충전과 별개.
- 충전은 로그인하지 않아도 상한까지 누적되는 방향.

짧은 1시간 게릴라 창을 놓쳐 큰 손해를 보는 구조는 사용하지 않는다.

## 10. 상시 SPECIAL

1차 주요 묶음:

- 폭식룡의 둥지
- 망자의 행진
- 유리성의 재판
- 녹슨 기계성
- 균열 관측기록
- 세 왕의 잔향
- 제한전 소수

대부분 `SOLO_OR_COOP`.

SPECIAL 허브는 1장 완료 후 열리지만 각 묶음은 난이도와 속성 도입 시점에 맞춰 추가 잠금을 둘 수 있다.

상시 콘텐츠는 FIRST_CLEAR 의미가 크고 반복 파밍 최적해가 되지 않게 한다.

---

## 11. 이벤트 SPECIAL

- SPECIAL 허브 해금 이후 입장 가능.
- 4~10스테이지 소형 캠페인 허용.
- 전용 적/배경/보스/룰 적극 사용.
- 종료 후 복각 가능 구조.
- 성능 캐릭터가 있으면 재획득 경로 보장.
- 이벤트를 놓쳤다고 핵심 성장 격차가 영구 고착되지 않게 한다.

제1장 미완료 사용자에게 이벤트가 보일 경우 `제1장 완료 후 SPECIAL 개방` 안내를 명확히 표시한다.

첫 설계 샘플:

- 한여름 괴수 대소동
- 제로 엣지 시험운용

세부: `EVENT_AND_RECORD_SPECIALS_DETAILED.md`.

## 12. 기록 SPECIAL

1차는 두 개만 핵심으로 둔다.

### 끝없는 전선

- SPECIAL 허브와 별도로 제3장 완료 해금 후보.
- SOLO_ONLY.
- 생존 최고기록.
- 새로 넘은 매 1분 경계만 1회 보상.
- 반복 파밍 보상 거의 없음.
- 난도 시간 가속.
- 30분 방치 모드 금지.

### 보스 러시

- 제4장 완료 해금 후보.
- SOLO_ONLY.
- 보스 연속 격파/최고 단계 기록.
- 첫 도달 구간/보스 기록 보상.
- 반복 앞구간 파밍 금지.

두 기록전 모두 2배속/소탕/협동을 기본 허용하지 않는다.

## 13. 스테이지 멀티 정책

모든 스테이지:

- `SOLO_ONLY`
- `SOLO_OR_COOP`
- `COOP_ONLY`

기본:

- 메인: 대부분 SOLO_OR_COOP
- 상시/주기/이벤트 SPECIAL: 대부분 SOLO_OR_COOP
- 기록전: SOLO_ONLY
- COOP_ONLY: 특별 이벤트/실험에서만 제한적

## 14. 2인 PvE 협동

### 편성/경제

- A 5칸 + B 5칸 = 팀 10종.
- 개인 보급/보급소/생산 cooldown.
- 공유 기지 HP/승패/전장/거점 병기.

동일 캐릭터를 두 플레이어가 각각 가져오는 것은 허용 후보이며 벽/상태효과/초장거리 2중 편성을 테스트 후 잠근다.

### 난이도 보정

출발 후보:

- 적 HP ×1.15~1.30
- 적 공격 ×1.05~1.15
- 적 거점 HP ×1.10~1.20

기본적으로 이동속도, 사거리, 공격주기, KB, 웨이브 수, 적 개체 수, 스폰 시점, 공격 패턴은 바꾸지 않는다.

스테이지별 이유가 있는 예외는 위키에 명시한다.

### 보상

- 솔로/협동 기본 보상 동일.
- 협동 최초 클리어도 정상 진행.
- 협동만 가능한 필수 성장재화 금지.
- 참가자마다 자기 보상/충전 상태 처리.

## 15. 협동 매칭/재접속

입장:

- 친구 초대
- 공개 매칭

필수 UX:

- 검색 중 취소
- 파트너 연결 상태
- 준비 상태
- 전투 시작 실패 이유
- 재접속 중 표시

재접속:

- 일정 유예 동안 5칸/보급/보급소/쿨다운 상태 보존.
- 장기 이탈 시 임시 AI 인계 후보.
- 복귀하면 다시 플레이어 제어.
- 정확 유예/AI 규칙은 멀티 위키에서 TESTED 후 잠근다.

스토리 장면은 협동 상대를 장시간 기다리게 하지 않으며 PRE/POST narrative는 각자 로컬 처리한다.

## 16. 친구/빠른 통신

1차:

- 친구 코드/검색
- 요청/수락/거절
- 목록/온라인 상태
- 협동 초대
- 친선전 초대
- 최근 플레이어
- 삭제/차단

자유 텍스트 채팅은 1차 필수가 아니다.

빠른 통신 예:

- 준비됐어
- 보급 올릴게
- 전열 부탁
- 후열 부탁
- 병기 사용
- 위험
- 좋아

스팸 방지 rate limit 적용.

## 17. PvP

### 일반전

- 레이팅 없음.
- 실험/재미.
- 기본 성장 표준화.

### 랭킹전

- MMR + 티어 + 순위표.
- 1차는 1v1 랭킹.
- 실제 보유 캐릭터/해금 형태만 사용.
- 기본 Lv/+Lv/메인 영구 성장은 표준화.
- PvP 전용 필수 성장재화 금지.

### 친선전

- 친구/방코드.
- 레이팅/보상 없음.
- 표준 성장/실제 성장 선택 후보.
- 1v1/2v2.

### 2v2

- 1차 일반/친선.
- 플레이어당 5칸.
- 랭킹은 동접/매칭시간 확인 후 후속 가능.

정확한 MMR/티어/시즌/보상은 `PVP_RANKING_MMR_REWARDS.md`를 따른다.

---

## 18. 스테이지 데이터 최소 필드

장기 데이터 모델:

- id / collectionId / chapterId
- name / subtitle
- stageKind
- difficulty
- multiplayerPolicy
- unlockPolicy / unlockRequirement
- mapLength / theme / decorSeed
- playerBaseHp / enemyBaseHp
- startingSupply
- playerUnitCap / enemyUnitCap
- waves / trigger DSL
- rewards / firstClearRewards / repeatRewards
- permanentBonus
- speedUpEligibility
- sweepEligibility
- rewardChargePolicy
- formationRestrictions
- specialRules
- coopStatScaling
- unlocks

`playerUnitCap`은 스테이지 전술 변수일 수 있으나 메인 영구 성장 보상으로 증가시키지 않는다.

SPECIAL collection도 최소 `globalHubRequirement`, `collectionRequirement`, `stageRequirement`을 분리할 수 있어야 한다.

---

## 19. 트리거 DSL

지원 목표:

- 특정 tick/time
- 적 거점 HP 비율
- 아군 거점 HP 비율
- 특정 적 사망
- 누적 처치/사망
- 특정 페이즈 완료
- AND/OR 복합 조건

특수 규칙은 자유 문자열 patch가 아니라 등록된 rule ID/schema로 구현한다.

## 20. 스테이지 구현 전 필수 위키 항목

- stageId/표시 이름
- 상태
- 목적/학습 요소
- 난이도와 근거
- 권장 기본 Lv/+Lv/형태
- unlock requirement
- 맵 길이/기지 HP/시작 보급
- 정확 spawn timeline
- 반복 wave
- trigger
- 보스/페이즈
- 솔로/협동 정책
- coop scaling
- FIRST_CLEAR/repeat/permanent reward
- reward charge
- 2배속/소탕
- 예상 클리어 시간
- deterministic baseline
- 사람 플레이테스트 결과

필수 필드가 없으면 DESIGN_TARGET 완료로 보지 않는다.

# 전선소환전 / Frontline Summoners — 통합 전체 기획서 v1.1

문서 상태: **1차 완성 범위 상세 정본**  
최상위 결정: `docs/CANONICAL.md`  
성장/모집/진화: `docs/GROWTH_RECRUITMENT_DESIGN.md`  
스테이지/SPECIAL/멀티: `docs/STAGE_SYSTEM_DESIGN.md`  
콘텐츠 제작 사양: `docs/content-wiki/`  
실제 구현 상태: `docs/IMPLEMENTATION_STATUS.md`

> 이 문서는 게임 전체의 목적·규칙·1차 완성 범위를 설명한다. 캐릭터 한 명의 정확한 형태별 수치, 적 한 종의 스폰 배율, 개별 스테이지의 타임라인 같은 제작 세부는 `docs/content-wiki/`가 담당한다. 구현 데이터와 기획이 다르면 구현을 조용히 정답으로 취급하지 않는다. `LOCKED` 위키 사양과 구현이 다르면 구현 불일치다.

---

# 1. 게임 정의

**서로 다른 실루엣·비용·사거리·역할을 가진 캐릭터를 모아 덱을 구성하고, 전투 중 보급과 생산 타이밍을 관리하며 1차원 전선을 밀어 상대 거점을 파괴하는 브라우저 기반 횡스크롤 실시간 소환 전략 게임.**

핵심은 버튼 수가 아니라 다음 판단의 반복이다.

- 지금 싼 전열을 더 낼지, 고비용 핵심 유닛을 위해 기다릴지
- 보급소에 투자할지 즉시 전투력을 확보할지
- 적의 사거리와 공격 프레임을 보고 전선을 어디에 형성할지
- 같은 10칸 안에서 벽/러셔/광역/장거리/속성 대항을 얼마나 넣을지
- 거점 병기와 생산 쿨다운을 언제 맞물릴지

싱글 플레이만으로 게임의 성장과 본편을 완주할 수 있어야 하고, 같은 결정론적 전투 코어 위에서 2인 PvE 협동과 PvP가 동작해야 한다.

# 2. 1차 완성 범위

1차 완성은 **냥코 대전쟁의 본능에 해당하는 후반 성장축 직전까지의 밀도**를 목표로 한다. 구조적 참고는 하되 명칭·캐릭터·아트·수치·스토리를 복제하지 않는다.

1차 완성에 포함한다.

- 메인 4장 × 20 = 80스테이지
- 기본/스토리 캐릭터와 모집 공통 C/B/A 풀
- 초기 모집 시리즈 3개, 각 시리즈 S 5명 + SS 정확히 1명
- 기본 레벨 Lv1~50와 장별 레벨 상한 해제
- +레벨 장기 성장축
- 1/2/3형태 진화와 이전 형태 재선택
- 속성/전투 태그/상태효과/특수 공격 구조
- 도감, 편성, 성장, 모집 UI
- 상시/주기/이벤트 SPECIAL
- 기록 SPECIAL 2종: 끝없는 전선, 보스 러시
- 이미 클리어한 스테이지의 무료 2배속
- 전투 소탕 아이템
- 대부분의 메인/SPECIAL에 2인 PvE 협동
- 친구 목록/초대/친선전/빠른 통신
- PvP 일반전/랭킹전/친선전
- PvP 티어/레이팅/랭킹/보상
- 게스트 저장과 로그인 계정의 기본 흐름

1차 완성에 억지로 넣지 않는다.

- 본능에 대응하는 후반 추가 성장 시스템
- 난이도 9~12를 채우기 위한 억지 초고난도
- 캐릭터별 액티브 스킬 버튼 난립
- 에너지/스태미나
- 무작위 품질 보물 파밍
- 누적 모집 천장/100회 선택권
- 필수 성능을 기간 한정 콘텐츠에 묶는 FOMO

# 3. 제품 및 운영 원칙

- 플랫폼: Web PC + 모바일 브라우저, 전투는 가로 화면 기준.
- 판타지 약 40%, 괴상함/유머/예상 밖의 소재 약 60%.
- 인간형 캐릭터만 반복하지 않는다.
- 과금이 없어도 완결되는 경제를 기준으로 설계한다.
- 플레이 시간을 억지로 늘리는 에너지 제한을 두지 않는다.
- 모든 핵심 전투 정보는 게임 내부 도감/UI에서 확인할 수 있게 하며 외부 위키를 강제하지 않는다.
- 게임 UI에는 `prototype`, `TODO`, `debug`, 내부 ID, 저장 버전, 테스트 수치, 개발 메모를 노출하지 않는다.
- 미완성 기능은 “준비 중” 버튼을 잔뜩 두기보다 출시 UI에서 숨긴다.
- 새 시스템을 추가할 때 폐기한 구체계를 호환용으로 영구 병존시키지 않는다.

# 4. 문서와 구현의 권위

권위 순서는 다음과 같다.

1. `docs/CANONICAL.md` — 게임 전체에서 절대 깨지면 안 되는 규칙
2. 시스템 상세 문서 — 성장/모집/스테이지/멀티 등 공통 규칙
3. `docs/content-wiki/`의 `LOCKED` 사양 — 개별 캐릭터/적/스테이지/콘텐츠 제작값
4. 실제 `content/` 데이터와 코드 — 위 사양을 구현한 결과
5. `IMPLEMENTATION_STATUS.md` — 현재 구현 진척의 기록

위키 상태는 다음을 사용한다.

- `CONCEPT`: 방향만 있음. 구현 금지.
- `DESIGN_TARGET`: 구현 가능한 목표값. 테스트 전이므로 조정 가능.
- `TESTED`: 자동/수동 테스트를 통과했으나 밸런스 조정 가능.
- `LOCKED`: 현재 릴리스 기준 정본.
- `REWORK`: 현재 구현/초안 폐기 후 재설계 대상.

`DESIGN_TARGET` 수치를 구현하면서 바꿀 수는 있지만, 변경 즉시 위키에도 이유와 결과를 반영한다. `LOCKED`와 코드가 다르면 버그다.

# 5. 전투 코어

## 5.1 시뮬레이션

- 고정 30 tick/s 결정론 시뮬레이션.
- 렌더링은 60fps 이상 보간 가능.
- 싱글과 권위 멀티 서버가 같은 simulation core를 사용한다.
- 전투 판정은 1D X축이며 Y는 연출용이다.
- 난수는 필요할 때 seed 기반 결정적 PRNG만 사용한다.

## 5.2 기본 틱 순서

1. 확정 입력 적용
2. 보급/쿨다운/상태 타이머
3. 예약된 아군·적 스폰
4. 이동
5. 표적 탐색과 공격 상태 전환
6. 해당 틱 모든 hit event 수집
7. 피해/효과 동시 적용
8. 자연 KB/강제이동/사망 판정
9. 제거와 승패 판정
10. 결정성 상태 갱신

배열 순서 때문에 같은 프레임의 생존 결과가 달라지면 안 된다.

## 5.3 공격

- `이동 → 선딜 → hit frame → 후딜/공격대기 → 재탐색`.
- 공격 시작 시 잡은 대상은 공격 트리거일 뿐, 실제 hit frame에서 범위를 다시 판정한다.
- 멀티히트는 hit frame을 여러 개 가진다.
- standing range와 attackMin/attackMax는 별도다.
- 사각지대·원거리 안쪽 파고들기·전후방 공격을 이 차이로 설계한다.

## 5.4 자연 KB와 강제이동

- 자연 KB는 HP 임계에 따른 자체 반동.
- 하나의 피해 패킷이 여러 임계를 통과해도 실제 자연 KB 애니메이션은 최대 한 번만 발생하되 통과한 임계 자체는 소모한다.
- 강제이동은 자연 KB와 별개 상태로 처리한다.
- 자연 KB/강제이동/공격 취소 우선순위는 콘텐츠별 예외를 만들지 말고 sim 공통 규칙으로 고정한다.

## 5.5 사망

HP가 0 이하가 되는 즉시 전투 대상에서 제외되는 사망 상태로 들어간다. 사망 애니메이션은 시각 표현일 뿐 전투 판정을 지연시키지 않는다.

모든 전투 정의는 최소 다음을 구분한다.

- HP

- 이동속도
- standingRange

- 단일/범위/특수 범위
- 공격 시작 선딜

- 전체 공격주기
- backswing
- 자연 KB 횟수/시간
- 생산비

- 전투 태그 `combatTags[]`

- 공격 VFX/SFX 연결

프레임·초·표시값의 변환 규칙을 각 캐릭터마다 다르게 만들지 않는다.

# 7. 속성, 전투 태그, 능력

## 7.1 속성

1차 기본 후보 속성군:

- NEUTRAL
- BEAST
- UNDEAD
- NATURE
- ARCANE
- DEMON
- MACHINE
- ANOMALY

플레이어와 적 모두 속성을 가진다. 한 유닛이 하나 또는 필요 시 두 속성을 가질 수 있다.

속성은 전역 가위바위보가 아니다. 일반 공격은 모든 대상에게 정상 피해를 주며, 특정 캐릭터가 가진 `BEAST 대상 강한 피해`, `MACHINE 저항`, `UNDEAD 정지` 같은 대항 능력이 속성을 참조한다.

## 7.2 전투 태그

예시:

- ARMORED
- FLYING
- GIANT
- STRUCTURE
- SUMMON
- BOSS

태그는 속성의 두 번째 상성표가 아니다. 특정 능력의 조건, 연출, AI, 도감 분류에 사용한다.

## 7.3 능력군

1차 구현 후보:

- 단일 / 범위
- 장거리 / 사각지대
- 전후방·omni형 범위
- 멀티히트
- Push
- Slow
- Freeze
- Weaken
- Strengthen
- Critical
- 방어관통
- 속성 대상 공격/저항/상태효과

모든 S/SS가 능력 여러 개를 가져야 하는 것은 아니다. 단순한 HP·사거리·공격 효율만으로도 충분히 강하고 개성 있는 캐릭터를 허용한다.

# 8. 전투 경제

전투 재화는 `보급` 하나다.

- 캐릭터 생산과 보급소 강화가 같은 자원을 경쟁한다.
- 초반부터 보급이 넘쳐 모든 버튼을 누르는 구조를 금지한다.
- 반대로 기다리는 시간이 전투의 대부분이 되지 않게 한다.
- 저비용 전열, 고비용 핵심 유닛, 보급소 투자가 서로 실제 선택지가 되어야 한다.

제1장 경제의 현재 출발 방향은 저속 경제다.

- Lv1: 12/s, 최대 1000
- Lv2: 20/s, 최대 1400, 강화비 160
- Lv3: 30/s, 최대 1900, 강화비 260
- Lv4: 42/s, 최대 2500, 강화비 390
- Lv5: 56/s, 최대 3200, 강화비 560
- Lv6: 72/s, 최대 4000, 강화비 760
- Lv7: 90/s, 최대 5000, 강화비 1000
- Lv8: 110/s, 최대 6200, 강화비 1300

이 수치는 `DESIGN_TARGET`이며 장별 스테이지 위키에서 권장 시작 보급과 함께 검증한다. 뒤 장은 플레이어가 더 비싼 캐릭터를 다루게 되므로 시작 보급과 전투 템포를 자연스럽게 높일 수 있다.

적 처치 보급은 전투가 마르는 것을 막되, 웨이브를 잡을수록 자원이 폭발적으로 복리 증가하지 않게 조절한다.

---

# 9. 재생산

- 캐릭터마다 기본 재생산 시간을 가진다.
- 형태/영구 보상/향후 후반 시스템의 재생산 감소를 모두 적용한 뒤 최종 하한을 적용한다.
- **1차 완성 기준 최종 재생산 최소치는 2초(60F)**.
- 저비용 벽이라도 0.x초 무한 생산이 되지 않는다.
- 하한 변경은 전선 밀도, 협동 서버 부하, PvP 반복 소환까지 함께 검증한 뒤만 허용한다.

---

# 10. 거점과 거점 병기

- 양쪽 전장 끝에 거점이 있으며 상대 거점 파괴가 기본 승리조건이다.
- 거점 HP는 전투 시간과 보스 연출을 무의미하게 만들 정도로 과도하게 높이지 않는다.
- 거점 병기는 전투당 장착 1종을 기본으로 한다.
- 캐릭터마다 별도 액티브 스킬 버튼을 늘리는 대신 소환·보급·거점 병기 타이밍이 플레이 조작의 중심이다.
- 병기의 정확한 피해/범위/쿨다운은 별도 시스템 위키에서 관리한다.

---

# 11. 캐릭터 획득 분류

## 11.1 스토리/확정 획득

- `acquisitionClass = STORY` 등 별도 획득 분류를 사용한다.
- C/B/A/S/SS 모집 희귀도를 부여하지 않는다.
- 기본 10종은 전투 문법을 가르치는 로스터이며 모집 저희귀의 하위호환이 아니다.

## 11.2 모집

희귀도:

- C
- B
- A
- S
- SS

C/B/A는 대체로 공통 풀, S/SS는 시리즈별 전용이다.

**각 모집 시리즈의 SS는 정확히 1명**을 기본 규칙으로 한다. 초기 시리즈는 S 5명씩으로 시작한다.

희귀도는 생산비나 절대 전투력 순서가 아니다.

# 12. 초기 모집 시리즈

1. **성휘의 기사단** — 미소녀·판타지 영웅, 무기와 실루엣의 극단적 차별화
2. **태고의 거수** — 괴수·고대 생물·이형, 인간형 의존 없음
3. **제로 엣지** — 강화인간·기계·드론·무인 병기·SF 검단

각각 S 5명 + SS 1명. 캐릭터 개별 사양은 콘텐츠 위키가 정본이다.

S/SS는 실제 전투에서의 사용감과 화면 존재감이 특히 중요하므로 구현 전 상세 사양과 아트 방향을 검수한다.

---

# 13. 모집 확률과 연출

과거의 10/30/60/100회 보장, 누적 천장, 직접 선택권은 사용하지 않는다.

현재 확률 출발 후보는 `DESIGN_TARGET`이다.

- C 42.0%
- B 32.0%
- A 22.7%
- S 3.0%
- SS 0.3%

확률은 모집 재화 공급, 중복 분해 효율, 시리즈 복각 주기와 함께 검증한다.

연출 원칙:

- C/B: 빠르고 방해되지 않는 결과
- A: 작은 강조
- S: 시리즈 문장/컷인 등 명확한 고급 연출
- SS: 해당 시리즈의 단 하나뿐인 특별 연출
- 이미 본 연출은 빠르게 스킵 가능
- 결과 확인을 일부러 오래 끌어 반복 피로를 만들지 않는다.

---

# 14. 레벨과 +레벨

## 14.1 기본 레벨 상한

- 시작 Lv10
- 1장 최종 클리어 → Lv20
- 2장 → Lv30
- 3장 → Lv40
- 4장 → Lv50

별도 사용자 랭크로 상한을 열지 않는다.

## 14.2 성장 체감

기본 레벨은 주로 HP와 공격 피해를 크게 올린다.

목표 앵커:

- Lv1 ×1.0
- Lv10 약 ×1.8~2.0
- Lv20 약 ×3.0~3.5
- Lv30 약 ×4.5~5.5
- Lv40 약 ×6.5~7.5
- Lv50 약 ×8~10

사거리, 이동속도, 생산비, 재생산, KB, 공격 방식은 기본 레벨 때문에 자동으로 변하지 않는다.

## 14.3 +레벨

- 같은 캐릭터 중복은 직접 +1에 쓰는 것이 최고 효율.
- 1차 상한 후보 +50.
- 중복을 공용 +성장 재화로 분해하여 다른 캐릭터에 사용할 수 있다.
- 교차 전환은 직접 중복 대비 대략 20~30% 효율에서 시작해 검증한다.
- Base Lv50만으로도 정상 완성 캐릭터여야 한다.

---

# 15. 진화와 형태

모든 정식 캐릭터는 원칙적으로 1/2/3형태 구조를 사용할 수 있다.

- 소유권·기본 레벨·+레벨 공유
- 해금한 이전 형태 재선택 가능
- 3형태가 반드시 2형태의 완전 상위호환일 필요 없음
- 형태별로 비용, 재생산, 사거리, 이동, KB, 공격 방식, 대항 효과까지 달라질 수 있음
- 형태가 실전에서 다른 역할처럼 느껴져도 허용
- 외형은 색상 변경만으로 끝내지 않음

진화재료 상대 요구량 출발점:

- C ×1.0
- B ×1.4~1.6
- A ×2.0~2.3
- S ×3.2~3.5
- SS ×4~5

정확한 종류와 수량은 각 캐릭터 위키에 기록한다.

필터:

- 전체 / 스토리 / C / B / A / S / SS
- 속성 대항
- 역할
- 비용
- 기본 레벨 / +레벨
- 최근 획득
- 즐겨찾기
- 검색

빠른 필터와 상세 필터를 분리해 화면을 버튼으로 도배하지 않는다.

# 17. 도감

## 17.1 아군

- 미획득: 실루엣 + `???`
- 편성 화면에는 미획득 캐릭터 자체를 표시하지 않음
- 획득 후 형태, 속성, 태그, 스탯, 공격 구조, 비용, 재생산, 획득처 공개

## 17.2 적

- 미발견: 실루엣 + `???`

- 스테이지 적 미리보기에서 발견한 적을 누르면 도감으로 이동

전투 중 모든 속성 아이콘을 머리 위에 상시 띄우지 않는다. 실루엣과 도감 학습을 중심으로 하고 상태효과 아이콘만 필요 시 일시 표시한다.

# 18. 메인 캠페인

1차 완성은 4장 × 20스테이지다.

각 장의 기본 학습 흐름:

- 1~4: 새 문법 소개
- 5: 첫 복합 응용
- 6~9: 적 조합·경제·사거리 심화
- 10: 중간 변곡/중간보스
- 11~14: 새 적/속성/공격 구조
- 15~18: 복합 압박
- 19: 최종전 전조
- 20: 장 최종보스

모든 장이 똑같은 공식으로 보이지 않도록 테마별 변형은 허용한다.

메인은 **대부분 솔로 또는 2인 협동 선택 가능**으로 설계한다. 협동으로 최초 클리어해도 다음 스테이지, 첫 클리어 보상, 영구 보상, 장 진행을 정상 인정한다.

기록/업적으로 별도 `솔로 클리어` 마크를 남길 수는 있지만 핵심 성장재화를 강제하지 않는다.

---

# 19. 메인 영구 보상

각 메인 스테이지의 첫 클리어는 확정 영구 보상을 줄 수 있다.

- 20개 효과가 전부 달라야 할 필요 없음
- 같은 성장축의 반복 누적 허용
- RNG 품질/등급 없음
- 반복 파밍으로 더 좋은 보물을 뽑는 구조 없음

사용 가능한 주요 축:

- 전체 또는 조건부 HP
- 전체 또는 조건부 공격
- 거점 HP
- 시작 보급
- 적 처치 보급
- 보급소 강화비 감소
- 재생산 감소

사용하지 않는 축:

- 영구 이동속도 증가
- 영구 아군 출전/배치 한도 증가

사거리 영구 증가는 전선 정체성을 크게 흔드므로 기본 보상축으로 쓰지 않는다.

장 20번째 보상은 레벨 상한 해제와 별도 큰 보상을 함께 제공한다.

# 20. 난이도 1~12

난이도 표시는 장기 확장을 포함한다.

- 1: 튜토리얼급
- 2: 매우 쉬움
- 3: 쉬움
- 4: 보통 이하
- 5: 보통
- 6: 제법 어려움
- 7: 1차 완성의 일반적인 상위 난도
- 8: 일부 후반 보스·상위 SPECIAL
- 9~12: 후반 성장/업데이트용 공간

1차 완성에서 9~12를 채우기 위해 적 HP/공격을 비정상적으로 키우지 않는다.

난이도는 해당 스테이지가 실제로 열리는 시점의 정상 계정을 기준으로 평가한다. 정확한 산정표는 `content-wiki/systems/DIFFICULTY_CALIBRATION.md`에서 관리한다.

# 21. SPECIAL 구조

SPECIAL은 한 카드 안에 여러 내부 스테이지를 가진 `collection` 구조를 기본 지원한다.

분류:

- 상시 SPECIAL
- 주기 SPECIAL
- 이벤트 SPECIAL
- 기록 SPECIAL

`1회성`은 콘텐츠 자체 삭제가 아니라 첫 클리어 보상이 1회라는 속성으로 처리하는 것을 기본으로 한다.

주기 재화전 예시:

- 황금 수송대 — 골드
- 혼의 제련소 — 공용 +레벨 재화
- 진화의 문 — 진화재료
- 별빛 균열 — 모집 재화

하나의 묶음 안에 초급~고급 여러 단계가 있으며 단계가 높아질수록 단순 스탯뿐 아니라 적 조합/신규 적/보스/경제 압박이 발전한다.

다단계 구조는 재화전뿐 아니라 보스 연전, 속성 도전, 이벤트, 진화 관련 연속전에도 사용한다.

---

# 22. SPECIAL 보상 충전

에너지 대신 일부 반복 보상에 `보상 충전`을 사용한다.

- 플레이 자체는 무제한
- 충전이 남아 있으면 정상 고효율 반복 보상 획득
- 충전 소진 후에도 플레이 가능
- 소진 후 반복 보상은 낮아짐
- 각 단계 첫 클리어 보상은 충전과 별도
- 충전은 묶음 단위로 사용하여 초보는 낮은 단계, 고수는 높은 단계에 사용할 수 있음

짧은 시간 창을 놓쳤다고 며칠 손해 보는 게릴라/FOMO 구조는 피한다.

# 23. 기록 SPECIAL

1차 완성에서는 두 개면 충분하다.

## 23.1 끝없는 전선

- 솔로 전용
- 개인 최고 생존 시간 기록
- 이전 최고 기록보다 새롭게 넘어선 1분 구간에만 1회성 보상
- 같은 기록 반복 파밍 불가
- 뒤로 갈수록 난도가 가속되어 수십 분 방치 모드가 되지 않게 함

## 23.2 보스 러시

- 솔로 전용
- 연속 보스 격파/최고 단계 기록
- 반복 파밍보다 기록 갱신 보상 중심

두 기록전 모두 소탕/협동을 허용하지 않는다.

---

# 24. 2배속과 소탕

## 24.1 2배속

- 최초 클리어는 기본 1×
- 해당 스테이지를 한 번 클리어하면 이후 1×/2× 무료 전환 가능
- 소모품 아님
- 2배속에서도 sim 결과 규칙은 동일

## 24.2 소탕권

- 이미 직접 또는 정상 협동으로 클리어한 반복 가능 스테이지에 사용
- 최초 클리어·신기록·랭킹 기록 생성 불가
- 소탕권이 없어도 직접 플레이는 항상 가능
- 보상 충전형 SPECIAL은 `소탕권 1장 + 충전 1회`로 정상 반복 보상을 받을 수 있음
- 기록전/PvP에는 사용 불가

소탕권이 사실상의 입장 에너지가 되지 않게 한다.

---

# 25. 2인 PvE 협동

대부분의 메인/SPECIAL은 같은 스테이지를 솔로 또는 협동으로 선택할 수 있다.

- 플레이어당 5캐릭터
- 팀 총 10칸
- 개인 보급
- 개인 보급소
- 개인 생산 쿨다운
- 공유 전장
- 공유 아군 거점 HP
- 공유 승패
- 공유 거점 병기

협동이 덱 20종을 쓰는 모드가 아니므로 적을 2배로 강화하지 않는다.

출발 보정 후보:

- 적 HP ×1.15~1.30
- 적 공격 ×1.05~1.15
- 적 거점 HP ×1.10~1.20

기본적으로 이동속도, 사거리, 공격주기, KB, 웨이브 수, 스폰 패턴은 건드리지 않는다. 실제 두 경제의 이점만 측정해 최소 보정한다.

협동 최초 클리어도 정상 진행으로 인정한다.

# 26. 친구와 소셜

1차 기능:

- 닉네임/친구 코드 또는 검색
- 친구 요청/수락/거절
- 친구 목록
- 온라인/오프라인 및 초대 가능 상태
- 협동 초대
- 친선 PvP 초대
- 최근 함께 플레이한 사용자
- 친구 삭제/차단

자유 텍스트 채팅은 1차에서 필수로 두지 않는다. 협동 중에는 빠른 통신을 사용한다.

빠른 통신 예시:

- 준비됐어
- 보급 올릴게
- 전열 부탁
- 후열 부탁
- 병기 사용
- 위험
- 좋아

스팸 방지를 위해 쿨다운을 둔다.

# 27. 재접속과 이탈

멀티에서 짧은 연결 끊김이 즉시 패배로 이어지지 않게 한다.

- 일정 재접속 유예
- 캐릭터 5칸/보급/보급소/쿨다운 상태 보존
- 장기 이탈 시 AI 임시 인계 후보
- 복귀하면 다시 플레이어가 제어

정확한 유예 시간과 AI 행동은 멀티 위키에서 테스트 후 잠근다.

# 28. PvP 모드

## 28.1 일반전

- MMR/티어에 직접 영향 없음
- 새 덱/캐릭터 실험과 부담 없는 플레이
- 표준화 전투 규칙을 기본으로 사용

## 28.2 랭킹전

- MMR
- 티어
- 순위표
- 시즌/기간 단위 경쟁 구조 가능
- 티어 최초 도달 보상
- 상위권 숫자 순위 표시

랭킹전에서는 기본 레벨/+레벨/메인 영구 보너스의 격차가 승부를 결정하지 않도록 **성장 수치를 표준화**한다. 실제 보유 캐릭터와 해금 형태 선택은 의미를 유지한다.

## 28.3 친선전

친구 또는 방 코드를 통해 플레이한다.

후보 설정:

- 표준 성장 / 실제 성장
- 1v1 / 2v2
- 맵 선택
- 허용된 특수 규칙

보상/레이팅은 없다.

## 28.4 2v2

1차 완성에서는 2v2 일반/친선을 지원하는 방향으로 설계하되, 2v2 랭킹 큐는 동시접속과 매칭 분산을 보고 후속 개방할 수 있다. 플레이어당 5칸을 기본으로 한다.

---

# 29. PvP 보상 철학

랭킹전을 잘하면 보상은 있어야 하지만 PvP가 핵심 성장의 의무가 되면 안 된다.

허용:

- 티어 최초 도달 모집 재화
- 골드
- 공용 +성장 재화
- 진화재료
- 프로필 테두리
- 칭호
- 문장/배너/장식

금지:

- PvP에서만 획득 가능한 필수 진화/성장 재화
- 시즌 상위권만 영구 성능을 독점하는 보상
- 강자가 더 강해지는 대량 순위별 성능 보상

시즌 종료 상위 보상은 명예/장식 비중을 높인다.

---

# 30. 이벤트

기간 이벤트는 4~10스테이지 정도의 소형 캠페인부터 장기적으로 확장할 수 있다.

- 전용 배경·적·보스·특수 규칙 적극 사용
- 기간 종료 후 복각 가능
- 이벤트 성능 캐릭터가 있다면 재획득 경로 보장
- 이벤트를 놓쳤다는 이유로 계정 성장 격차가 영구 고착되지 않게 함

# 31. 저장과 계정

게스트 플레이를 허용한다.

로그인 계정 후보:

- Google
- 이메일

원칙:

- 게스트 → 로그인 진행 이전 지원

- 진행 초기화: 계정은 유지하고 게임 진행 데이터 제거
- 계정 삭제: 계정/서버 저장 제거
- 게스트 데이터 삭제: 로컬 저장 제거
- 파괴적 작업은 두 단계 확인

저장 대상:

- 스테이지/첫 클리어/영구 보상
- 캐릭터 소유
- 기본 레벨/+레벨
- 해금 형태/선택 형태
- 덱
- 재화
- 모집 통계
- SPECIAL 기록
- PvP 레이팅/티어/시즌 정보
- 친구/차단 관계는 서버 관리
- 설정

# 32. UI/UX 원칙

- PC와 모바일 가로화면 모두 먼저 설계한다.
- UI가 네모 박스만 반복되는 개발툴처럼 보이지 않게 한다.
- 판타지 전선의 천막, 깃발, 리본, 금속, 목재, 양피지 등 형태 언어를 일관되게 사용하되 가독성을 우선한다.
- 텍스트는 컨테이너 밖으로 넘치지 않아야 한다.
- 모바일 safe area와 손가락 가림을 고려한다.
- 주요 버튼은 상태 변화가 즉시 보이고 눌림 반응이 명확해야 한다.
- 생산 쿨다운은 숫자/게이지가 실제 남은 시간과 일치해야 한다.
- 보급 획득/소비, 레벨업, 새 캐릭터, 첫 클리어 보상은 시청각 피드백이 즉각적이어야 한다.
- 패배 후 재도전까지의 마찰을 최소화한다.
- 2배속 상태는 스테이지 재입장 정책과 설정 보존 여부를 명확히 한다.

세부 UI 사양은 위키에서 화면별로 작성한다.

# 33. 아트/애니메이션/VFX

최우선은 작은 전투 크기에서도 알아보는 실루엣이다.

캐릭터별로 다음 중 여러 축을 강하게 다르게 한다.

- 키/몸 비율
- 다리 수와 이동 방식
- 무기 크기/방향
- 머리/등/꼬리 구조
- 부유/기어다님/탈것
- 대표 소품
- 공격 자세

금지:

- 같은 인간형 색상 교체
- 같은 갑옷 베이스 반복
- 희귀도만 바꾼 실루엣 재사용
- 진화를 색상 변화만으로 처리

모션 최소 세트:

- Idle
- Move
- Attack
- KB/피격 반응
- Death

필요 캐릭터는 소환/변형/투사체/상태 전용 연출을 추가한다. hit frame과 시각 접촉 프레임이 일치해야 한다.

# 34. 사운드

- 생산 성공/실패
- 보급 획득/소비
- 타격 종류
- KB
- 거점 피해
- 보스 등장
- 승패
- S/SS 모집 결과

등 주요 상태는 화면을 계속 보지 않아도 구분될 정도의 사운드 언어를 가진다.

동일 효과음을 모든 캐릭터에 복제하지 않고 공격 재질·크기·속성을 반영한다. 모바일에서 지나치게 큰 저음/고주파가 반복되지 않게 검증한다.

# 35. 난이도와 밸런스 검증

스테이지 난이도는 숫자를 감으로 붙이지 않는다.

평가 입력:

- 해금 시점 권장 기본 레벨/+레벨/형태
- 요구 덱 역할 수
- 속성 대항 의존도
- 초반 30~60초 경제 압박
- 적 총 압박량과 동시 전선 밀도
- 사거리 상성
- 보스 체급과 페이즈
- 패배 복구 가능성
- 예상 클리어 시간
- deterministic 샘플 시뮬레이션
- 사람 플레이테스트 승률/재도전 수

1차 완성의 메인 대부분은 1~7, 일부 후반/SPECIAL만 8에 도달하는 것이 정상이다.

# 37. 콘텐츠 제작 원칙

캐릭터·적·스테이지를 코드 작성 중 즉흥적으로 설계하지 않는다.

순서:

1. 상위 정본 확인
2. 위키에서 상세 `DESIGN_TARGET` 작성
3. 기존 콘텐츠와 역할/실루엣/보상 중복 검사
4. 구현 데이터 작성
5. 자동검증
6. 실제 플레이
7. 위키에 테스트 결과/수정 이유 기록
8. `TESTED`
9. 릴리스 기준 확정 시 `LOCKED`

개별 수치가 아직 테스트되지 않았으면 확정값인 척하지 않고 상태를 표시한다.

# 39. 1차 완성 판정

1차 완성은 단순히 80개 스테이지 JSON이 존재하는 상태가 아니다.

다음이 한 제품처럼 연결되어야 한다.

- 메인 80스테이지
- 충분한 SPECIAL 묶음과 내부 단계
- 기본/모집 캐릭터의 수집·성장·진화
- 도감/편성/모집/성장 UI
- 솔로와 대부분 콘텐츠의 2인 협동
- 친구/초대/재접속
- PvP 일반/랭킹/친선
- 티어/랭킹/보상
- 2배속/소탕
- 저장/계정
- PC/모바일 UI 완성도
- 개발자 문구 제거
- 콘텐츠 위키와 실행 데이터 일치
- 자동검증과 사람 플레이테스트

이 지점 이후에 본능 대응 성장과 난이도 9~12, 장기 후반 콘텐츠를 업데이트로 설계한다.

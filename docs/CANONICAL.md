# Frontline Summoners 정본 v0.25 요약

> 상세 원본: 2026-08-23 「전선소환전 통합 게임 기획서 v0.21 — 전수검수 반영」을 기반으로 한다. v0.22의 보물·UI·첫 수동 테스트 기준, v0.23의 **초기 1캐릭터 시작·순차 해금·스테이지 순차 개방·다양한 전장 구성**, v0.24의 **전문 속성 4태그·원거리 발사/도달 시각 규칙·거점 병기 1슬롯·ForcedDisplacement**에 더해, v0.25에서는 **획득 보물의 실제 영구 modifier 적용·미래 보물 선적용 금지·최종 보스전 시각/등장 보장 baseline·원거리 렌더 보간**을 현재 프로토타입 정본으로 고정한다. 개발 전 매 작업에서 이 문서를 다시 확인하고, 변경이 필요하면 정본 문서와 구현을 함께 갱신한다.

## 제품 정의

- Web(PC/모바일 브라우저) 횡스크롤 소환 전략 게임.
- 냥코 대전쟁에서 검증된 `돈 → 생산 → 전선 → 사거리 → 공격 프레임 → KB → 재생산 → 적 스폰` 상호작용과 캠페인의 단계적 개방 감각을 참고하되 수치·캐릭터·명칭·아트·맵은 독자 설계.
- 싱글 플레이만으로 완전한 게임이어야 한다. 멀티는 2인 협동, 1v1, 2v2.
- 과금 없음. 에너지 제한, 랜덤 필수 보물 파밍, 중복 강제 +레벨, 지나친 성장 재화는 금지.
- 분위기는 판타지 약 40%, 개그/괴상함 약 60%. 캐릭터별 액티브 버튼은 두지 않는다.

## 전투 정본

- 규칙 시뮬레이션은 고정 30 tick/s, 렌더링은 60fps 이상 보간 가능.
- 브라우저 싱글과 권위 멀티 서버가 동일 `packages/sim` 코어를 사용한다.
- HP·보급·프레임·좌표는 정수 우선, 필요 시 동일 fixed-point 구현. 랜덤은 seed 기반 PRNG 하나만 사용.
- 틱 순서: 입력 확정 → 타이머/경제 → 스폰 → 이동 → 탐지/상태 전이 → 모든 타격 이벤트 수집 → 피해/상태 일괄 적용 → 자연 KB/강제이동/사망 → 제거/승패 → stateHash.
- 동시 타격은 먼저 수집 후 일괄 적용하여 순회 순서에 따른 생존 차이를 금지한다.
- 전장은 판정상 1차원 X축. Y축은 시각 연출만 담당.
- 공격은 `이동 → 선딜 → 타격 프레임 → 후딜 → 공격간 대기` 상태머신.
- 공격 시작 대상은 트리거일 뿐 실제 피해는 타격 프레임 순간 공격영역에 있는 대상에게 적용. 선딜 중 적이 빠지면 빗나갈 수 있다.
- 멀티히트는 여러 타격 프레임. 자연 KB가 발생하면 진행 공격과 남은 멀티히트 취소.
- 일반 피격 애니메이션은 없다.
- 자연 KB와 능력 Push/ForcedDisplacement는 별개다. 하나의 피해 패킷이 여러 자연 KB 임계값을 넘더라도 해당 패킷에서 자연 KB는 최대 1회이며 중간 임계값은 소비한다.
- 기본 자연 KB 상태는 약 12F, 캐릭터별 8~18F 조정 가능. 자연 KB 중 hurtbox는 기본 비활성.
- `FORCED_DISPLACEMENT`는 현재 행동을 취소하고 자기 거점 방향으로 정해진 거리/프레임만큼 이동하는 별도 상태다. 강제이동 중 hurtbox는 유지한다.
- 강제이동 중 자연 KB 임계 피해를 받으면 자연 KB가 우선하며 남은 강제이동을 취소한다. 이미 자연 KB 또는 DYING인 유닛에는 새 강제이동을 적용하지 않는다.
- HP≤0이면 즉시 `DYING`. 시각적으로 KB 모션 재사용 가능하지만 타겟·회복·상태효과 대상이 아니며 퇴장 후 제거.
- 기본 아군 배치 한도 50체. 적은 스테이지별 약 40~60체. 제한전에서 축소 가능.
- stateHash에는 현재 보이는 HP/좌표뿐 아니라 미래 판정에 영향을 주는 맵 길이, 양쪽 거점 정의, 공격 타이밍·사거리·KB 정의·displacement 목표/지속시간·보급소 정의·유닛 비용/쿨다운·적 보상·미래 웨이브·배치 한도·거점 병기 설정까지 포함한다.

## 사거리/능력

- standingRange와 실제 공격영역을 분리하여 근접 사각지대, 장거리, 전후방 공격을 표현한다.
- 단일/범위/장거리/전후방/멀티히트/Push/Slow/Freeze/Weaken/Strengthen/Critical/방어관통을 초기 핵심 후보로 둔다.
- 동일 종류 상태효과는 단순 합산하지 않고 더 강한 효과 + 더 긴 잔여시간을 기본으로 한다.
- 속성은 단순 가위바위보 배율이 아니라 특정 유닛의 전문 역할 태그다. 기본 공격은 모든 적에게 정상 피해.
- 제1장 프로토타입의 1차 전투 태그는 `LIGHT / ARMORED / ARCANE / BOSS` 4종이다. 속성 자체에는 전역 약점표가 없다.
- 특정 유닛에 명시된 전문 피해 보너스만 해당 태그를 가진 적에게 적용한다. 대상이 여러 전문 조건을 동시에 만족해도 가장 강한 배율 하나만 적용하고 중첩하지 않는다.
- 전문 배율은 결정성을 위해 permille 정수로 저장하며 거점에는 적용하지 않는다.

## 경제/덱

- 전투 자원은 `보급` 하나. 초기 후보: 시작 300, 최대 3,000, 기본 수입 65/초.
- 보급소 Lv.1~8은 수입과 최대 보급을 높이며 유닛 생산과 같은 자원을 경쟁한다.
- **한 전투에서 장착·사용 가능한 거점 병기는 1개**이며 캐릭터 액티브 대신 유일한 즉시 개입 수단으로 둔다.
- 장기적으로 거점 병기 종류 자체는 2종 이상 후보를 만들 수 있으나, 여러 병기 버튼을 한 전투에 동시에 나열하지 않는다. 병기 선택/장착이 생겨도 실제 전투 즉시 개입 슬롯은 1개다.
- 현재 제1장 프로토타입의 기본 병기는 `전선포`: 적 전체 90 피해 → 사망/자연 KB 판정 → 남은 적 60 거리/10F 강제 후퇴, 재충전 900틱(30초). 적 거점에는 피해를 주지 않는다.
- 싱글/1v1은 10칸. 협동/2v2는 플레이어당 5칸, 팀 전체 10칸.
- PC는 10칸 2행, 모바일은 5칸 페이지/2행 표시 선택 가능.
- 콤보는 덱 전체에서 판정하되 3칸 이상 잡아먹는 장식 콤보는 효과를 약하게 제한.
- **신규 계정은 기본 캐릭터 `징집병` 1종만 보유한다.** 처음부터 10칸을 채워 주지 않는다.
- 첫 캠페인에서는 스테이지 첫 클리어 보상으로 캐릭터가 순차 합류한다. 현재 제1장 프로토타입 해금 순서는 ST1 방벽기사 → ST2 수렵창병 → ST4 결투검사 → ST6 청창대 → ST8 전투마도사 → ST10 화염술사 → ST13 왕실기사 → ST16 이단주술사 → ST20 공허현자다.
- 보유 캐릭터가 10종 이하인 첫 마일스톤에서는 보유 캐릭터 전부를 자동 편성해 전투 규칙을 검증하고, 이후 수집 규모가 늘어나는 단계에서 10칸 수동 편성을 본격 연결한다.

## 수집/성장

- 희귀도 C/B/A/S/SS 후보. 희귀도는 절대 성능 순위가 아니다. X는 변칙 태그로 별도 운용 가능.
- 메타 통화는 골드 + 모집권/별가루 + 조각의 3축 중심.
- 레벨 1~50. HP/기본 공격력만 완만히 상승하고 사거리·비용·선딜·KB 횟수는 원칙적으로 고정.
- Lv.30 이후 성장 기울기를 낮춘다. 랭크 PvP는 선택 형태의 Lv.30 기본 스탯으로 표준화하고 계정 영구 보너스/중복 스탯은 제외.
- 진화 1/2/3형태는 반드시 상위호환이 아니며 이전 형태 재선택 가능.
- 중복은 캐릭터 조각 + 공용 조각. 중복 횟수가 정상 성능의 필수 조건이 되어서는 안 된다.
- 가챠는 수익화가 아니라 새 장난감 공급 장치. 최종 목표는 매우 후한 지급. 단 첫 프로토타입 10종 단계에서는 100연 지급을 적용하지 않고 디버그 지급으로 루프만 검증한다.

## 스테이지/콘텐츠

- 스테이지는 JSON 기반 DSL. 시간, 기지 HP, 특정 적 사망, 복합조건 등으로 스폰/페이즈를 제어한다.
- 난이도는 HP 배율보다 스폰 간격, 전후열 조합, 돈 공급, **맵 길이**, 사거리, 제한 편성으로 만든다.
- 메인 캠페인은 기본적으로 앞 스테이지를 클리어해야 다음 스테이지가 열린다. 새 계정에서 20개 스테이지를 모두 즉시 선택할 수 있게 하지 않는다.
- **각 스테이지의 보물은 첫 클리어 시 100% 확정 획득한다.** 보물 등급/드랍률 RNG, 최고 등급을 위한 반복 파밍, 필수 보물 노가다는 사용하지 않는다.
- 이미 획득한 보물을 위해 같은 스테이지를 다시 돌 필요가 없다. 재클리어 보상은 별도 일반 보상으로 설계할 수 있지만 보물 성능은 확률에 묶지 않는다.
- 제1장 보물의 실제 영구 효과는 `content/treasures/chapter-01.json`의 typed modifier 데이터가 정본이다. 결과 화면의 설명 문구만 존재하고 실제 수치가 안 바뀌는 가짜 보상을 금지한다.
- 전투 생성 시 IndexedDB에 실제 저장된 `treasureIds`만 modifier로 전달한다. 아직 클리어하지 않은 미래 스테이지 보물을 미리 적용하지 않는다.
- 현재 modifier 범위는 시작 보급, 아군 거점 HP, 유닛 HP/공격/이동/사거리/재생산/자연 KB 시간, 처치 보급, 보급소 강화비, 아군 배치 한도, 장 완료 플래그를 포함한다.
- 현재 시뮬레이션 주요 수치가 정수이므로 작은 퍼센트가 반올림으로 완전히 사라지지 않도록, 적용 대상의 양수 정수는 0이 아닌 증감 효과에서 최소 1단위 변화하도록 결정적으로 양자화한다. 향후 fixed-point 전환 시 이 규칙을 재검토한다.
- 20개 스테이지 보물 ID와 typed effect ID가 정확히 1:1이어야 하며 누락/중복은 회귀검사 실패다.
- 캐릭터 해금이 걸린 스테이지는 보물과 별개로 첫 클리어 시 해당 캐릭터를 100% 확정 해금한다.
- 영구 성장 보상은 확정 지급. 필수 스탯을 RNG 반복 파밍으로 막지 않는다.
- 메인 캠페인, 외전, 보스전, 제한전, 무한전, 샌드박스.

### 맵/전장 구성 정본

- 모든 스테이지가 같은 평지 배경에 적 구성만 바뀌는 구조를 금지한다.
- 냥코 대전쟁처럼 스테이지를 넘길 때 장소가 바뀌었다는 감각이 즉시 들어야 한다. 단, 원작 배경을 복제하지 않고 독자적인 지형/건축/색감으로 구성한다.
- 제1장 프로토타입은 `풀바람 평원 / 붉은 협곡 / 불붙은 곡창지대 / 안개 폐허 / 달그늘 고개 / 철문 요새권 / 황금가면 관문`의 7개 전장 계열을 사용한다.
- 같은 전장 계열 안에서도 스테이지별 `decorSeed`, 전장 길이, 산/구름/기둥/성벽/깃발/불탄 나무 등 오브젝트 배치를 달리해 복붙처럼 보이지 않게 한다.
- 전장 길이는 짧은 압박전·표준전·장거리 전선을 구분하는 실제 전투 변수이며, 배경 연출과 전선 압축감도 길이에 맞춘다.
- 지역에 따라 하늘, 원경, 중경, 지면, 장식, 양쪽 거점 팔레트가 달라진다. 보스 스테이지는 진입 전부터 시각적으로 일반 스테이지와 구분돼야 한다.
- ST19는 황금가면 제단/의식 깃발을, ST20은 황금가면 제단에 철문 요새 실루엣을 겹친 전용 랜드마크를 사용해 일반 황금길 스테이지와 시각적으로 분리한다.
- ST19/ST20은 현재 프로토타입 baseline에서 보스가 실제 등장하기 전에 적 거점이 파괴되는 흐름을 허용하지 않는다. ST19 황금가면 대주술사, ST20 황금가면 대주술사+철문장군의 실제 등장 여부를 자동검사한다.
- 배경 장식은 판정에 영향을 주지 않는 것이 기본이며, 전투 판정과 충돌하는 지형 기능이 필요하면 별도 스테이지 규칙으로 명시한다.

## 원거리 공격 시각 정본

- 원거리/마법 피해 판정 자체를 시각 투사체 충돌에 종속시키지 않는다. 실제 피해는 30Hz 공격 `hitFrame`에서 기존 전투 코어가 확정한다.
- `PIERCE / MAGIC / FIRE / VOID`는 선딜 후반에 시각 투사체를 발사하고 해당 `hitFrame`에 목표 지점에 도달하도록 역산한다.
- 거리별 원하는 이동시간을 정수 simulation tick 수로 올림해 `launchFrame = firstHitFrame - travelTicks`로 계산한다.
- `SLASH / BLUNT`는 근접 즉시 VFX를 유지한다.
- 포물선 Y축은 시각 장식일 뿐 1차원 전투 판정에 영향을 주지 않는다.
- 타깃이 피해 프레임 전에 이동하더라도 실제 피해 대상은 hitFrame 순간의 공격영역 규칙을 따른다. 시각 발사체는 발사 당시의 목표 방향을 보여 주는 표현이며 판정 정본이 아니다.
- 렌더 위치는 정수 simulation tick 사이에서 `accumulator / SIM_TICK_MS`로 fractional interpolation한다. 이 보간은 화면 위치에만 적용하며 피해/충돌/stateHash에 영향을 주지 않는다.

## 멀티

- 2인 협동: 각 5유닛, 공유 기지/승패/거점 병기, 개인 보급/보급소. 팀 편성을 합쳐 콤보 계산.
- 재접속 유예 30초 동안 슬롯·보급·보급소 보존. 이후 AI가 해당 플레이어 슬롯/경제를 인계하고 복귀 시 회수.
- 합동 병기: 한 명 사용 후 1.5초 내 다른 플레이어 확인 시 강화. 혼자 사용해도 기본 버전 즉시 발동 가능.
- 1v1/2v2는 동일 전투 코어. 랭크 기본 목표 4~6분. PvP 처치 보급은 PvE의 약 20~30% 후보.
- 랭크는 Lv.30 표준화. 친구전은 성장전/표준전 선택.
- 초기 2v2 공개 매칭보다 친구방 우선.

## 계정/서버

- 게스트 핵심 진행은 IndexedDB. localStorage는 설정 정도만.
- 로그인은 Google + 이메일 우선. 로그인 계정의 경제/가챠/성장/통화는 서버가 정본.
- 멀티에서 클라이언트는 명령만 전송. 서버가 보급·쿨다운·소유권·충돌·피해를 결정.
- 명령은 matchId/playerId/clientSequence를 포함하고 서버가 중복/스팸/불가능 행동을 거부.
- 30Hz 전체 상태를 매 틱 전송하지 않고 중요 이벤트 + 약 10~15Hz 패치/스냅샷 + 보간. 주기적 stateHash로 desync 탐지.
- 인프라: Cloudflare Pages(클라이언트), Workers(API/매치 입구), Durable Objects(실시간 방), D1(계정/진행), 필요 시 R2(대형 에셋).

## 아트/UI

- 초기 기준 화풍은 LuizMelo CC0 횡스크롤 픽셀아트 계열.
- 무료 에셋을 무작정 섞지 않는다. 원출처/라이선스/수정 여부를 Asset Registry에 기록.
- 기존 Hit는 상시 피격이 아니라 KB 모션 후보. 일반 Death는 공통 퇴장 연출로 단순화 가능.
- 신규 캐릭터 제작은 `역할/비용/사거리/KB/타격 프레임 → 정지 디자인 → Idle/Run/Attack/KB → 실제 판정 동기화 → 실전 검수` 순서.
- 공격 모션이 최우선이며 타격 프레임과 시각 타격 순간이 정확히 맞아야 한다.
- 640×360은 첫 브라우저 하네스에서 UI 글자가 흐릿해지는 문제가 확인되어 **기본 렌더 기준을 1280×720으로 상향**한다. 픽셀 캐릭터 텍스처는 nearest-neighbor를 유지하되 UI 텍스트를 전체 캔버스 pixelated CSS로 강제 확대하지 않는다.
- PC/모바일 모두 성 HP, 현재/최대 HP, 보급, 쿨다운 등 핵심 정보가 즉시 읽혀야 한다.
- 개발용 tick/hash/debug 텍스트는 일반 플레이 UI에 노출하지 않는다.
- 전문 속성은 편성에서 읽을 수 있어야 하고, 전투 중에는 적의 핵심 태그를 과밀하지 않은 형태로 식별할 수 있어야 한다.

## 개발/검증

- monorepo: `apps/client`, `apps/server`, `packages/sim`, `packages/shared`, `packages/content-schema`, `content`, `assets`, `tools`, `docs`.
- GitHub `main`이 정본. package-lock을 커밋.
- CI: install → typecheck → unit test → deterministic replay/hash test → content schema validation → build.
- 동일 seed+동일 명령 로그는 브라우저와 Node에서 같은 최종 stateHash를 만들어야 한다.
- 자동 밸런스는 표준 더미 6종과 seed 반복. CI는 30~50 seed 빠른 회귀, 심층 검사는 1,000 seed.
- 수동 검수: 타격 프레임 동기화, KB/ForcedDisplacement 취소 자연스러움, anchor 흔들림, 저비용 유닛 과밀, 모바일 오조작, UI 가독성, 맵별 지면/거점 정렬, 잠긴 스테이지 우회 진입 방지.
- 캠페인 baseline은 각 스테이지 이전에 실제로 획득 가능한 캐릭터와 보물만 사용한다. 미래 해금/미래 보물로 통과하는 가짜 테스트를 금지한다.

## 첫 사용자 수동 테스트 게이트

개발자용 전투 하네스가 동작한다는 이유만으로 사용자에게 테스트를 요청하지 않는다. 다음 조건을 모두 만족한 뒤 첫 사용자 테스트를 요청한다.

- 메인 화면이 존재한다.
- 스테이지 선택 화면이 존재하고 20스테이지를 페이지 단위로 탐색할 수 있다.
- 새 진행 데이터에서 STAGE 1만 열리고 징집병 1종만 보유한다.
- 스테이지 클리어 후 다음 스테이지와 지정 캐릭터가 정상적으로 순차 해금된다.
- 편성 화면에서 보유/미해금 10종 상태가 명확히 구분된다.
- 전투에서 문자/도형 대체물이 아니라 실제 기준 화풍 스프라이트가 움직이고 공격한다.
- 최소 7개 전장 계열과 스테이지별 전장 길이/장식 차이가 실제 화면에 반영된다.
- ST19/ST20은 일반 황금길과 구분되는 보스전 랜드마크가 보인다.
- 양쪽 거점 HP바와 숫자가 선명하게 보인다.
- 보급/생산비/쿨다운/보급소가 정상 작동한다.
- 거점 병기 1슬롯이 정상 작동하고 자연 KB/강제이동과 충돌하지 않는다.
- 원거리/마법 공격의 발사→도달 연출이 실제 hitFrame과 명백하게 어긋나지 않고 60fps 이상 렌더에서 30Hz 계단 이동처럼 보이지 않는다.
- 속성/전문 역할을 편성에서 읽을 수 있고 적 속성 식별이 전투를 가리지 않는다.
- 승리/패배 결과 화면이 존재한다.
- 승리 시 해당 스테이지 보물을 첫 클리어 100% 확정 획득하며 게스트 진행을 IndexedDB에 기록한다.
- 획득한 보물의 typed modifier가 다음 전투의 실제 전투/경제 설정에 반영되고, 미획득 보물은 적용되지 않는다.
- 일반 플레이 글자가 PC 기준으로 뭉개져 보이지 않는다.

## 첫 콘텐츠 마일스톤

- 플레이어 캐릭터 10종(C3/B3/A2/S1/SS 또는 X1)을 실제 화면에서 운용 가능하게 한다.
- 적 8종 + 보스 2종, 스테이지 20개, 최소 7개 전장 계열을 첫 캠페인 프로토타입에 포함한다.
- 초기 전문 태그는 `LIGHT / ARMORED / ARCANE / BOSS` 4종을 사용한다.
- 이후 거점 병기 종류는 2종 이상 후보로 확장할 수 있으나 한 전투의 즉시 개입 병기 슬롯은 1개로 유지한다.
- 멀티보다 싱글 전투 재미 검증을 먼저 통과한다.

## Anti-goals

- 희귀도만 높으면 저등급이 전부 사라지는 구조.
- 배율만으로 난이도 상승.
- 만능 캐릭터.
- FOMO/에너지/필수 RNG 파밍.
- 보물 등급/드랍률 반복 파밍.
- 보물 획득 문구만 있고 실제 효과가 적용되지 않는 가짜 영구 보상.
- 미래 스테이지 보물을 현재 baseline이나 실제 플레이에 미리 적용하는 구조.
- 처음부터 모든 캐릭터/스테이지를 열어 진행 감각을 없애는 구조.
- 모든 스테이지가 같은 배경/같은 전장 길이를 재사용하는 구조.
- 중복 강제 성장.
- 싱글/멀티 전투 코어 분리.
- 그림체가 다른 무료 에셋 무작정 혼합.
- 공격 애니메이션과 실제 타격 프레임 불일치.
- 한 전투에 여러 거점 병기 버튼을 동시에 늘어놓아 캐릭터 액티브처럼 만드는 구조.
- 캐릭터별 액티브 버튼 남발.
- 초기부터 수십 성장 재화/후반 시스템 동시 구현.
- 개발자용 하네스를 완성된 테스트 빌드처럼 사용자에게 전달.

## 현재 구현 순서

1. 신규 계정 `징집병 1종 + STAGE 1만 개방` 및 20스테이지 순차 개방/9회 확정 해금 회귀검사.
2. 20개 확정 보물 typed modifier를 실제 전투 설정에 적용하고 미래 보물 선적용을 금지한다.
3. 7개 전장 계열·스테이지별 decorSeed·전장 길이·보스 랜드마크의 시각/판정 동기화 검증.
4. 10종 로스터의 LuizMelo 기준 화풍 실제 스프라이트 및 공격 프레임/원거리 투사체 정교화.
5. Character/Enemy/Stage/Treasure 데이터와 속성/전문 태그의 단일 정본 유지.
6. 거점 병기 1슬롯 + 자연 KB와 분리된 ForcedDisplacement 검증.
7. ST1~ST20 baseline을 실제 시점의 캐릭터+보물 진행 상태로 회귀하고 초반/중반/후반 난이도를 감사한다.
8. 모바일/PC 수동 UI 검수와 밸런스 조정.
9. 첫 수동 테스트 게이트 통과 후 사용자 실플레이 피드백 반영.

# Frontline Summoners 정본 v1.1 — 1차 완성 범위

> 이 문서는 전선소환전의 최상위 게임 규칙이다. 세부 시스템은 `docs/GAME_DESIGN_FULL.md`, `docs/GROWTH_RECRUITMENT_DESIGN.md`, `docs/STAGE_SYSTEM_DESIGN.md`, `docs/content-wiki/`를 따른다. 실제 실행값이 최신 정본과 다르면 구현 불일치로 취급하고 코드 쪽을 조용히 정답으로 삼지 않는다.

## 1. 1차 완성의 경계

- 1차 완성은 **냥코 대전쟁의 본능에 해당하는 후반 성장축 직전까지의 완성된 게임**을 목표로 한다.
- 메인 4장 × 20 = **80스테이지**.
- 기본 레벨 상한: 시작 Lv10 → 1장 Lv20 → 2장 Lv30 → 3장 Lv40 → 4장 Lv50.
- Lv50 이후의 새 후반 성장축, 난이도 9~12 본격 콘텐츠, 추가 대형 시스템은 1차 완성 후 업데이트에서 설계한다.
- 1차 완성 전에 후반 시스템을 계속 추가해 범위를 넓히지 않는다.

## 2. 제품 원칙

- Web PC/모바일 브라우저 기반 횡스크롤 실시간 소환 전략 게임.
- 싱글 플레이만으로 핵심 성장과 본편을 완주할 수 있어야 한다.
- 2인 PvE 협동과 PvP 일반/랭킹/친선을 지원한다.
- 에너지/스태미나를 전제로 설계하지 않는다.
- FOMO, 필수 RNG 보물작, 외부 위키 의존을 피한다.
- 핵심 재미는 보급 → 생산 → 전선 → 사거리 → 공격 프레임 → KB → 재생산 → 적 스폰의 상호작용이다.
- 캐릭터 액티브 버튼을 남발하지 않고 생산, 보급소, 거점 병기, 덱 구성과 성장에 집중한다.
- `prototype`, `TODO`, `debug`, 내부 ID, save version, 개발 메모 같은 개발자 문구를 플레이어 UI에 노출하지 않는다.

## 3. 전투 코어

- 고정 30 tick/s 결정론 시뮬레이션.
- 싱글과 권위 멀티 서버는 동일한 simulation core 사용.
- 전투 판정은 1D X축, Y는 시각 연출용.
- 공격은 anticipation/선딜 → hit/contact → recovery 구조.
- standingRange와 실제 attackMin/attackMax를 분리한다.
- 실제 피해 대상은 hit frame에 유효 범위로 판정한다.
- 동일 프레임 피해는 먼저 수집한 뒤 일괄 적용한다.
- 자연 KB와 강제이동은 별도 규칙이다.
- HP≤0은 즉시 전투 대상에서 제외한다.
- 멀티히트의 각 hit와 시각 contact를 1:1로 맞춘다.
- 모든 보정 후 최종 재생산 시간은 **60F = 2초 미만으로 내려가지 않는다.**

## 4. 전투 경제

- 전투 자원은 `보급` 하나.
- 캐릭터 생산과 보급소 강화가 같은 자원을 경쟁한다.
- 초반부터 보급이 넘쳐 무지성 연타가 되지 않게 한다.
- 반대로 기다리는 시간이 전투 대부분이 되지 않게 한다.
- 제1장은 현재 저속 경제 방향을 유지하고 뒤 장에서 점진적으로 tempo를 높인다.
- 협동에서도 플레이어별 보급/보급소/생산 cooldown은 독립이다.

## 5. 캐릭터 성장

- 기본 레벨 Lv1~50.
- Lv은 HP/기본 공격력 중심으로 강하게 체감되어야 한다.
- 현재 DESIGN_TARGET 앵커:
  - Lv1 ×1.00
  - Lv10 ×1.90
  - Lv20 ×3.25
  - Lv30 ×5.00
  - Lv40 ×7.25
  - Lv50 ×10.00
- 사거리, 비용, 재생산, 이속, KB, 공격 방식은 기본 레벨 때문에 자동 증가하지 않는다.
- +레벨은 중복 성장축이며 현재 +50 후보.
- 현재 +레벨 후보식: `1 + 0.02 × plusLevel`.
- 같은 캐릭터 중복 직접 +1이 가장 효율적이다.
- 중복을 공용 +성장 재화로 분해해 다른 캐릭터에 쓸 수 있으나 교차 효율은 낮다.
- Base Lv50만으로 정상 완성 성능이어야 하며 S/SS 중복이 정상 사용의 필수조건이 되어서는 안 된다.

## 6. 진화

- F1/F2/F3 구조.
- 소유권, 기본 Lv, +Lv 공유.
- 이전 형태를 무료로 재선택 가능하게 하는 것을 기본으로 한다.
- F3가 항상 단순 상위호환일 필요는 없다.
- 형태별로 HP/공격/비용/재생산/사거리/이속/KB/공격범위/멀티히트/대항 능력까지 달라질 수 있다.
- 단순 색놀이 진화 금지.
- 진화재료 체급은 SS가 STORY/C의 약 4~5배까지 허용하는 DESIGN_TARGET을 사용한다.

## 7. 획득 분류와 희귀도

- STORY 캐릭터는 모집 희귀도가 없다: `acquisitionClass=STORY`, `rarity=null`.
- 모집 희귀도: C / B / A / S / SS.
- C/B/A는 대부분 시리즈 공통 풀.
- S/SS는 시리즈 전용.
- **SS는 시리즈당 정확히 1명.**
- 희귀도는 비용이나 전투력의 절대 서열이 아니다.
- C/B/A도 후반까지 비용/재생산/전문 역할로 사용 가치가 있어야 한다.
- X는 희귀도로 사용하지 않는다.

## 8. 초기 로스터

1차 DESIGN_TARGET 플레이어 로스터 총 43종.

- STORY 10
- 공통 모집 C/B/A 15
- 초기 3시리즈 S15 + SS3

초기 시리즈:

1. 성휘의 기사단
2. 태고의 거수
3. 제로 엣지

각 시리즈는 S5 + SS1로 시작한다.

S/SS, 특히 SS3의 정식 아트는 사용자 검수 전 LOCKED로 올리지 않는다.

## 9. 모집

- 여러 모집 시리즈를 운영한다.
- C/B/A 공통, S/SS 해당 시리즈 전용.
- 누적 pity, 10/30/60/100 보장, 직접 선택권/selection credit을 사용하지 않는다.
- 현재 확률 DESIGN_TARGET: C 42 / B 32 / A 22.7 / S 3 / SS 0.3%.
- 모집 재화는 충분히 공급하되 경제 시뮬레이션으로 검증한다.
- S/SS는 차등 연출을 사용하고 SS는 시리즈별 고유 최고 연출을 가진다.
- 결과 연출은 스킵 가능해야 한다.

## 10. 속성과 전투 태그

1차 속성:

- NEUTRAL
- BEAST
- UNDEAD
- NATURE
- ARCANE
- DEMON
- MACHINE
- ANOMALY

핵심 전투 태그:

- ARMORED
- FLOATING
- GIANT
- BOSS
- STRUCTURE
- SUMMON
- SWARM

- 공식 부유 태그는 **FLOATING**. `FLYING`은 금지 legacy alias.
- 속성/태그는 전역 가위바위보가 아니라 특정 대항/상태효과의 타겟 분류다.
- 아군도 동일 속성/태그 구조를 사용한다.

## 11. 도감과 편성

- 미발견 적/미획득 아군은 도감에서 실루엣 + `???`.
- 미획득 아군은 편성 목록에 표시하지 않는다.
- 발견한 적은 스테이지 출현 목록에서 도감으로 바로 이동 가능.
- 게임 내부에서 속성/태그/사거리/공격 구조/주요 스탯을 확인 가능하게 한다.
- 솔로/1v1 덱 10칸.
- 협동/2v2는 플레이어당 5칸, 팀 총 10칸.
- PC drag&drop, 모바일 long-press drag + tap fallback을 지원한다.

## 12. 메인 캠페인과 영구 보상

- 메인 4장 × 20 = 80.
- 1장 뒤집힌 국경 — NEUTRAL/BEAST.
- 2장 뒤틀린 숲 — NATURE/UNDEAD.
- 3장 마도도시 세라페 — ARCANE/DEMON.
- 4장 기어 제국의 균열 — MACHINE/ANOMALY.
- 각 장 ST20은 레벨 상한 해제 + 큰 추가 보상.
- 영구 보상은 같은 효과 반복 누적 허용.
- 이동속도 영구 증가 금지.
- 아군 출격/배치 한도 영구 증가 금지.
- 기본 영구 사거리 증가를 성장축으로 사용하지 않는다.
- 주요 축은 HP/공격/거점 HP/시작 보급/처치 보급/보급소 강화비/재생산 감소.

## 13. NORMAL_CLEAR, 2배속, 소탕

`NORMAL_CLEAR = 소탕이 아닌 실제 전투 승리`.

다음 둘 모두 동일하게 인정한다.

- 솔로 실제 승리
- 허용된 정상 2인 협동 실제 승리

NORMAL_CLEAR은 진행/FIRST_CLEAR/PERMANENT/다음 스테이지 해금을 인정한다.

- 해당 스테이지 NORMAL_CLEAR 후 무료 1×/2× 재클리어를 사용할 수 있다.
- sweepEligible 스테이지는 NORMAL_CLEAR 후 소탕권으로 소탕 가능.
- 소탕은 반복 보상만 처리하며 최초 NORMAL_CLEAR을 만들지 않는다.
- 소탕권이 없어도 직접 플레이는 항상 가능하다.
- 기록 SPECIAL/PvP는 소탕 불가.

## 14. SPECIAL

SPECIAL 대분류:

- 상시
- 주기
- 이벤트
- 기록

**SPECIAL 허브 최초 개방은 제1장 최종 `main_01_020` NORMAL_CLEAR 후다.**

```text
main_01_020 NORMAL_CLEAR
→ Chapter 1 완료
→ Lv20 상한 해금
→ SPECIAL 허브 개방
```

- 솔로/정상 협동 클리어 모두 동일.
- ST19까지는 허브가 열리지 않는다.
- 소탕으로 최초 SPECIAL 해금을 만들 수 없다.
- 허브 개방과 collection/stage 개별 해금은 분리한다.
- 제1장 이후 메인 2장과 SPECIAL을 자유롭게 왕복하는 구조다.
- 하나의 SPECIAL collection 안에 여러 내부 전장을 둘 수 있다.
- 대부분의 상시/주기/이벤트 SPECIAL은 SOLO_OR_COOP.
- 기록 SPECIAL은 기본 SOLO_ONLY.
- 기록 핵심은 `끝없는 전선`, `보스 러시` 두 개.
- 끝없는 전선은 제3장 완료 후, 보스 러시는 제4장 완료 후 개방 후보.
- 주기 고효율 반복보상은 보상 충전으로 통제할 수 있으나 플레이 입장은 막지 않는다.
- 같은 적/같은 스폰에 HP만 올린 단계 복제 금지.

## 15. 스토리 표시 정책

스토리는 **선택형 분위기 요소**이며 핵심 게임 시스템이 아니다.

- 장 시작/보스 등장/장 종료의 짧은 연출 정도만 사용 가능.
- 처음 보는 장면도 첫 프레임부터 즉시 Skip 가능.
- 설정에 `스토리 연출 자동 건너뛰기`를 제공한다.
- 스토리를 전부 스킵해도 진행, 보상, 튜토리얼, SPECIAL/시스템 해금 정보를 모두 이해할 수 있어야 한다.
- 핵심 전투 규칙을 대사에만 숨기지 않는다.
- gameplay boss telegraph와 narrative 연출을 분리한다.
- 협동에서 다른 플레이어가 스토리를 보고 있어도 상대를 대기시키지 않는다.
- 장대한 narrative bible은 1차 핵심 범위가 아니다.

## 16. 난이도 1~12

- 난이도 축은 1~12.
- 1차 대부분 1~7, 일부 8.
- 9~12는 후반 업데이트용.
- 숫자를 채우려고 HP/ATK를 과도하게 뻥튀기하지 않는다.
- 정상 해금 시점 계정의 성장, 초반/지속 압박, 보스, 경제, 덱 민감도, 사거리/맵, 시뮬레이션, 사람 플레이를 함께 본다.

## 17. 2인 PvE 협동

- 메인 대부분과 SPECIAL 대부분에서 솔로/협동 선택 가능.
- 플레이어당 5칸, 팀 총 10칸.
- 개인 보급/보급소/생산쿨.
- 공유 기지/전장/승패/거점 병기.
- 협동 최초 클리어도 NORMAL_CLEAR.
- 적을 2배 강화하지 않는다.
- 기본 보정 후보는 HP ×1.15~1.30 / ATK ×1.05~1.15 / 적 거점 ×1.10~1.20.
- 사거리/이속/공격주기/KB/적 수/스폰/패턴은 협동이라는 이유만으로 몰래 변경하지 않는다.
- 친구 초대와 공개 매칭.
- 재접속 유예와 임시 AI 인계 후보.

## 18. 친구 기능

- 친구 코드/검색.
- 요청/수락/거절.
- 친구 목록/온라인 상태.
- 협동/친선 초대.
- 최근 플레이어.
- 삭제/차단.
- 자유 텍스트 채팅은 1차 필수가 아니며 빠른 통신/핑을 우선한다.

## 19. PvP

- 일반전: 레이팅 없음.
- 랭킹전: MMR + 티어 + 순위표 + 보상.
- 친선전: 레이팅/보상 없음.
- 1차 정식 랭킹은 1v1.
- 2v2 일반/친선은 1차 지원, 2v2 랭킹은 동접 규모 확인 후.
- 랭킹 성장 표준화 DESIGN_TARGET: Lv50 / +0 / 메인 영구 전투보너스 0.
- 실제 보유 캐릭터와 해금 형태는 유지한다.
- PvP 전용 필수 성장재화 금지.

## 20. 거점 병기

- 전투당 거점 병기 1종 장착을 기본으로 한다.
- 초기 DESIGN_TARGET: 전선포 / 결계발진기 / 보급투하기.
- 협동은 shared weapon/cooldown 정책을 사용한다.
- PvP에서는 표준화한다.
- 캐릭터 액티브 스킬 대신 생산·경제·병기 타이밍을 직접 조작의 중심으로 둔다.

## 21. UI/UX·접근성·오디오

- 지휘소/전선 모티프의 배너/문장/리본/금속/목재/양피지 시각 언어를 사용하되 가독성이 우선.
- 단순 회색 사각형 카드만 반복하지 않는다.
- 모바일 가로 최소 640×360부터 실제 검증.
- COMPACT/MEDIUM/WIDE 반응형.
- 일반 최소 touch target 44×44 CSS px.
- safe area, 80/100/125/150% 확대, overflow를 검사한다.
- 화면 흔들림 0/50/100, flash reduction, reduce motion, high contrast/color assist, VFX density/저사양 옵션을 지원한다.
- BGM/SFX는 gameplay telegraph를 가리지 않는다.

## 22. 계정/저장

- 게스트 플레이.
- 로그인 계정.
- 게스트→로그인 진행 이전.
- 로그인 이후 경제/소유/진행은 서버 권위.
- 서버 진행과 게스트 진행이 모두 있으면 자동 위험 merge를 하지 않는다.
- 진행 초기화 / 계정 삭제 / 게스트 로컬 삭제를 분리한다.
- 위험 작업은 2단계 확인.
- battle/recruitment reward는 idempotent 처리한다.

## 23. 업적/프로필

- 업적은 자연스러운 진행, 다양한 플레이, 기록 표현을 보조한다.
- 반복 노가다/FOMO/필수 성장 gate로 만들지 않는다.
- 초기 약 45~55개 후보.
- 보상은 칭호/frame/banner/emblem/badge + 소량 재화 중심.
- PvP 상위 장식은 성능 효과 없음.

## 24. 콘텐츠/코드 정리 원칙

- 새 정본으로 교체한 시스템의 구형 code/data/test/UI를 같은 작업에서 정리한다.
- 구·신 구현 병존, 누적 hotfix, 임시 override를 금지한다.
- 과거 이름/필드/상수 참조가 0인지 검색한다.
- Git history가 과거를 보존하므로 죽은 코드를 저장소에 남기지 않는다.
- 콘텐츠는 위키에서 DESIGN_TARGET 이상으로 설계 후 구현한다.
- 구현 → 자동검증 → 실제 플레이 → TESTED → 필요 시 LOCKED 순서를 따른다.

## 25. 1차 완성 후

Lv50, 3형태, +레벨, 메인80, 초기 SPECIAL, 초기 3모집 시리즈, 친구/협동/PvP, 계정, UI/접근성까지 실제 사용자 루프로 안정화한 뒤에만 본능 대응 이후의 전선소환전 고유 후반 시스템을 별도 업데이트로 설계한다.

# Frontline Summoners 정본 v1.0 — 1차 완성 범위

> 이 문서는 전선소환전의 최상위 규칙이다. 세부 콘텐츠는 `docs/content-wiki/`, 시스템 세부는 `STAGE_SYSTEM_DESIGN.md`와 `GROWTH_RECRUITMENT_DESIGN.md`를 따른다. 실제 실행값이 이 문서/위키와 다르면 구현 불일치로 취급하고 조용히 코드 쪽을 정답으로 삼지 않는다.

## 1. 1차 완성의 경계

- 1차 완성은 **냥코 대전쟁의 본능에 해당하는 후반 성장 시스템 직전까지**를 목표로 한다.
- 메인 4장 × 20스테이지 = **80스테이지**를 기본 본편으로 잡는다.
- 시작 기본 레벨 상한 Lv10.
- 1장 클리어 → Lv20, 2장 → Lv30, 3장 → Lv40, 4장 → Lv50.
- Lv50 이후의 새 후반 성장축, 추가 고난도 상한, 본능 대응 시스템은 1차 완성 후 업데이트에서 설계한다.
- 1차 완성 전에 후반 시스템을 억지로 끼워 넣어 범위를 계속 넓히지 않는다.

## 2. 제품 원칙

- Web PC/모바일 브라우저 횡스크롤 실시간 소환 전략 게임.
- 싱글 플레이만으로도 완전한 진행이 가능해야 한다.
- 2인 PvE 협동, PvP 일반전/랭킹전/친선전을 지원한다.
- 과금과 에너지 제한을 전제로 설계하지 않는다.
- 놓치면 영구 손해가 되는 FOMO, 필수 RNG 보물작, 외부 위키 의존을 피한다.
- 전투 핵심은 보급 → 생산 → 전선 → 사거리 → 공격 프레임 → KB → 재생산 → 적 스폰의 상호작용이다.
- 캐릭터별 액티브 버튼을 남발하지 않고 소환, 보급소, 거점 병기, 덱 구성과 성장에 집중한다.
- 게임 내부에는 `prototype`, `TODO`, `debug`, 내부 ID, 저장 버전, 개발 메모, 임시 밸런스 같은 **개발자 문구를 노출하지 않는다**. 미완성 기능은 플레이어 UI에서 숨긴다.

## 3. 전투 코어

- 고정 30 tick/s 결정론 시뮬레이션을 사용한다.
- 싱글과 권위 멀티 서버는 동일한 simulation core를 사용한다.
- 판정 전장은 1D X축, Y는 연출 전용이다.
- 공격은 선딜 → hit frame → 후딜 구조이며, 실제 피해 대상은 hit frame 순간 공격 범위로 다시 판정한다.
- 동일 프레임 피해는 먼저 수집 후 일괄 처리한다.
- 자연 KB와 강제이동은 별도 규칙이다.
- HP≤0 즉시 사망 상태로 들어가 타겟/회복/상태효과 대상에서 제외된다.
- standing range와 실제 공격 최소/최대 범위를 분리한다.
- 재생산 감소가 아무리 누적되어도 **최종 재생산 시간은 2초 미만으로 내려가지 않는다.** 2초는 1차 밸런스 하한이며 테스트로만 조정한다.

## 4. 전투 경제

- 전투 자원은 `보급` 하나.
- 초반부터 돈이 넘쳐 무지성 연타가 되는 구조를 금지한다.
- 현재 제1장 저속 경제 방향을 유지하고, 후반 장에서 시작 보급/보급 효율을 점진적으로 확장한다.
- 보급소 강화는 실제 투자 선택이어야 한다.
- 협동에서도 플레이어별 보급과 보급소를 독립 유지한다.

## 5. 캐릭터 성장

- 기본 레벨은 Lv1~50.
- Lv 상승은 HP와 기본 공격력 중심으로 **강하게 체감**되어야 한다.
- 1차 밸런스 목표는 대략 Lv50에서 Lv1의 약 8~10배 전투 스탯 체감이며 정확한 곡선은 시뮬레이션/플레이테스트로 확정한다.
- 사거리, 생산비, 재생산, 이동속도, KB, 공격 방식 등 정체성 수치는 기본 레벨로 자동 증가시키지 않는다.
- +레벨은 중복 성장축이며 높은 상한을 둔다. 1차 목표 상한은 +50 후보.
- 같은 캐릭터 중복은 직접 +1에 쓰는 것이 가장 효율적이다.
- 중복을 공용 +성장 재화로 분해하여 다른 캐릭터에 재투자할 수 있으나 효율은 낮고 희귀도별 비용을 둔다.
- Base Lv50만으로도 정상적인 완성 캐릭터여야 하며 고희귀 중복이 정상 성능의 필수조건이 되지 않는다.

## 6. 진화

- 모든 정식 캐릭터는 기본적으로 1/2/3형태 구조를 사용할 수 있다.
- 이전 형태 재선택이 가능하다.
- 형태는 단순 상위호환일 필요가 없다.
- 형태별로 HP/공격, 비용, 재생산, 사거리, 이동, KB, 단일/범위, 멀티히트, 속성 대응, 효과, 공격 방식까지 크게 바뀔 수 있다.
- 3형태가 사실상 다른 역할의 캐릭터처럼 느껴져도 허용한다.
- 진화재료 요구량은 희귀도에 따라 차이가 나며 **SS는 C의 약 4~5배 수준**까지 허용한다. 이것은 재료 종류/수량의 설계 목표이지 모든 캐릭터에 동일 공식을 강제하지 않는다.

## 7. 획득 분류와 희귀도

- **스토리/기본 캐릭터는 모집 희귀도 C/B/A/S/SS를 부여하지 않는다.**
- 모집 캐릭터의 희귀도: C / B / A / S / SS.
- C/B/A는 시리즈가 달라도 대부분 공유하는 공통 모집 풀이다.
- S/SS는 시리즈마다 달라진다.
- **SS는 시리즈당 정확히 1명**을 기본 규칙으로 한다.
- 시리즈당 S는 초기 기준 5~7명 정도를 목표로 한다.
- 희귀도는 생산비/순수 전투력의 서열이 아니다. 저희귀 초고비용 공성병, 고희귀 저비용 벽 등 모두 허용한다.
- C/B/A도 후반까지 사용 가치가 있어야 하며, S/SS는 희소성·시리즈 대표성·전투/시각 개성에 의미를 둔다.
- 업데이트가 누적되면 S 총수가 C/B/A보다 많아질 수 있으며 이는 정상이다.

## 8. 초기 모집 시리즈

1차 완성의 첫 모집 시리즈는 3개를 목표로 한다.

1. **성휘의 기사단** — 미소녀/판타지 영웅 중심, 단순 의상 색놀이 금지.
2. **태고의 거수** — 괴수/이형 생물 중심.
3. **제로 엣지** — 최첨단 전투기술/로봇/드론/SF 검단 중심.

각 시리즈 S/SS의 최종 콘셉트는 별도 검수 후 확정한다. 세부 초안은 콘텐츠 위키에 기록한다.

## 9. 모집 규칙

- 여러 모집 시리즈가 존재한다.
- C/B/A는 공통 풀, S/SS는 해당 시리즈 풀.
- 누적 천장, 60회 SS 보장, 100회 직접 선택권 등 과거 천장 체계는 **폐기**한다.
- 고희귀 획득률은 모집 재화가 후하게 공급되는 구조를 전제로 낮게 잡을 수 있다.
- S/SS는 등급별 고유 연출을 가지며 SS는 해당 시리즈를 대표하는 특별 연출을 갖는다.
- 결과 연출은 반복 시 스킵 가능해야 한다.

## 10. 속성/태그

- 플레이어 캐릭터와 적 모두 속성을 가진다. PvP에서도 동일 규칙을 사용한다.
- 속성은 냥코식 전문 대항 구조처럼 특정 캐릭터의 특효/저항/상태효과 타겟을 만드는 핵심 분류다.
- 전역 가위바위보 표를 강제하지 않는다.
- 전투 태그는 `중갑`, `부유`, `거대`, `보스`, `구조물`, `소환체` 같은 보조 분류로 사용하고 별도의 두 번째 상성표로 만들지 않는다.
- 전투 중 적 머리 위에 모든 속성을 상시 표시하지 않는다. 외형과 도감으로 학습하게 한다.

## 11. 도감과 식별성

- 미발견 적은 도감에서 실루엣 + `???`.
- 미획득 아군도 도감에서 실루엣 + `???`.
- 편성 화면에는 **보유한 아군만 표시**한다.
- 스테이지 출현 적 목록에서 이미 발견한 적을 누르면 도감 항목으로 바로 이동한다.
- 도감은 속성, 전투 태그, 공격 방식, 주요 스탯/특징, 등장처 등 게임 내 전략 정보의 기준 화면이다.
- 적과 아군 모두 작은 전투 화면에서 실루엣으로 구별되도록 설계한다. 인간형만 반복하지 않고 괴수, 기계, 동물, 부유체, 구조물형 등 폭넓은 체형을 허용한다.

## 12. 덱/편성 UI

- 솔로/1v1 기본 덱은 10칸.
- 2인 협동/2v2는 플레이어당 5칸, 팀 전체 10칸.
- PC와 모바일 모두 드래그 앤 드롭으로 원하는 슬롯에 바로 배치/순서 변경 가능해야 한다.
- 클릭/탭 추가도 보조 입력으로 지원할 수 있다.
- 필터: 전체/스토리/C/B/A/S/SS, 속성 대항, 역할, 비용, 레벨, +레벨, 최근 획득, 즐겨찾기 등.
- 자주 쓰는 필터는 칩, 나머지는 상세 필터 패널로 분리한다.

## 13. 메인 캠페인과 영구 보상

- 초기 본편은 4장 × 20스테이지.
- 각 장의 20개 영구 보상은 **서로 모두 달라야 할 필요가 없다**. 같은 성장축이 반복되어 누적 체감을 만드는 것을 허용한다.
- 이동속도 영구 보너스와 아군 배치 한도 영구 증가는 사용하지 않는다.
- 적절한 축: 아군 HP/공격, 특정 역할 HP/공격, 거점 HP, 시작 보급, 처치 보급, 보급소 강화비, 재생산 감소 등.
- 20번째 장 최종 보상은 기본적으로 `레벨 상한 해제 + 추가 보상`이다.
- Lv50 이후 장에서는 상한 해제 대신 추가 보상만 준다.
- 재클리어한 스테이지는 무료 2배속 사용 가능. 첫 클리어는 1배속을 기본으로 한다.

## 14. SPECIAL 구조

SPECIAL은 `상시 / 주기 / 이벤트 / 기록` 계열로 운영한다.

- 대부분의 상시/주기/이벤트 SPECIAL은 **솔로와 2인 협동 모두 가능**.
- 기록형은 기본적으로 솔로 전용.
- 기록형 1차 핵심은 **끝없는 전선**과 **보스 러시** 두 개면 충분하다.
- 하나의 SPECIAL 묶음 안에 여러 단계 스테이지를 둘 수 있다. 재화전뿐 아니라 보스전, 속성전, 이벤트에서도 사용 가능하다.
- 예: `황금 수송대` 하나의 카드 안에 초급~최상급/고유명 4~5단계.
- 각 단계는 단순 HP배율만 올리지 않고 적 구성/기믹/보스가 발전해야 한다.
- 주기성 고효율 보상은 `보상 충전`으로 횟수를 통제할 수 있으나 플레이 자체는 막지 않는다.
- 끝없는 전선은 개인 최고 기록의 새 1분 구간을 처음 넘을 때만 1회 보상을 준다.

## 15. 소탕/스킵

- 1회 이상 직접 클리어한 스테이지에 사용할 수 있는 `소탕권` 계열 아이템을 둔다.
- 소탕은 반복 보상만 획득하며 최초 클리어를 대체하지 않는다.
- 고효율 보상 충전형 SPECIAL에서는 소탕권과 충전 1회를 함께 소비한다.
- 끝없는 전선, 보스 러시, PvP에는 사용할 수 없다.
- 소탕권이 없더라도 직접 플레이는 항상 가능해야 하며 사실상의 에너지 시스템이 되어서는 안 된다.

## 16. 난이도 1~12

- 난이도 1~12 축을 사용하되 **숫자를 채우기 위해 고난도를 억지로 만들지 않는다**.
- 1차 완성에서 대부분 1~7, 일부 후반/SPECIAL 8 정도가 자연스럽다.
- 9~12는 후반 성장/업데이트에 필요할 때 사용한다.
- 난이도는 정상 해금 시점의 계정 성장, 적 총압박, 초반 압박, 보스, 대응 속성, 덱 민감도, 경제 압박, 시뮬레이션과 사람 플레이테스트를 함께 보고 매긴다.
- HP/공격력만 올려 난이도 숫자를 맞추지 않는다.

## 17. PvE 협동

- 메인과 SPECIAL은 스테이지별로 `솔로 전용 / 솔로+협동 / 협동 전용`을 지정할 수 있다.
- 대부분의 메인/SPECIAL은 솔로+협동 가능을 목표로 한다. 기록형 등 규칙상 필요한 콘텐츠만 솔로 전용.
- 협동 최초 클리어도 정상 진행/보상/해금을 인정한다.
- 2인 협동은 각자 5칸, 개인 보급/보급소/생산쿨, 공유 기지/승패/거점 병기.
- 총 편성 종류는 팀 10종이므로 협동 적 보정은 과하지 않게 한다.
- 기본 보정 후보는 적 HP/공격/적 거점 HP의 소폭 증가이며, 사거리/이동/공격주기/스폰/적 수/패턴은 함부로 바꾸지 않는다.
- 친구 초대와 공개 매칭을 지원한다.
- 재접속 유예와 임시 AI 인계를 지원하는 방향으로 구현한다.

## 18. 친구 기능

- 친구 코드/검색, 요청/수락/거절, 친구 목록, 온라인 상태, 협동 초대, 친선전 초대, 최근 함께 플레이한 사람, 삭제/차단을 지원한다.
- 자유 텍스트 채팅은 1차 핵심이 아니다. 빠른 통신/핑을 우선한다.

## 19. PvP

- **일반전**: 레이팅 변동 없음, 부담 없는 실험/재미용.
- **랭킹전**: MMR + 티어 + 순위표 + 티어/시즌 보상.
- **친선전**: 친구 초대, 레이팅/보상 없음, 옵션 자유도 높게.
- 랭킹전은 육성 수치 표준화를 기본으로 하여 Lv/+Lv/영구보상 격차가 승패를 결정하지 않게 한다.
- 보유 캐릭터와 해금 형태의 수집 의미는 유지한다.
- 랭킹 보상은 골드/모집재화/+재화/진화재료/프로필 장식/칭호 등을 줄 수 있으나 PvP 전용 필수 성장 재료를 만들지 않는다.
- 1차 우선순위는 1v1 일반/랭킹, 2v2 일반/친선. 2v2 랭킹은 동접 규모 확인 후 업데이트 가능.

## 20. UI/UX 품질

- 단순 사각형 패널만 반복하지 않고 세계관에 맞는 배너/방패/리본/금속/목재/원형 게이지 등 시각 언어를 구축한다.
- 외부 게임 UI 참고와 무료/CC0 UI 리소스를 조사해도 되지만 직접 복제하지 않는다.
- PC/모바일 가로 화면에서 텍스트 잘림, 겹침, 화면 밖 배치가 없어야 한다.
- 동적 목록은 grid/page/scroll을 사용하고 `index*x`식 무제한 가로 배치를 금지한다.
- 돈 부족, 쿨다운 완료, 선택 불가 이유, 새 캐릭터 획득, 재도전, 배속 상태 등 사소한 상호작용 피드백을 게임성의 일부로 취급한다.

## 21. 계정/저장

- 게스트 플레이 지원.
- 로그인 계정 지원.
- 게스트 진행을 로그인 계정에 일회성 이전 가능.
- 진행 초기화와 계정 삭제를 구분한다.
- 위험 작업은 2단계 확인을 사용한다.
- 서버 계정은 서버 저장이 권위, 게스트는 로컬 저장을 사용한다.

## 22. 콘텐츠/코드 정리 원칙

- 새 정본으로 교체된 시스템의 구형 코드/데이터/테스트/문서는 같은 작업에서 정리한다.
- 임시 override, 누적 hotfix, 구·신 구현 병존을 금지한다.
- 과거 이름/필드/상수의 참조가 0인지 검색해 확인한다.
- Git 히스토리가 과거 구현을 보존하므로 죽은 코드를 저장소 안에 보관하지 않는다.
- 세부 캐릭터/적/스테이지는 `docs/content-wiki/`에서 먼저 설계하고 구현한다.
- 콘텐츠 문서는 `DESIGN_TARGET → TESTED → LOCKED` 상태를 명시한다. 실제 플레이테스트로 더 나은 답이 확인되면 문서와 구현을 함께 수정한다.

## 23. 1차 완성 후

Lv50, 3형태, +레벨, 4장 메인, 초기 SPECIAL, 3개 모집 시리즈, 온라인 핵심이 안정적으로 완성된 뒤에만 본능 시점 이후의 전선소환전 고유 후반 시스템을 별도 업데이트로 설계한다.

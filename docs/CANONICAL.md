# Frontline Summoners 정본 v0.29 요약

> 상세 원본: `docs/GAME_DESIGN_FULL.md`. 이 문서는 현재 구현과 향후 개발에서 반드시 지켜야 하는 핵심 결정만 압축한 정본이다. 매 작업 전에 이 문서를 다시 읽고, 설계를 바꿀 때는 구현과 문서를 함께 갱신한다. v0.29는 v0.28까지의 전투·경제·맵·수집·시각 식별성 규칙에 더해 **진화를 외형·애니메이션·VFX·전투 효과까지 변화하는 핵심 성장 시스템으로 고정**한다.

## 1. 제품 정의

- Web PC/모바일 브라우저 횡스크롤 소환 전략 게임.
- 검증된 `돈 → 생산 → 전선 → 사거리 → 공격 프레임 → KB → 재생산 → 적 스폰` 상호작용과 단계적 캠페인 개방 감각을 참고하되 수치·캐릭터·명칭·아트·맵은 독자 설계한다.
- 싱글 플레이만으로 완전한 게임이어야 한다. 이후 멀티는 2인 협동, 1v1, 2v2.
- 현재 과금 없음. 에너지 제한, FOMO, 필수 RNG 보물작, 중복 강제 성장 금지.
- 분위기는 판타지 약 40% + 개그/괴상함 약 60%.
- 캐릭터별 액티브 버튼을 남발하지 않는다. 전투 중 직접 개입은 소환·보급소 강화·장착 거점 병기 중심.

## 2. 전투 시뮬레이션

- 규칙은 고정 30 tick/s. 렌더링은 60fps 이상 보간 가능.
- 브라우저 싱글과 권위 멀티 서버가 동일 `packages/sim` 코어를 사용한다.
- HP·보급·프레임·좌표는 정수 우선. 랜덤 필요 시 seed 기반 결정적 PRNG 하나만 사용.
- 틱 순서: 입력 확정 → 타이머/경제 → 스폰 → 이동 → 탐지/상태 전이 → 모든 타격 수집 → 피해/효과 일괄 적용 → 자연 KB/강제이동/사망 → 제거/승패 → stateHash.
- 동일 프레임 타격은 먼저 수집 후 일괄 처리하여 순회 순서가 결과를 바꾸지 못한다.
- 판정 전장은 1차원 X축. Y축은 시각 연출 전용.
- 공격 상태: 이동 → 선딜 → 정확한 hitFrame → 후딜 → 공격 대기.
- 공격 시작 대상은 트리거일 뿐 실제 피해 대상은 hitFrame 순간 공격영역으로 다시 판정한다.
- 자연 KB는 공격/남은 멀티히트를 취소한다. 한 피해 패킷으로 자연 KB 임계 여러 개를 넘더라도 자연 KB는 최대 1회만 발생하고 중간 임계는 소비한다.
- 자연 KB와 능력 Push/`FORCED_DISPLACEMENT`는 별도 상태. 강제이동 중 hurtbox 유지, 자연 KB가 발생하면 강제이동 취소.
- HP≤0 즉시 `DYING`; 타겟·회복·상태효과 대상에서 제외.
- standingRange와 실제 attackMin/MaxRange를 분리한다.
- 기본 아군 배치 한도 50, 적 약 40~60. 제한전에서 별도 조정 가능.
- stateHash는 현재 HP/좌표뿐 아니라 맵 길이, 거점 정의, 유닛 공격/사거리/KB/속성, displacement, 보급소, 비용/쿨다운, 적 보상, 미래 웨이브, 배치 한도, 거점 병기 등 미래 판정을 바꾸는 설정까지 포함한다.

## 3. 솔로 일시정지

- **솔로 전투는 언제든 완전 일시정지 가능**하다.
- 일시정지 동안 simulation tick이 증가하지 않으며 보급 증가, 재생산 쿨다운, 거점 병기 쿨다운, 적 스폰, 이동/공격, 시각 투사체 진행도 함께 정지한다.
- 화면 버튼과 PC `P`/`ESC`를 제공한다.
- 일시정지 중 소환·보급소 강화·거점 병기 입력은 처리하지 않는다.
- 모바일 세로 화면 가독성 가드가 활성화된 동안도 전투 tick을 정지하고 가로 복귀 시 같은 상태에서 이어간다.
- 멀티플레이에서는 개별 플레이어가 전체 전투를 일시정지시키지 못한다.

## 4. 경제 / 초반 템포

- 전투 자원은 `보급` 하나.
- **초반부터 돈이 넘쳐 물량을 무지성 연타하는 구조를 금지**한다. 첫 판에는 싼 기본병 한두 기를 두고 기다림·생산·보급소 투자 선택이 생겨야 한다.
- 현재 제1장 프로토타입 기본 보급소:
  - Lv1: 12/초, 최대 1000
  - Lv2: 16/초, 최대 1400, 강화비 160
  - Lv3: 22/초, 최대 1900, 강화비 260
  - Lv4: 29/초, 최대 2500, 강화비 390
  - Lv5: 38/초, 최대 3200, 강화비 560
  - Lv6: 49/초, 최대 4000, 강화비 760
  - Lv7: 62/초, 최대 5000, 강화비 1000
  - Lv8: 78/초, 최대 6200, 강화비 1300
- ST1 시작 보급은 50이며 징집병 비용도 50이다. 시작 즉시 대량 생산 가능한 자본을 주지 않는다.
- 제1장 시작 보급은 ST1~20에서 대략 50→260으로 완만히 증가한다.
- 적 처치 보급도 초반 경제를 즉시 포화시키지 않도록 제한한다.
- 비싼 후반 유닛은 보급소 최대치 자체를 올려야 생산 가능할 수 있다. 지갑 강화가 실제 전략 선택이어야 한다.
- 단, 경제를 줄였다는 이유로 플레이가 장시간 무행동 대기가 되어서는 안 된다. 스테이지별 시작 보급·수입·처치 보급·웨이브를 함께 조정한다.

## 5. 거점 HP / 이동속도 템포

- 초반 거점은 수천~수만 HP로 시작하지 않는다. 작은 피해도 읽히고 한 판이 지나치게 늘어지지 않아야 한다.
- 현재 후보: ST1 아군 900 / 적 800에서 시작, 후반으로 점진 증가, ST20 아군 4000 / 적 7200 수준.
- 제1장 일반 이동속도는 이전 개발 하네스보다 전반 하향한다. 시작 징집병 3, 첫 일반 적 2, 명시적 돌격병만 4 수준.
- 느린 탱커/마법사는 1~2, 빠른 전열은 2~3, 특수 돌격 역할만 그 이상을 허용한다.
- 속도가 높아 맵 길이와 사거리 설계가 무의미해지는 것을 금지한다.

## 6. 능력 / 속성

- 제1장 1차 태그: `LIGHT / ARMORED / ARCANE / BOSS`.
- 속성 자체에는 전역 가위바위보 약점표가 없다. 기본 공격은 모든 적에게 정상 피해.
- 명시된 전문 피해 보너스만 해당 태그에 적용하며 여러 조건이 맞아도 가장 강한 하나만 적용. permille 정수 사용.
- 초기 핵심 후보: 단일/범위, 장거리, 전후방, 멀티히트, Push, Slow, Freeze, Weaken, Strengthen, Critical, 방어관통.
- 동일 상태효과는 단순 합산보다 더 강한 효과 + 더 긴 잔여시간을 기본으로 한다.

## 7. 캐릭터 시각 식별성

- **캐릭터는 이름표나 색상 없이 작은 전투 화면에서도 실루엣만 보고 구분 가능해야 한다.**
- 종족, 생물학적 형태, 체형, 키, 머리/몸 비율, 팔다리 길이, 장비 부피, 대표 소품, 이동 방식, 공격 자세 중 여러 축을 적극적으로 다르게 한다.
- 사람형 캐릭터만 색·투구·망토를 바꿔 수십 종 만드는 식의 반복을 금지한다.
- 사람, 소형 종족, 거구, 비인간형, 기계/골렘형, 동물형, 부유형, 탈것형, 괴물형 등 세계관에 맞는 다양한 실루엣군을 확장 후보로 둔다.
- 같은 역할이라도 외형 언어가 같아야 할 필요는 없다. 역할은 전투 수치로, 정체성은 실루엣과 모션으로 읽히게 한다.
- 진화 형태도 이전 형태와 분명히 구분되는 실루엣/장비/VFX 변화가 있어야 한다.
- 단순 색놀이 스킨을 새 캐릭터나 진화로 취급하지 않는다.

## 8. 덱 / 기본 로스터 / 획득

- 솔로/1v1 10칸. 협동/2v2는 플레이어당 5칸, 팀 전체 10칸.
- 신규 계정은 **징집병 1종만 보유**한다.
- 제1장 확정 합류: ST1 방벽기사 → ST2 수렵창병 → ST4 결투검사 → ST6 청창대 → ST8 전투마도사 → ST10 화염술사 → ST13 왕실기사 → ST16 이단주술사 → ST20 공허현자.
- **기본/핵심 로스터는 약 10종이면 충분하다.** 현재 제1장 10종을 그 역할로 사용한다.
- 10종 이후의 대부분의 캐릭터는 모집(뽑기), 특정 스테이지/보스 첫 클리어, 외전, 이벤트, 도전 콘텐츠 등 별도 획득 루트로 확장한다.
- 모든 신규 캐릭터를 메인 스토리 자동 지급으로 몰아넣지 않는다.
- 캐릭터 풀이 커지면 10칸 수동 편성이 핵심 메타가 된다.
- 희귀도 C/B/A/S/SS 후보. 희귀도가 곧 절대 성능 순위가 되어서는 안 된다. X는 변칙/규칙 파괴 태그 후보.
- 가챠는 새 장난감 공급 장치다. 현재 10종뿐인 단계에서는 대규모 모집 경제를 억지로 열지 않고, 충분한 풀을 만든 뒤 후한 지급 구조로 확장한다.
- 중복은 캐릭터 조각 + 공용 조각 후보. 정상 성능에 중복 강제 금지.

## 9. 캐릭터 업그레이드 / 성장 / 진화

- **캐릭터 자체 업그레이드 시스템은 핵심 메타 시스템이며 보물이나 보급소 강화로 대체하지 않는다.**
- 현재 구현은 전투 코어/캠페인 검증이 우선이라 캐릭터 레벨·강화·진화 UI/데이터는 아직 본격 구현 전이다.
- 기본 성장 범위는 Lv1~50 후보. HP/기본 공격력 중심으로 완만하게 증가시키고 사거리·비용·선딜·KB 횟수 등 정체성 스탯은 원칙적으로 고정한다.
- Lv30 이후 성장 기울기는 낮춘다. 랭크 PvP는 Lv30 표준화 후보.
- 레벨 상승 비용과 성장 재화의 정확한 곡선은 콘텐츠 풀/보상 경제와 함께 결정하며, 불필요하게 많은 재화 종류를 만들지 않는다.

### 진화 원칙

- **진화는 단순 스탯 증가나 색상 교체가 아니다.**
- 진화 시 다음 요소가 실제로 변할 수 있고, 중요한 진화에서는 여러 항목이 함께 변해야 한다.
  - 전체 실루엣, 체형, 의상/갑옷, 무기, 대표 소품
  - Idle / Run / Attack / KB / Death 등 주요 모션
  - 공격 VFX, 투사체, 타격음/효과음, 소환 연출
  - 공격 방식, 단일/범위, 사거리 구조, 멀티히트
  - 속성/전문 대상, Push/Slow/Freeze/Weaken/Strengthen/Critical/방어관통 등 효과
  - 비용, 재생산, HP/공격력 등 수치
- 진화는 반드시 완전 상위호환일 필요가 없다. 역할이 달라지는 sidegrade/전문화 형태를 허용한다.
- 이전 형태 재선택을 허용하여 상황에 따라 형태를 고르는 전략성을 살린다.
- 진화 전후가 작은 전투 화면에서도 서로 다른 형태로 읽혀야 한다.
- 진화가 원래 캐릭터의 핵심 정체성을 완전히 지워 버리지는 않되, ‘같은 그림에 숫자만 오른 버전’도 금지한다.

## 10. 스테이지 / 보물 / 맵

- 스테이지는 JSON 기반 DSL. 시간, 거점 HP, 특정 적 사망, 복합 조건 등의 스폰/페이즈 확장 가능.
- 난이도는 HP 배율만이 아니라 스폰 간격·전후열 조합·경제·맵 길이·사거리·편성 제한으로 만든다.
- 제1장 20스테이지는 앞 스테이지 클리어 후 순차 개방.
- 각 스테이지 보물은 **첫 클리어 100% 확정 획득**. 보물 등급 RNG/드랍률/최고등급 반복 파밍 금지.
- 보물 효과는 `content/treasures/chapter-01.json` typed modifier가 정본이며 실제 다음 전투 수치에 적용. 미래 보물 선적용 금지.
- 캐릭터 해금은 보물과 별도 확정 보상.
- 제1장 전장 계열: 풀바람 평원 / 붉은 협곡 / 불붙은 곡창지대 / 안개 폐허 / 달그늘 고개 / 철문 요새권 / 황금가면 관문.
- 같은 테마라도 `decorSeed`, 맵 길이, 장식, 하늘/원경/중경/지면/거점 팔레트를 바꿔 복붙 금지.
- 맵 길이는 실제 1D 전투 변수.
- ST19 황금가면 제단/의식 깃발, ST20 황금가면+철문 요새 전용 랜드마크. 보스 등장 전에 거점 러시로 끝나는 흐름을 baseline에서 금지.

## 11. 원거리 / 시각 연출

- 실제 피해는 30Hz hitFrame에서 확정하며 시각 투사체 충돌에 종속시키지 않는다.
- `PIERCE / MAGIC / FIRE / VOID`는 선딜 후반에 발사해 hitFrame에 목표 지점에 도달하도록 정수 tick으로 역산.
- `SLASH / BLUNT`는 근접 즉시 VFX.
- 투사체 렌더는 accumulator 기반 fractional interpolation만 사용하며 판정/stateHash에 영향 없음.
- 현재 LuizMelo CC0 계열은 초기 프로토타입 기준 화풍/개발 에셋이다. 장기적으로 캐릭터 수가 늘 때는 **각 캐릭터의 실루엣 정체성을 우선**하며 비슷한 인간형 에셋 반복 사용을 최종 아트 해법으로 보지 않는다.
- 공격 모션과 실제 타격 프레임의 동기화를 최우선으로 한다.

## 12. 거점 병기

- 한 전투에서 장착·사용 가능한 즉시 개입 거점 병기는 1슬롯.
- 장기적으로 병기 종류는 여러 개가 될 수 있지만 전투 화면에 여러 즉시 버튼을 나열하지 않는다.
- 현재 `전선포`: 적 거점 제외 적 전체 90 피해 → 사망/자연 KB → 남은 적 60 거리/10F 강제 후퇴, 쿨다운 900F.

## 13. UI / 진행 저장

- 내부 렌더 기준 1280×720. 픽셀 캐릭터 nearest-neighbor, 전체 UI 텍스트를 CSS pixelated 확대하지 않는다.
- 양쪽 거점 HP바+현재/최대 HP, 보급, 생산비, 쿨다운, 보급소, 병기가 즉시 읽혀야 한다.
- 개발용 tick/hash 텍스트는 일반 플레이에 노출하지 않는다.
- 진행 연동 도감에서 캐릭터/보물의 보유·미해금·속성·특효·획득 조건을 확인한다.
- 캐릭터 성장 구현 후 도감/편성/성장 화면에서 현재 레벨, 진화 형태, 다음 성장 효과를 명확히 확인할 수 있어야 한다.
- 적 속성 라벨은 과밀 방지. 보스는 항상 식별 가능해야 한다.
- 모바일은 현재 가로 화면 기준이며 세로에서는 안내 + simulation pause.
- 게스트 진행은 IndexedDB 정본. 저장 실패 시 성공으로 거짓 표시하지 않고 현재 탭 세션 진행은 임시 보존한다.

## 14. 멀티 / 서버

- 협동: 각 5유닛, 공유 기지/승패/거점 병기, 개인 보급/보급소. 팀 덱 전체로 콤보 계산.
- 재접속 유예 30초 후 AI 인계 후보.
- 합동 병기: 한 명 사용 후 1.5초 내 동료 확인 시 강화 후보.
- 랭크 1v1/2v2는 동일 전투 코어, Lv30 표준화 후보. 친구전은 성장/표준 선택 가능.
- 클라이언트는 명령만 전송, 서버가 보급·쿨다운·소유권·피해를 결정.
- 중요 이벤트 + 약 10~15Hz 상태 패치/스냅샷 + 렌더 보간, 주기적 stateHash.
- 인프라: Cloudflare Pages / Workers / Durable Objects / D1 / 필요 시 R2.

## 15. 개발 / 검증

- monorepo: `apps/client`, `apps/server`, `packages/sim`, `packages/shared`, `packages/content-schema`, `content`, `assets`, `tools`, `docs`.
- GitHub `main` 정본.
- 문서 권위 순서는 `docs/CANONICAL.md` → `docs/GAME_DESIGN_FULL.md` → `docs/IMPLEMENTATION_STATUS.md`이며 실제 수치 데이터는 `content/` JSON을 우선한다.
- 실제 npm 환경에서 생성한 package-lock을 최종적으로 커밋해야 하며 무결성 값을 임의 생성하지 않는다.
- CI 목표: install → typecheck → unit test → deterministic replay/hash → content validation → build.
- 캠페인 baseline은 그 시점에 실제 획득 가능한 캐릭터/보물만 사용. 미래 해금으로 통과하는 가짜 테스트 금지.
- 새 경제 baseline은 필요 시 보급소 업그레이드까지 수행한다.
- 수동 검수: 타격 프레임, KB/ForcedDisplacement, 발 위치/그림자, 저비용 유닛 과밀, 모바일 오조작, 일시정지, UI 가독성, 맵/거점 정렬, 잠긴 스테이지 우회 방지, 캐릭터 실루엣 식별성.

## 16. 첫 사용자 수동 테스트 게이트

개발자용 전투 하네스가 동작한다고 사용자 테스트를 요청하지 않는다. 아래를 만족한 뒤 요청한다.

- 메인 / 20스테이지 선택 / 편성 / 도감 / 결과 화면.
- 새 진행 ST1만 개방 + 징집병 1종.
- 실제 스프라이트 Idle/Run/Attack 및 hitFrame 동기화.
- 최소 7개 전장 계열, 길이/장식 차이, ST19/20 전용 보스 랜드마크.
- 양쪽 거점 HP 숫자/바 가독성.
- 보급/비용/쿨다운/보급소/거점 병기 정상 작동.
- 초반 보급이 넘치지 않고 지갑 강화 선택이 의미 있음.
- 초반 거점 HP 및 이동속도가 지나치게 크거나 빠르지 않음.
- **솔로 일시정지 시 tick/경제/쿨다운/스폰/투사체가 모두 멈춤.**
- 원거리 발사→도달이 hitFrame과 명백히 어긋나지 않음.
- 속성/특효 정보가 과밀하지 않음.
- 승리 시 확정 보물 저장 및 실제 typed modifier 적용, 미획득 보물 미적용.
- PC/가로 모바일에서 일반 플레이 글자가 뭉개지거나 너무 작지 않음.
- ST1~20 합법 진행 baseline과 최종 보스 등장 검증.
- 현재 10종은 프로토타입 아트 반복이 일부 있어도 되지만, 수집 풀을 본격 확장하기 전에는 신규 캐릭터/진화의 실루엣 식별성 기준을 적용한다.

## 17. Anti-goals

- 희귀도만 높으면 하위 캐릭터가 전부 사라지는 구조.
- 배율만으로 난이도 상승.
- 만능 캐릭터.
- 초반부터 지갑/보급이 넘쳐 생산 판단이 사라지는 구조.
- 초반 거점 HP가 과도해 무의미하게 전투가 늘어지는 구조.
- 모든 유닛이 과속해 맵 길이/사거리 설계를 무력화하는 구조.
- FOMO/에너지/필수 RNG 보물 파밍.
- 처음부터 모든 캐릭터/스테이지 개방.
- 현재 제1장 10종을 전체 게임 캐릭터 풀의 상한으로 고정.
- 모든 스테이지 같은 배경/전장 길이.
- 중복 강제 성장.
- **캐릭터나 진화를 색놀이/비슷한 인간형 반복으로 양산.**
- **진화를 같은 외형에 숫자만 올리는 강화로 처리.**
- 캐릭터 성장 시스템을 보물만으로 대체.
- 싱글/멀티 전투 코어 분리.
- 그림체가 다른 무료 에셋 무작정 혼합.
- 공격 애니메이션과 실제 hitFrame 불일치.
- 한 전투에 여러 거점 병기 버튼 동시 배치.
- 개발자용 하네스를 완성된 테스트 빌드처럼 전달.

# 거점 병기 시스템 v1 상세 사양

상태: `DESIGN_TARGET`  
상위: `docs/CANONICAL.md`, `docs/GAME_DESIGN_FULL.md`

거점 병기는 캐릭터별 액티브 스킬을 남발하지 않으면서 플레이어가 전투에 직접 개입할 수 있는 **전투당 1슬롯 공용 능력**이다. 생산/경제/전선 판단을 대체하지 않고 위기 대처 또는 타이밍 보조 역할만 한다.

---

# 1. 공통 규칙

- 전투당 장착 병기 1종.
- 병기 자체는 캐릭터 10칸을 차지하지 않는다.
- 전투 시작 시 기본 cooldown으로 시작한다. 즉시 사용 가능 여부는 병기별 정의.
- cooldown은 simulation frame 기준.
- PvE/협동/PvP가 같은 병기 정의를 사용하되 랭킹전에서 성장 수치는 표준화한다.
- 병기 공격은 플레이어 캐릭터 생산 쿨다운에 영향 없음.
- 병기로 적 거점을 직접 공격할 수 있는지는 병기별 명시. 1차 기본 병기는 적 거점 피해 없음.
- 병기 효과로 난이도 핵심 패턴을 완전히 무력화하지 않게 한다.
- 병기 upgrade가 존재해도 메인 영구 보상과 독립된 과도한 별도 성장축을 만들지 않는다.

---

# 2. 1차 병기 수

1차 DESIGN_TARGET은 **3종**이다.

1. `전선포` — 즉시 광역 피해 + 약한 Push
2. `결계발진기` — 아군 전선 생존 보조
3. `보급투하기` — 전투 경제 순간 보조

세 병기는 `공격 / 방어 / 경제`로 역할을 명확히 분리한다.

4종 이상은 실제 3종 사용률과 역할 중복을 확인한 뒤 추가한다.

# 4. 전선포

weaponId: `base_weapon_front_cannon`

역할:

- 위험한 적 물량 정리
- 자연 KB/Push로 전선을 짧게 재정렬
- 보스 결정타보다 일반/중형 적 제어

기본 DESIGN_TARGET:

- initialCharge: 100%
- cooldown: 900F = 30초
- 조준: 별도 타겟 선택 없이 전장 적 전체 중 유효 대상
- 적 거점: 피해 없음
- 기본 피해: 90
- Push: 살아남은 적을 자기 거점 방향 60거리 / 10F
- BOSS 태그 대상 Push 거리: 20
- STRUCTURE 대상 Push 면역, 피해만 적용
- 타격 frame: 사용 입력 후 24F

연출:

1. 0F 거점 포신 상승
2. 6F 조준선/경고 광원
3. 14F 포격 발사
4. 24F 전장 충격파 hit
5. 36F 연기/포신 복귀

SFX:

- 14F 발사음
- 24F impact

피해보다 타격 timing과 Push 피드백이 명확해야 한다.

# 5. 결계발진기

weaponId: `base_weapon_aegis_emitter`

역할:

- 무너지는 전열을 잠깐 유지
- 강한 보스 한방/연속 웨이브를 받아낼 시간 확보
- 공격력 상승이 아니라 생존 시간 구매

기본 DESIGN_TARGET:

- initialCharge: 0%
- 첫 사용 가능까지: 600F = 20초
- 재사용 cooldown: 1050F = 35초
- 적용: 사용 순간 살아 있는 아군 전투 유닛
- 지속: 150F = 5초
- 받는 피해 감소: 25%
- 신규 소환 유닛: 결계 지속 중 소환되어도 효과 없음이 기본 후보
- 상태효과 면역: 없음
- 자연 KB: 정상 발생
- 아군 거점: 효과 없음

왜 신규 소환까지 적용하지 않는가:

- 5초 동안 물량을 계속 생산해 결계 효과를 무한 확장하는 것을 방지.
- 사용 순간의 현재 전선을 지키는 병기로 정체성 고정.

연출:

- 사용 시 거점에서 전선 방향으로 얇은 보호막 파동.
- 적용된 개체는 발밑/외곽에 작은 결계 표시.
- 화면 전체를 불투명한 색으로 덮지 않는다.

PvP:

- 동일 25%/5초 후보.
- 경기 스톨을 유발하면 20% 또는 4초로 조정하되 PvE 몰래 별도 수치 사용 금지.

# 6. 보급투하기

weaponId: `base_weapon_supply_drop`

역할:

- 고비용 핵심 유닛 생산 timing 단축
- 보급소 투자 직후 생기는 짧은 전력 공백 완화
- 직접 전투 피해 없음

기본 DESIGN_TARGET:

- initialCharge: 0%
- 첫 사용 가능: 750F = 25초
- cooldown: 1200F = 40초
- 즉시 보급 획득: 현재 보급 최대치의 18%
- 최소 지급: 120
- 최대 지급: 900
- 최대 보급 cap 초과 저장 없음

계산:

```text
supplyGain = clamp(round(maxSupply × 0.18), 120, 900)
currentSupply = min(maxSupply, currentSupply + supplyGain)
```

낮은 보급소에서 18%가 너무 적어 보이는 문제를 최소 120으로 보정하고, 후반 maxSupply가 커져도 900을 넘지 않는다.

연출:

- 거점 뒤에서 보급 상자가 짧게 날아와 UI 보급 게이지로 흡수되는 연출.
- 실제 보급 증가는 지정 hit frame 30F에 발생.
- 애니메이션 전에 숫자가 먼저 오르지 않는다.

PvP:

- 표준화된 worker/maxSupply 정의에서 동일 공식.
- 경제 폭발이 생기면 상한을 먼저 조정.

# 7. 협동

협동에서 거점 병기는 **팀 공유 1슬롯**이다.

기본 방식:

- 방 생성/준비 단계에서 두 플레이어가 병기 하나를 합의 선택.
- 기본은 방장 선택이 아니라 양쪽 UI에 선택 상태를 보여주고 ready 전에 변경 가능.
- 양쪽이 같은 병기를 선택해야 최종 ready가 성립한다.
- 각 플레이어가 실제로 해금한 병기만 제안할 수 있으며 서버도 전투 생성 전에 양쪽 진행도를 다시 검증한다.
- 전투 중 charge/cooldown 공유.

사용 권한:

- 두 플레이어 모두 사용 버튼 접근 가능.
- 한 명이 사용하면 즉시 shared cooldown 시작.
- 동일 frame 두 명 입력 시 서버가 결정론적 command 순서로 하나만 승인하고 중복 소모 없음.
- 승인된 command의 `playerId/seatId`를 해당 사용의 activator로 기록한다.

## 7.1 보급투하기의 개인 보급 귀속

상위 `CANONICAL`의 협동 규칙에서 보급/보급소/생산 cooldown은 플레이어별 독립 경제다. 따라서 팀 공유 병기라고 해서 별도의 shared supply wallet을 만들지 않는다.

보급투하기는 다음처럼 처리한다.

- 슬롯과 cooldown은 팀 공유.
- **효과 owner는 실제로 사용이 승인된 seat**.
- 30F hit frame에서 activator seat의 그 시점 `maxSupply`를 기준으로 18%를 계산한다.
- min 120 / max 900 clamp도 activator의 개인 경제에 적용한다.
- 지급은 activator의 `currentSupply`에만 들어간다.
- 상대 플레이어 보급은 0 증가.
- 공용 기지 상태에 존재하는 내부 shared/dummy supply에는 지급하지 않는다.
- 같은 frame에 A/B가 동시에 사용해도 서버가 승인한 한 seat만 owner가 된다.

예시:

```text
A maxSupply = 1000
B maxSupply = 2500
A의 USE_BASE_WEAPON이 먼저 승인

30F hit:
A supplyGain = clamp(round(1000 × 0.18), 120, 900) = 180
B supplyGain = 0
```

이 규칙은 공유 병기를 개인 경제 복제로 바꾸는 것이 아니다. **사용권/쿨다운은 공유하고, 개인 경제를 수정하는 효과만 승인된 사용자에게 귀속**한다.

오사용 방지:

- 사용 직후 빠른 통신에 `병기 사용!` 자동 표시 후보.
- 누가 사용했는지 작게 표시 가능.
- 보급투하기 HUD에는 `사용한 플레이어의 개인 보급`임을 표시한다.
- 매 사용마다 상대 확인을 요구하는 2단 입력은 전투 리듬을 끊으므로 기본 미사용.

과거 `1.5초 안에 두 명 확인하면 강화` 아이디어는 1차 기본 규칙으로 사용하지 않는다. 필요 시 후속 협동 전용 병기로 재검토.

# 8. PvP

## 일반/랭킹

- 양 플레이어 각자 병기 1종.
- 상대 병기는 경기 시작 전 공개하지 않는 것을 기본 후보.
- 한 번 사용하면 상대 HUD에서 병기 icon/쿨 추정 가능하게 할 수 있음.
- 병기 level이 있다면 랭킹에서는 표준화.

병기 때문에 캐릭터 counterplay가 무의미해지면 안 된다.

## 친선

- 병기 사용 ON/OFF 옵션 후보.
- 같은 병기만 사용 규칙 후보.

# 9. 병기 성장

1차에서는 별도의 수십 레벨 병기 성장축을 만들지 않는다.

후보 방식:

- 메인 진행으로 병기 기본 성능이 소폭 자동 강화되거나
- 병기별 최대 5단계 upgrade를 골드로 해금

그러나 첫 구현은 **고정 base stats**로 플레이테스트하는 것을 우선한다.

병기 성장 수치를 넣기 전에:

- 덱/캐릭터 성장과 역할 중복
- PvP 표준화
- 메인 영구 보상과 총 성장폭

을 검증한다.

# 12. 결정성/서버

병기 사용은 command로 처리.

```text
USE_BASE_WEAPON(playerId, weaponId, inputFrame)
```

서버/sim 검증:

- 장착한 병기인지
- cooldown 0인지
- 전투 종료 전인지
- 협동 shared cooldown 경쟁에서 먼저 확정된 command인지
- 개인 경제 효과라면 어떤 seat가 승인된 activator인지

효과 계산은 클라이언트가 보내지 않는다.

---

# 13. 2배속/일시정지

솔로 2배속:

- cooldown도 simulation time 기준 2배 빠르게 체감.
- 실제 frame 수는 동일.

솔로 일시정지:

- 병기 cooldown 정지.
- 일시정지 중 사용 입력 받지 않음.

---

# 14. AI 인계

협동 한 플레이어가 장기 이탈해 AI가 인계해도 shared 병기를 함부로 사용하지 않는 것을 기본으로 한다.

AI 사용 후보 조건:

- 아군 거점 HP < 30%
- 또는 명백한 패배 위험 heuristic

그러나 1차에서는 AI가 shared 병기를 사용하지 않고 복귀 플레이어/남은 플레이어에게 맡기는 쪽이 안전하다.

# 15. QA

전선포:

- 같은 frame 피해/Push 순서 결정성
- BOSS Push 20 적용
- STRUCTURE Push 없음
- 적 거점 피해 없음

결계발진기:

- 사용 순간 snapshot 대상만 효과
- 신규 소환에 잘못 적용되지 않는지
- 피해감소와 Weaken/방어 효과 순서

보급투하기:

- min/max clamp
- maxSupply 초과 없음
- 협동에서 승인된 activator seat만 보급 증가
- 협동에서 상대 보급 증가 0
- 협동 내부 shared/dummy supply 증가 0
- hit frame 이전 선지급 없음

공통:

- shared cooldown 중복 사용 없음
- 동일 frame A/B 동시 입력 시 1회만 승인되고 activator가 결정론적으로 고정
- 2배속 결과 동일
- 일시정지 cooldown 정지
- PvP 표준화
- tooltip 수치와 실제 값 일치
- 모바일 오조작

# 16. LOCKED 전 결정할 것

- 병기 3종 유지 여부
- 결계가 신규 소환에도 적용될지 최종 확정
- PvP 시작 전 상대 병기 공개 여부
- 병기 성장 시스템을 1차에 넣을지 여부
- 협동 방 준비에서 병기 선택 충돌 UX의 최종 문구/시각 피드백

이 결정 전까지 3종 base stat은 DESIGN_TARGET으로 유지한다.

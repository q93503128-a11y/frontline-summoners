# 친구·협동·PvP 상세 기획

상태: `DESIGN_TARGET`  
상위 규칙: `docs/GAME_DESIGN_FULL.md`, `docs/STAGE_SYSTEM_DESIGN.md`

이 문서는 1차 완성의 온라인 기능을 구현 가능한 수준으로 정의한다. 핵심 원칙은 **싱글을 약화시키지 않고 같은 콘텐츠를 친구와 함께 즐길 수 있게 하며, PvP는 경쟁과 부담 없는 재미를 분리**하는 것이다.

---

# 1. 온라인 모드 구성

1차 완성 목표:

- PvE 2인 협동
- PvP 1v1 일반전
- PvP 1v1 랭킹전
- PvP 1v1 친선전
- PvP 2v2 일반전
- PvP 2v2 친선전

2v2 랭킹전은 동접과 큐 분산을 확인한 뒤 개방하는 것이 기본 방향이다.

---

# 2. 친구 시스템

## 2.1 식별

플레이어는 다음 중 최소 하나로 찾을 수 있다.

- 닉네임 + 고유 짧은 코드
- 친구 코드 직접 입력
- 최근 함께 플레이한 사용자

닉네임만으로 계정을 유일하게 식별하지 않는다.

## 2.2 친구 요청

상태:

- NONE
- OUTGOING_PENDING
- INCOMING_PENDING
- FRIEND
- BLOCKED

동일 대상에게 중복 요청을 보내지 않는다.

## 2.3 친구 목록 표시

- 닉네임
- 프로필 아이콘/테두리
- 온라인/오프라인
- 현재 초대 가능 여부
- 마지막 접속 표시 정책 후보
- 협동 초대
- 친선전 초대
- 삭제
- 차단

정확한 위치 정보나 불필요한 개인정보를 노출하지 않는다.

---

# 3. 차단

차단 시:

- 친구 관계 해제
- 친구 요청 차단
- 직접 초대 차단
- 최근 플레이어 목록에서 상호작용 제한
- 공개 매칭에서 가능한 한 재매칭 우선순위를 낮춤

신고 기능을 추가할 경우 별도 안전 정책과 함께 설계한다.

---

# 4. 빠른 통신

자유 텍스트 채팅은 1차 필수 기능이 아니다.

기본 퀵 메시지:

- 준비됐어
- 보급 올릴게
- 전열 부탁
- 후열 부탁
- 병기 쓸게
- 위험!
- 기다려
- 좋아!

규칙:

- 짧은 쿨다운
- 연속 스팸 제한
- 화면 중앙을 가리지 않는 작은 표시
- 소리 on/off 설정
- 악성 사용자 차단 시 메시지 차단

---

# 5. 협동 입장 흐름

메인/SPECIAL의 `SOLO_OR_COOP` 스테이지에서:

1. 혼자 시작
2. 친구 초대
3. 공개 매칭

중 하나를 선택한다.

친구 초대 시 방 생성 → 초대 → 상대 수락 → 양측 5칸 편성 확인 → Ready → 전투.

공개 매칭은 비슷한 스테이지 진행/권장 성장대를 우선하되 대기시간을 지나치게 늘리지 않는다.

---

# 6. 협동 덱

- 플레이어당 5칸
- 팀 총 10칸
- 각 플레이어는 자신이 보유한 캐릭터만 사용
- 한 플레이어 내부 동일 캐릭터 중복 슬롯 금지

두 플레이어가 동일 캐릭터를 각각 가져오는 것은 PvE에서는 기본 허용 후보다. 특정 캐릭터 2중 편성이 밸런스를 깨는 경우 캐릭터 설계를 먼저 검토한다.

---

# 7. 협동 경제

각자 독립:

- 현재 보급
- 최대 보급
- 보급 증가량
- 보급소 레벨
- 캐릭터 재생산 쿨다운

공유:

- 아군 거점
- 적 거점
- 전장
- 승패
- 거점 병기

한 사람이 생산해도 다른 사람의 보급은 줄지 않는다.

---

# 8. 협동 거점 병기

1차 기본은 팀 공유 병기 1개.

사용 충돌 방지:

- 한 명이 사용하면 서버에서 즉시 확정
- 다른 클라이언트 버튼도 같은 쿨다운으로 전환

향후 합동 입력 강화형 병기를 넣을 수 있으나 1차 코어를 복잡하게 만들지 않는다.

---

# 9. 협동 적 보정

기본 스테이지 디자인은 솔로를 기준으로 한다.

협동 출발 후보:

```yaml
enemyHp: 1.15 ~ 1.30
enemyAttack: 1.05 ~ 1.15
enemyBaseHp: 1.10 ~ 1.20
```

기본 변경 금지:

- 이동속도
- 사거리
- 공격주기
- KB
- 웨이브 수
- 스폰 시점
- 적 개체 수

스테이지별로 같은 계수만 기계적으로 쓰지 않고 실제 플레이테스트 결과를 기록한다.

---

# 10. 협동 진행 인정

협동 최초 클리어도 다음을 모두 정상 인정한다.

- 스테이지 클리어
- 다음 스테이지 해금
- 첫 클리어 보상
- 영구 보상
- 장 최종 보상
- 캐릭터/콘텐츠 해금

`솔로 클리어` 마크/업적은 별도로 둘 수 있지만 필수 성장재화를 주지 않는다.

---

# 11. 협동 보상

- 개인별 저장에 지급
- 솔로와 기본 보상 동일
- 친구와 했다고 보상 삭감 없음
- 협동이라고 보상 2배 없음
- 보상 충전은 각 계정에서 독립 소비

공개 매칭 반복 악용을 막기 위해 상대 유무만으로 추가 고효율 보상을 주지 않는다.

---

# 12. 협동 중 이탈

## 짧은 끊김

- 서버가 플레이어 슬롯/경제/쿨다운 상태 보존
- 재접속 시 동일 상태 복구

## 장기 이탈

AI 임시 인계 후보.

AI는:

- 플레이어의 기존 5칸만 사용
- 보급소를 무작정 최대 강화하지 않음
- 정상적 전열 유지 우선
- 거점 병기 사용은 보수적으로

복귀 시 제어권 반환.

---

# 13. 재접속 유예

초기 목표 30초 전후를 후보로 한다.

테스트 항목:

- 모바일 앱 전환
- Wi-Fi ↔ LTE 변경
- 브라우저 탭 잠깐 비활성
- 3~10초 패킷 끊김

짧은 네트워크 흔들림으로 즉시 패배하지 않게 한다.

---

# 14. 공개 협동 매칭

우선순위 후보:

1. 같은 stageId
2. 비슷한 권장 성장대
3. 지역/핑
4. 대기시간

대기시간이 길어지면 성장대 조건을 완화할 수 있다.

완전히 다른 스테이지를 자동으로 바꿔 매칭하지 않는다.

---

# 15. PvP 공통

PvP 승리 조건은 상대 거점 파괴.

기본 1v1:

- 각 10칸
- 개인 보급/보급소
- 상대 덱은 경기 전 전체 공개하지 않는 방향
- 전투 중 나온 캐릭터를 보고 대응

2v2:

- 플레이어당 5칸
- 팀 10칸
- 팀 거점 공유
- 개인 경제

---

# 16. PvP 성장 표준화

랭킹전은 장기 성장 격차를 제거한다.

표준화 대상:

- 기본 레벨
- +레벨
- 메인 영구 HP/공격 보너스
- 시작 보급 영구 보너스
- 기타 계정 영구 전투 스탯

유지:

- 실제 보유 캐릭터
- 실제 해금 형태
- 선택한 형태
- 캐릭터 고유 비용/사거리/재생산/능력

표준 레벨은 전체 1차 성장과 밸런스 테스트 후 확정한다. 단순히 과거 Lv30 후보를 자동 유지하지 않는다.

---

# 17. PvP 일반전

목적: 부담 없는 실험/재미.

- 레이팅 변동 없음
- 티어 변동 없음
- 기본 표준화
- 매칭 승패 기록은 개인 통계 후보
- 보상은 소량 또는 플레이 보조 수준

랭킹 유저와 일반 유저 큐를 분리한다.

---

# 18. PvP 랭킹전

구성:

- 내부 MMR
- 표시 티어
- 순위표
- 시즌
- 티어 최초 도달 보상

티어 예시는 구현 전 세계관 명칭으로 최종 확정한다.

구조 예:

- Bronze
- Silver
- Gold
- Platinum
- Diamond
- Master
- 최상위 티어

최상위권은 `전체 127위`처럼 숫자 랭킹을 표시한다.

---

# 19. MMR 원칙

초기에는 검증된 단순 rating 방식을 사용한다.

필수:

- 신규 배치 구간
- 비슷한 MMR 우선
- 연승 때문에 과도한 점프를 만들지 않음
- 고의 패배/양학 이득 억제
- 시즌 리셋 시 완전 0 초기화보다 소프트 리셋 후보

정확 공식은 서버/매칭 구현 단계에서 별도 LOCKED 문서로 내린다.

---

# 20. 랭킹 보상

## 티어 최초 도달

가능:

- 골드
- 모집 재화
- 공용 +재화
- 진화재료
- 프로필 테두리
- 칭호

## 시즌 종료

성능보다 명예 위주:

- 테두리
- 시즌 문장
- 칭호
- 프로필 배너

고순위가 다음 시즌 전투력까지 크게 앞서는 보상 금지.

---

# 21. PvP 친선전

친구 초대 또는 방 코드.

옵션 후보:

- 표준 성장
- 실제 성장
- 1v1
- 2v2
- 맵 선택
- 일부 특수 규칙

레이팅/티어/랭킹/핵심 보상 없음.

---

# 22. 2v2 랭킹 보류 원칙

1차에서 1v1 일반/랭크와 2v2 일반/친선까지 제공할 수 있다.

2v2 랭크를 처음부터 분리하면 큐가:

- 1v1 일반
- 1v1 랭크
- 2v2 일반
- 2v2 랭크
- PvE 공개협동

으로 나뉘어 소규모 동접에서 매칭 품질이 급락할 수 있다.

따라서 실제 동접/대기시간 자료 후 개방한다.

---

# 23. PvP 안티스톨

검토할 문제:

- 양측 벽만 뽑고 무한 교착
- 장거리만 쌓아 서로 접근 불가
- 처치 보급으로 승자가 더 폭주
- 초반 러시가 사실상 확정 승리

해결은 캐릭터별 PvP 전용 수치 남발보다:

- 맵 길이
- 처치 보급
- 경제 시작값
- 기본 기지 압박
- 특정 극단 캐릭터 조정

순으로 한다.

---

# 24. 매칭 취소/AFK

- 매칭 성사 전 취소 자유
- Ready 이후 반복 이탈은 짧은 재매칭 제한 후보
- 랭킹전 AFK/고의 이탈은 패배 처리
- 네트워크 끊김은 재접속 유예 적용

오탐으로 정상 사용자를 과하게 처벌하지 않는다.

---

# 25. 관전/리플레이

1차 필수는 아니지만 결정론 전투 구조를 이용해 향후 리플레이/관전 확장이 가능하게 입력 로그와 seed 설계를 깨뜨리지 않는다.

---

# 26. 서버 권위

멀티에서 클라이언트가 보내는 것은 명령이다.

서버가 검증:

- 캐릭터 소유
- 덱
- 비용
- 보급
- 쿨다운
- 스폰
- 피해
- 승패
- 보상

클라이언트가 HP/보급/승리를 직접 확정하지 않는다.

---

# 27. 멀티 QA

필수 테스트:

- 100~300ms 지연
- 짧은 packet loss
- 한 플레이어 느린 기기
- 브라우저 background/resume
- 재접속
- 동일 캐릭터 양측 생산
- 최대 엔티티 밀도
- 2배속이 멀티에 잘못 적용되지 않는지
- 결과 화면 중복 지급
- 한쪽만 첫 클리어인 협동
- 보상 충전이 서로 다른 두 계정
- 친구 차단 후 초대
- 랭킹 이탈

---

# 28. 1차 완료 조건

온라인 기능은 버튼이 존재한다고 완료가 아니다.

- 친구 추가/삭제/차단 실제 동작
- 친구 협동 초대
- 공개 협동
- 협동 진행 저장
- 재접속
- 일반전
- 랭킹전 MMR/티어/랭킹
- 친선전
- 2v2 일반/친선
- 보상 중복 없음
- 모바일/PC 네트워크 전환 테스트

까지 검증해야 1차 완성으로 본다.

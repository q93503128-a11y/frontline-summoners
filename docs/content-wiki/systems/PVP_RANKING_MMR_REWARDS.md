# PvP 랭킹·MMR·티어·보상 상세 목표

상태: `DESIGN_TARGET`  
상위: `MULTIPLAYER_SOCIAL_PVP.md`

이 문서는 1차 완성의 1v1 랭킹전을 실제 구현 가능한 수준으로 수치화한다. PvP의 목적은 경쟁을 원하는 플레이어에게 장기 목표를 제공하는 것이며, PvE 성장을 강제하는 필수 통로로 만들지 않는다.

---

# 1. 모드 분리

## 일반전
- MMR/티어 변화 없음.
- 기본 표준 성장.
- 일일/주간 필수 숙제로 만들지 않는다.
- 실험 덱, 캐릭터 연습, 부담 없는 플레이용.

## 랭킹전
- 숨은 MMR + 표시 티어 + 시즌 순위표.
- 1차는 1v1만 정식 랭킹.
- 2v2 랭킹은 동접/대기시간 데이터 확보 후 추가.

## 친선전
- 친구/방코드.
- 랭킹 영향 없음.
- 표준 성장/실제 성장 선택 가능.

---

# 2. 랭킹전 전투 표준화

1차 랭킹전 표준:

- 모든 캐릭터 기본 Lv50으로 계산.
- +레벨 = +0.
- 메인 영구 HP/공격/경제/거점 보너스 = 0.
- 플레이어가 실제 소유한 캐릭터만 사용 가능.
- 실제 해금한 형태만 선택 가능.
- 선택 형태의 고유 HP Lv1값, 공격 Lv1값, 비용, 재생산, 사거리, 이속, KB, 능력은 그대로 사용.
- 기본 레벨 표준 배율은 Lv50 ×10을 적용.

목적: 수집/형태 해금은 의미가 있지만 반복 파밍/+레벨/메인 진행량으로 승패가 압도되지 않게 한다.

일반전도 기본은 동일 표준화를 사용한다.

친선전 `실제 성장` 규칙에서만 계정의 실제 Lv/+Lv/영구보너스를 적용할 수 있다.

---

# 3. 랭킹 참가 조건

후보:

- 메인 1장 완료.
- 10칸 편성을 정상적으로 구성할 수 있는 보유 캐릭터 수 확보.
- 계정 닉네임 설정 완료.
- 비정상 게스트 세션이 아니라 영속 저장 가능한 상태.

랭킹을 4장 완료 후에만 열면 너무 늦으므로 1장 완료 정도를 첫 후보로 둔다.

---

# 4. 시즌 길이

1차 후보: **6주 시즌 + 3일 정산/프리시즌 구간**.

이유:

- 1~2주 시즌은 접속 압박이 강함.
- 3개월 이상은 목표 갱신이 느림.
- 6주는 실력 변화를 확인하면서도 시즌 장식의 희소성을 유지하기 적절한 출발점.

시즌 종료 후 일반전/친선은 계속 가능.

---

# 5. 배치전

첫 시즌 또는 랭킹 첫 참가:

- 배치전 5경기.
- 내부 시작 MMR 1000.
- 배치 중 화면에는 임시 `배치 중 2/5` 표시.
- 상대는 가능한 한 850~1150에서 시작하고 대기시간에 따라 범위 확대.
- 배치 결과만으로 최상위 티어 직행 금지.

배치 완료 후 최대 초기 표시 티어는 `플래티넘` 후보로 제한한다. 실제 MMR이 더 높으면 이후 승리로 빠르게 올라갈 수 있다.

---

# 6. MMR 공식

1차는 단순 Elo 계열을 사용한다.

기대승률:

```text
E = 1 / (1 + 10 ^ ((opponentMMR - playerMMR) / 400))
```

업데이트:

```text
newMMR = oldMMR + K × (score - E)
```

- 승리 score = 1
- 무승부 score = 0.5
- 패배 score = 0

K 후보:

- 배치전: 48
- 배치 후 MMR < 1400: 32
- 1400~1799: 26
- 1800+: 20

MMR은 정수 반올림.

이 공식은 첫 구현용 DESIGN_TARGET이며 고수층 분포가 뭉치면 Glicko 계열로 교체 가능하다.

---

# 7. 표시 티어

작업명은 다음 8단계로 둔다. 실제 세계관 명칭은 UI 아트 단계에서 바꿀 수 있으나 MMR 구간은 별도 검증 전까지 유지한다.

| 티어 | MMR |
| --- | ---: |
| 브론즈 | 0~899 |
| 실버 | 900~1049 |
| 골드 | 1050~1199 |
| 플래티넘 | 1200~1399 |
| 다이아 | 1400~1599 |
| 마스터 | 1600~1799 |
| 그랜드마스터 | 1800~1999 |
| 전선 최상위 | 2000+ |

브론즈~다이아는 필요하면 III/II/I 세부 디비전을 UI에서 둘 수 있으나, 첫 구현에서는 티어 숫자를 지나치게 쪼개지 않는다.

2000+는 정확한 전체 순위를 함께 표시한다.

---

# 8. 티어 승급/강등

MMR이 경계를 넘으면 즉시 티어를 갱신하는 단순 구조를 기본으로 한다.

단, 경계선 1점 왕복으로 UI가 계속 깜빡이는 것을 줄이기 위해 표시 티어에 15점 완충을 둘 수 있다.

예:

- 골드 → 플래티넘: 1200 도달 즉시 승급.
- 플래티넘 → 골드 강등: 1185 미만에서 강등.

최상위 티어는 완충보다 실제 MMR 표시를 우선한다.

---

# 9. 매칭 범위

초기 검색:

- ±100 MMR.

대기 15초:

- ±180.

대기 30초:

- ±280.

대기 60초 이상:

- ±400까지 확대 후보.

지역/핑을 먼저 만족시키되 MMR 차이가 너무 커지는 경우 예상 MMR 변화량을 줄이지 않는다. 약한 상대를 잡았을 때 얻는 점수가 이미 Elo 기대승률로 작아진다.

동일 상대와 짧은 시간 반복 매칭될 경우 우선순위를 낮춘다.

---

# 10. 시즌 소프트 리셋

완전 1000 초기화 금지.

후보:

```text
nextSeasonMMR = 1000 + (previousMMR - 1000) × 0.60
```

범위 clamp:

- 최소 800
- 최대 1750

예:

- 800 → 880
- 1200 → 1120
- 1600 → 1360
- 2000 → 1600

최상위가 새 시즌 첫날 초보와 바로 붙는 것을 줄이면서 다시 경쟁할 공간을 만든다.

---

# 11. 순위표

기본:

- 전세계/전체 서버 Top 1000.
- 내 순위 주변 ±5명 표시.
- 친구 중 순위.
- 닉네임, 티어, MMR, 시즌 승수 후보.

개인정보나 상세 덱 전체를 순위표에서 노출하지 않는다.

동점 MMR 순서:

1. 더 많은 랭킹 승리
2. 더 최근에 해당 MMR 도달
3. 그래도 같으면 동일 순위 표시 가능

정확한 tie-break는 서버 구현 전에 LOCKED.

---

# 12. 랭킹전 보상 원칙

보상은 존재하지만 PvP가 필수 성장 통로가 되지 않는다.

## 티어 최초 도달 보상

계정당 시즌 내 1회가 아니라 **각 티어를 계정 최초로 달성했을 때 1회**를 기본 후보로 한다. 시즌마다 대량 성장재화를 재지급하지 않는다.

| 최초 티어 | 골드 | 모집 재화 | soul_shard | 진화재료 | 장식 |
| --- | ---: | ---: | ---: | --- | --- |
| 실버 | 5,000 | 100 | 40 | - | - |
| 골드 | 10,000 | 200 | 80 | fragment 8 | 칭호 |
| 플래티넘 | 18,000 | 300 | 140 | fragment 15 | 테두리 |
| 다이아 | 30,000 | 500 | 240 | core 2 | 칭호+테두리 |
| 마스터 | 45,000 | 700 | 360 | core 3 | 프로필 배너 |
| 그랜드마스터 | 60,000 | 900 | 500 | crown 1 | 전용 문장 |
| 전선 최상위 | 80,000 | 1,200 | 700 | crown 1 | 최상위 테두리 |

숫자는 경제 테스트 전 DESIGN_TARGET.

## 시즌 종료 보상

성능 성장보다 장식 위주.

- 골드 이상: 시즌 참가 문장.
- 플래티넘 이상: 시즌 테두리 변형.
- 마스터 이상: 시즌 칭호.
- Top 1000: 랭커 배너.
- Top 100: 특수 랭킹 문장.
- Top 10: 숫자 순위가 새겨진 명예 장식 후보.

시즌 종료 성능 재화는 소량만 주거나 생략 가능하다.

---

# 13. 일반전 보상

일반전이 무보상이어서 아무도 하지 않는 문제를 피하되 파밍 최적해가 되지 않게 한다.

후보:

- 첫 3경기 승패 무관 소량 골드.
- 승리 시 추가 소량 골드.
- 모집재화/희귀 진화재료 반복 지급 없음.

PvP 보상 때문에 일반전을 매크로로 돌리는 구조를 피한다.

---

# 14. 탈주/연결 끊김

랭킹전:

- 연결 끊김 즉시 패배 처리 금지.
- 20초 재접속 유예 후보.
- 복귀하지 않으면 패배 처리.
- 서버 장애/양측 동시 연결문제는 무효경기 판정 가능.

고의 탈주 반복:

- MMR 패배는 정상 적용.
- 짧은 매칭 제한을 단계적으로 적용 가능.
- 첫 네트워크 사고에 강한 제재 금지.

---

# 15. 무승부/시간 제한

무한 벽 스톨 방지용 경기 시간 상한 후보: 8분.

8분 종료 시 판정 순서 후보:

1. 남은 거점 HP 비율 높은 쪽
2. 동일하면 누적 거점 피해량 높은 쪽
3. 동일하면 무승부

갑자기 양측에게 자동 데미지를 넣는 방식보다 결과 판정이 단순하다.

실제 평균 경기시간은 2.5~5분 목표.

---

# 16. 안티스톨 전투 설계

- 재생산 최소 60F.
- 과도한 무한 벽 조합은 개별 캐릭터 비용/재생산으로 조절.
- PvP 전용으로 캐릭터 스탯을 몰래 바꾸지 않는 것을 우선한다.
- 정말 필요한 경우 PvP modifier를 명시적 시스템으로 도입하고 도감/룰에 공개한다.

---

# 17. 덱 공개 정책

경기 전 상대 10칸 전체를 보여주지 않는다.

경기 중:

- 상대가 한 번이라도 소환한 캐릭터는 작은 기록 영역에서 확인 가능 후보.
- 형태/속성/주요 능력은 이미 획득/발견 정보와 무관하게 PvP에서는 공정성을 위해 확인 가능하게 한다.

상대 덱을 외우기 위해 화면을 캡처할 필요가 없게 한다.

---

# 18. 랭킹 통계

개인 프로필 후보:

- 시즌 최고 MMR
- 현재 MMR
- 최고 티어
- 랭킹 승/패
- 일반전 승/패
- 선호 캐릭터 상위 3개

승률을 과도하게 전면 노출해 신규 유저 압박을 만들지 않는 UI도 검토.

---

# 19. 부정행위 방지

- 권위 서버가 자원/쿨다운/스폰/피해/승패 판정.
- 클라이언트가 `승리했다`는 결과만 전송하는 구조 금지.
- 비정상 명령 빈도 제한.
- stateHash 불일치 기록.
- 동일 계정 동시 랭킹 매치 금지.
- 의도적인 자기 계정 매칭/승작 패턴을 서버 로그로 탐지 가능하게 한다.

---

# 20. QA

- Lv1 계정과 Lv50 계정이 같은 캐릭터/형태를 쓰면 랭킹전 실제 전투 스탯이 동일한가.
- +50이 랭킹전에 섞이지 않는가.
- 메인 영구보너스가 랭킹전에 섞이지 않는가.
- 일반/랭킹/친선 UI가 명확히 다른가.
- 랭킹 첫 입장 전에 규칙을 보여주는가.
- MMR 경계 왕복이 과도한가.
- 소프트 리셋 후 상위권이 신규와 섞이지 않는가.
- 탈주와 네트워크 장애를 구분할 여지가 있는가.
- 시즌 보상 때문에 PvE 필수 성장 격차가 생기지 않는가.

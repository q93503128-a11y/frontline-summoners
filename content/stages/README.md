# 스테이지 콘텐츠 데이터

`chapter-01.json`은 제1장 20개 **진도 스테이지**의 런타임 정본이다.

현재 브라우저와 전투 프로토타입은 `apps/client/src/prototype.ts`에서 이 JSON을 직접 읽고 `@frontline/content-schema` 검증을 통과한 데이터만 사용한다. 같은 스테이지 수치를 TypeScript 배열에 다시 복제하지 않는다.

스테이지 시스템의 정밀 설계는 `docs/STAGE_SYSTEM_DESIGN.md`를 따른다. 장기적으로 진도 스테이지와 특수 스테이지는 콘텐츠 축을 분리하며, 현재 제1장 JSON은 입력에 `stageType`이 없으면 스키마에서 `PROGRESSION`으로 정규화된다.

각 스테이지는 현재 다음을 가진다.

- 실제 전투 길이 `mapLength`
- 플레이어/적 거점 HP
- 시작 보급
- 전장 테마와 `decorSeed`
- 적 웨이브와 등장 틱
- 첫 클리어 100% 확정 보물
- 필요한 경우 첫 클리어 캐릭터 해금

웨이브는 **패턴 단위**다. 한 스테이지 안에서 일회성 패턴과 반복 패턴을 함께 사용할 수 있으며 적 종류로 반복 여부를 하드코딩하지 않는다.

- `atTick`: 첫 사이클 시작 틱
- `count`: 사이클 하나에서 나올 적 수
- `intervalTicks`: 같은 사이클 내부의 개별 스폰 간격
- `repeatDelayTicks`: 사이클 종료 뒤 다음 사이클까지의 간격. 없으면 한 번만 실행한다.
- `maxCycles`: 첫 사이클을 포함한 총 반복 횟수. `repeatDelayTicks`가 있는데 이 값이 없으면 전투 종료까지 계속 반복한다.

따라서 일반 적도 일회성 패턴일 수 있고, 보스도 콘텐츠가 원하면 반복 패턴으로 만들 수 있다. 현재 제1장/첫 SPECIAL의 보스 패턴은 데이터상 일회성으로 두되 엔진이 보스를 특별 취급하지 않는다. 적 동시 출격 한도에 막힌 스폰은 소모되지 않으며, 자리가 난 실제 스폰 시점을 기준으로 다음 간격을 잡아 밀린 스폰이 한꺼번에 따라잡지 않게 한다.

스키마에서 추가로 정규화·지원하는 항목:

- `stageType`: `PROGRESSION / SPECIAL`
- 난이도 **1~12**
- `playerUnitCap` / `enemyUnitCap` — 기본값 50 / 50
- 편성 제한 `formationRestrictions`
- 등록형 특수 규칙 ID `specialRules`

현재 제1장은 입문 진도 캠페인이므로 난이도 1부터 최종전 9까지 사용하며, 10~12는 이후 더 높은 체급의 진도/특수 콘텐츠를 위해 남긴다. 난이도는 단순 적 스탯 배율 공식이 아니라 스폰·조합·경제·맵·사거리·제한을 종합한 가이드 값이다.

검증 항목:

- 스테이지 ID / 보물 ID 중복 금지
- 적 ID와 캐릭터 해금 ID 참조 유효성
- 난이도 1~12
- 양쪽 거점 HP / 전장 길이 / 웨이브 수치 범위
- 반복 웨이브 간격/횟수 유효성 (`maxCycles` 단독 사용 금지)
- 아군/적 동시 출격 한도 유효 범위
- 편성 제한 데이터 형식/중복 검증
- 특수 규칙 ID 배열 중복 금지
- 웨이브 시작 틱 오름차순
- 제1장 20스테이지 고정
- 최소 7개 전장 테마 사용
- 기본캐 `militia`를 보상으로 다시 해금하는 오류 금지
- 비스타터 9종이 정확히 한 번씩 해금되어야 함
- 같은 테마 + 같은 전장 길이를 연속 재사용하는 단순 복붙 금지

새 계정은 STAGE 1만 열리며 앞 스테이지 클리어로 다음 진도 스테이지가 순차 개방된다. 보물은 첫 클리어 시 100% 확정 획득하고 캐릭터 해금 보상과 별도다.
